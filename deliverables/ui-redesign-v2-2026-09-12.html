④ 必须遵守的既有约束（来自代码注释与你的历史要求）

约束出处与含义
画像页：不要百分比 / 进度条 / 健康度2026-09-11 你的要求。只给静态「已用 / 上限 + 条数」；容量红线由 write_gate 写入时强制。（v1 原型在此违规，v2 已改）
冷热分布 / 超 R 节 / 指针健康：不要client.js 注释：「已按 2026-09-11 用户要求移除」。后端仍在算（/cognition/report 的 activity / overR），但 UI 不展示
34 个端点必须都有 UI 入口check-ui-contract 第④项，无入口即 FAIL。本方案 6 视图全部覆盖，无需改白名单
改 client.js 必须跑 build:clientpretest 只含 build:host；不跑则「改了源码没生效」且无报错
UI 改动需重启 DSH热重载只换 host 侧 lib/*.js，不换前端 client.js（2026-09-12 13:20 实测确证）
视图切换才 Fold.clear()同视图内重绘（轮询 / 保存后重取）必须保留折叠态

⑤ v2 相对 v1 的修正

v1 原型在画像页画了「78% + 容量条」，与「不要百分比/进度条/健康度」直接冲突 —— 本轮读 client.js:2204 注释才发现这是你 2026-09-11 的明确要求，v2 已改为静态数字 + 一行文字提示。
另：v1 猜测「冷热分布 / 超 R 节是前端没用的缺口」，逐字段核实后确认是你主动移除的，不是缺口（同一个注释出处）。 v1 那个判断方向错了，已撤回。
