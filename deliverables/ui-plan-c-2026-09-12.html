方案 C · 保守增强 · 可点击左侧导航与页内 Tab / 折叠 / 锚点

优点

  • 改动量最小，回归风险最低，不涉及视图增删，UI 契约门禁的端点覆盖检查天然不受影响
  • 保留配置原文一级入口，排查时最顺手
  • 图标补全后导航立刻可扫读，这是投入产出比最高的一处

代价 / 风险

  • 首屏仍是配置原文（YAML 墙），这是现状最大的体验问题，本方案不解决
  • 参数页 620 行、记忆板块 289 行的长页问题只靠锚点缓解，没有根治
  • 不新增总览视图，系统健康状态仍然分散在多个页面里

改动清单

  1. ICONS 补 3 个：suite / deepsleep / observe（现状此三项复用 toggles 图标）
  2. 页脚常驻健康条（记忆库状态 + 库路径），替换现状的静态 storage 文案
  3. renderViewToggles / renderMemoryExpanded 顶部加吸顶锚点条
  4. 其余不动：视图集合、首屏、分区结构全部保持现状

现状实测基线（读 client.js 得出）

  • 默认首屏 currentView = 'file'（配置原文 YAML）
  • ICONS 5 个服务 8 个视图：toggles 被 深度睡眠 / 运行观测 / 参数调节 / 界面设置 共用；file 被 插件集合 / 配置原文 共用
  • renderViewToggles 620 行（1289–1909）；renderMemoryExpanded 289 行（2186–2475）
  • 导航分组已实现（VIEWS 第 4 项 + renderNav 渲染 sc-nav-group），本轮不是新增能力

本页基础 CSS 与图标取自 client.js 同一份定义；Tab、KPI、锚点条、页脚健康条为方案新增样式，目前只在本页存在。
