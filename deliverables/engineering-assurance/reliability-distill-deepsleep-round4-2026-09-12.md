## 21. 第五盲「假无」：没看到输出 ⇒ 判定没发生（Cody 自我更正）

### 21.1 事实

Cody 曾报告「环境失效、跑不了任何东西」，据此放弃验证。**这个结论是错的。**

后续探针证明：命令**一直在执行**，只是 stdout/stderr 不回传——`echo hi > f` 与 `node -e writeFileSync` 两个文件**都真实生成了**，而他在同一时刻判定"没执行"。

### 21.2 与「假有」互为镜像

| 盲 | 形态 | 危害 |
|---|---|---|
| **假有** | 没验证就宣称存在（"已加"／"已修"／"已部署"） | 让不存在的安全感流通 |
| **假无** | **没看到输出 ⇒ 判定没发生** | 让人在工具静默时**放弃本可完成的工作** |

⇒ 已入册为**第五盲**。它比假有更隐蔽：假有会被复核抓到，**假无会让验证根本不发生**。

### 21.3 固化手法（强制）

```
一律：cmd > file 2>&1 然后 Read 该文件
禁止：凭空 stdout 判断「执行了 / 没执行」
```

**适用范围**：任何 shell / node / git 调用，**尤其是怀疑工具静默时**。

### 21.4 一条配套手法：只替换目标块的双向锚点

Cody 补做 exit 5 兜底变体时的做法值得照抄：

1. 把真 `check-runner.mjs` 复制到临时目录
2. **只替换 CHECKS 块**
3. **断言非 CHECKS 区与真件逐字节相同** —— 双向锚点，防止自己改坏别处却归因于被测逻辑

结果：

| exit 4 | `⚠ … exit=4 xfail` | 否 | **0** |

⇒ **4 分支没把 else 吞掉**，G-23 的兜底方向也闭合。
