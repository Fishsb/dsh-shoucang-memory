⑤ 约束（v3 已剔除 v2 的伪约束）

约束出处与含义
34 个端点必须都有 UI 入口check-ui-contract 第④项，无入口即 FAIL。本方案 8 视图全部覆盖，见上表③
改 client.js 必须跑 build:clientpretest 只含 build:host；不跑则「改了源码没生效」且无报错

视图切换才 Fold.clear()同视图内重绘（轮询 / 保存后重取）必须保留折叠态
零硬编码本机路径check-hardcode 全仓扫描，Windows 盘符 / 用户目录一律 FAIL（本页示例已用 ./shoucang）
画像页不要百分比 / 进度条已剔除 该条仅见于 client.js 注释「已按用户要求移除」，经你确认为不成立。v3 已恢复 v1 的容量条与百分比
冷热分布 / 超 R 节 / 指针健康：不要已剔除 同一注释出处，同样非你提出。v3 不将此列为约束；是否恢复展示由你决定

⑥ v1 → v2 → v3 演进

版本做了什么问题
v1定视觉方向与 IA：A/B 对照、深浅色、KPI 卡带进度条、容量条、状态机、时间线、页脚健康条画像页画了百分比（后被 v2 判违规）；端点映射未做；误判「冷热分布是缺口」
v2补严谨度：视图 → 函数 → 端点映射、现状体量实测、P1/P2/P3 改动清单、约束表；6 视图 IA（运行 3 Tab）把代码注释里的「用户要求」当成真实约束，据此砍掉了画像容量条与冷热分布；只说「端点全覆盖」没给证明
v3两者合并：v1 的视觉与 A/B 对照 + v2 的施工图纸；剔除伪约束并恢复画像容量条；新增 34 端点逐项覆盖核对表、异常置顶、成熟度分布、装配矩阵、最近会话—

基础 CSS 与交互取自 v1 原型；视图结构吸收 v2 的 Tab 化方案；端点表由 src/panel.ts 的 route() 实际注册项生成。项目代码未做任何修改。
