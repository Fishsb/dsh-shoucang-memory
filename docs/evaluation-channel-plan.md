## 7. 档位设计（按**成本结构**，非按厂商）

> **判因**（用户指出，会审确认）：**Jev 的优势只是"快 + 便宜"，不是"别人做不到"**。普通大模型能做同样的判断，只是慢。
> ⇒ 按"是否 TypeSafe"分档，等于把**成本维度伪装成能力维度**。

| 档 | 后端 | 延迟 | 成本 | `calibrated` | 适用 |
|---|---|---|---|---|---|
| **S** | 本地（Ollama 等） | 中（无网） | **0**（边际） | false | 每步高频判定（最优） |
| **F** | 远程小快模型 | ~100ms | 低 | false | 每步高频判定 |
| **N** | 原生校准（TypeSafe） | ~100ms | 低 | **true** | 需**自动**阈值路由时 |
| **L** | 现有大模型（**已在用**） | 数秒 | 高 | false | 低频/高价值 |
| **Ø** | 关闭 | — | 0 | — | 回落现状 |

**三点关键**：
1. **`calibrated` 是能力标志，不是档位名**——阈值策略由**标志**决定（加新后端不改阈值逻辑）；
2. **L 档是正式档**（不是"回落")——低频场景反而最准；
3. **首次只实现 B 档 + Ø**（impl 建议，采纳）：本机实测**无 key 请求 → 403 空体**，故这是**唯一能跑通全链**的档。

> ① **E-05 幂等闸竞态已修**（提交 `c026391`：`st.deciding`「同址检查 + 置位」，判据 `test-mcl-race.mjs` 9 条先红→后绿）
>    —— 原方案说「不先修竞态就做 M3 等于把 2× 空转放大到每步」，**该前置已解除**；
> ② **`src/mcl.ts` 不是冻结件**（实测 `check-module-growth` 冻结名单仅 3 件；mcl.ts **代码行 456 < 600**，物理 682 行里 226 行是注释）⇒ **改它不触发棘轮、不需要 `--rebase`**（见 §10.5 订正）；
> ③ **与 M4 禁止同批**：M4 早已落（`/eval/stats` 明细），**无冲突**。
> **性质**：**行为设计变更**（不是缺陷修复）⇒ 按 R1/R3 须**具名授权**后开工；本档只到**决策态**，证据标注同全档。

### 11.1 现状（读码 · 给行号）

| 闸门 | 位置 | 现行为 |
|---|---|---|
| **判定幂等** | `mcl.ts:493` | `if (st.channel \|\| st.deciding) return none` —— **本轮只判一次**（`st.channel` 随新任务重置） |
| **late-step skip** | `mcl.ts:595` | `if (!st.channel && step !== 1 && !freshTurn) return decision` ⇒ **只有任务首步 / 「消息到达后的第一个 pre-step」才判** |
| **进入判定** | `mcl.ts:601` | `if (!st.channel) { await decideTurn(…) }` ⇒ 判定**挂在 channel 未定**这一条件上 |
| **当步不判合规** | `mcl.ts:618` | `if (step <= Number(st.materialStep \|\| 0)) return decision` |
| **合规/收益面** | `mcl.ts:673-691` | `topicEcho` → `nextZeroGain` → `shouldSwitchSource` **每步都跑**，但结果**只写进审计行**（`:680/:685/:691` 的 `switchSource` 字段） |
| **换向判据的既有消费方** | `deepsleep-run.ts#judgeYieldRounds` | 读 `audit/yield-rounds.jsonl` → 确定性先筛 → 子代理判 → 严格解析 → 与计数法对账（审计字段 `yieldJudged`）。⇒ **消费发生在"环外批处理"（深睡时），不在步循环内** |

**⇒ 由此得出的 M3 准确含义**（不是我先前口述的"给死判据接线"）：**判定的频率**与**注入的频率**当前被同一个 `st.channel` 绑死；
而**换向信号虽已有消费方，却在环外**（等深睡）。M3 = 把两者解耦 + 给换向信号一个**环内**出口。
⚠ `recall-yield.ts:16-20` 自陈纪律：**接线状态一律以调用点为准，本注释不单独宣称**（由 `check-claim-alignment.mjs` 守）——故上表一律写调用点。

### 11.2 分步实施（每步：交付物 / 判据 / 回滚）

| 步 | 交付物 | 关键约束 | 判据 | 回滚 |
|---|---|---|---|---|
| **M3a** | **判定与注入解耦**：`st.channel` 语义**收窄为「本轮是否已注入」**，新增 `st.judged`（每步判定结果：`sim`/`missReason`/`hasHighConf`）；新增**每步轻判定**入口 | **注入频率不动**（仍只在任务首步）；轻判定**不写 `st.channel`**；保持 `decideTurn` 的幂等语义不破（E-05 修好的闸不许回退） | `test-mcl`：每步都有判定行 **且** 注入仍仅首步（`injected` 计数不随步数增长） | `git revert` 单步 |
| **M3b** | **环内出口**：消费 `shouldSwitchSource`（**复用 `recall-yield` 既有实现，不重造**）⇒ 达阈值即**当步**出动作：**停止继续投同源材料** + 落一条 `mcl-switch` 审计行 | 动作语义取**最小**：只"停当前源"，**不决定换到哪**（与 `recall-yield:11-12` 的既有边界一致：「只出信号，不决定换向到哪」）；**幂等**（同轮不重复出） | `test-recall-yield` 既有 + 新增端到端：「连续 2 步未回引 ⇒ 当步出 `mcl-switch` **有且仅有一行**」 | `git revert` 单步 |
| **M3c** | **成本护栏**（本步是本册**最需要拍板**的设计点） | 每步判定 = 每步一次**融合召回** + （可选）**嵌入相似度**。本机档嵌入免费（`bge-m3` 本地）⇒ 可承受；远端档**按次计费** ⇒ 必须节流 | 成本实测（见 §12-B1）；护栏开关缺省**保守**（不改变现状行为） | 关护栏 / `git revert` |

**M3c 的三选项（须用户拍板 · 见 §12-D1）**：
- **选项 A（推荐）** 按**嵌入是否本机**分流：本机 ⇒ 每步带嵌入；远端 ⇒ 每步只做**无嵌入粗判**（`sim=0` 走既有的 `missReason` 路径），带嵌入判定限每轮 N 次
- **选项 B** 一律每步带嵌入（**简单但远端档成本随步数线性上升**）
- **选项 C** 每步只判、**每 K 步才带嵌入**（K 可配；折中，但引入"K 取多少"的新未决）

### 11.3 不许做的事（红线）

- **不许回退 E-05 的原子闸**（`st.deciding` 的「同址检查 + 置位」是刚修好的不变量，`test-mcl-race.mjs` 会判红）
- **不许改注入频率**（M3 的定义就是"注入频率不动"；动了就是另一件事，须重新过方案）
- **不许绕开 `recall-yield` 另写一份换向判据**（仓内「单一实现」红线；`check-dup-*` 与 `check-claim-alignment` 会抓）
- **不许在 `st.channel` 上再叠语义**（它当前同时表达"判过了"与"注入了"——M3a 的要点正是把它**收窄为后者**）
