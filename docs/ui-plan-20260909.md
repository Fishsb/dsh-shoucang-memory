# UI 补充规划 — 展示与可调设置项（2026-09-09）

> ⚠ **时点文档（2026-09-09）——文中「模型已固化 nssm 服务」「自建 9915 桥」等表述已于 2026-09-11 过时**：nssm 已卸载、旧桥停用，现行向量承载 = **Ollama `bge-m3`** @ `http://127.0.0.1:11434/v1`（见 `ARCHITECTURE.md` §Provider）。本文保留原样作为**当时**的规划记录，正文中相关描述**不代表现状**。

> 性质：规划方案（非协议），供拍板后按批次实施。约束（用户拍板 2026-09-09 修订）：**不破坏画像板块与记忆板块**——「不破坏」≠「零改动」，而是：
> ① **保留**两个板块的视觉语言、分区结构与信息层级（sc-* 组件体系、容量卡/进度条/索引行的既有样式与布局）；
> ② **允许**优化细节（视觉一致性、间距、空态文案、信息可读性）与**增加**新区块/新设置；
> ③ 禁止推翻现有风格、禁止重排核心分区、禁止改既有 sc-* 类名语义（新增样式用新类或复用既有类）。
> 配套：`ARCHITECTURE.md`（架构）· `settings-guide.md`（设置说明）· 本文件（UI 缺口与规划）。

## 0. 审查结论（为什么现在补 UI）

S1-S5 + 向量 GPU 迁移后，**后端能力已超前于面板展示**，形成三类缺口：

| 类 | 缺口 | 实例 |
|---|---|---|
| A 展示缺失 | 新能力无展示位 | 晨起摘要 delta、向量召回状态（provider/缓存/融合）、召回命中分析、episode/转正进度 |
| B UI 脱节 | 旧 UI 指向已退役链路 | 「向量检索」区仍驱动旧 vector_search.py + 模型下载，实际召回已走新 bge-m3 GPU 服务 |
| C 设置无通道 | 架构文档已列的可调键无 UI | embed 三键（改云端/开关）、蒸馏节流键缺展示态、llmProvider/llmModel 模型选择 |

## 1. 展示补充（保画像/记忆板块结构 → 增加区块与内容）

### 1.1 新增「向量召回」状态区块（记忆板块尾部 or 参数调节独立节）
只读展示，复用 `sc-mem-stat`/`sc-mem-grid`：
- **provider**：DmlExecutionProvider (GPU) / CPU / 云端名 / 未配置
- **模型**：bge-m3 · 1024d · q8
- **缓存**：`.vector-cache.jsonl` 行数（37→N）+ 磁盘 KB
- **最近一次召回**：mode（fusion/lexical）+ 延迟 ms（日志或内存统计）
- **命中示例**：最近语义查询 → 命中行（诊断价值）

数据源：新增只读端点 `GET /vector/status2`（读 vec.ts 运行态：cfg 生效值 + 缓存行数 + 最近召回内存计数），或复用 `shoucang_recall` 自测。

### 1.2 新增「晨起摘要 delta」区块（记忆板块顶部、成长卡旁）
- 展示 `suite/knowledge/delta.md` 当前内容 + 剩余有效期（48h）+ 已注入次数（injections 字段）
- 空态文案（不生成时不显示区块）
- 复用 `sc-mem-stat`/`sc-mem-sub`；只读

### 1.3 画像板块与记忆板块的**既有结构保留**（不破坏边界）
- `renderPersona`：USER/AGENT 容量卡 + 进度条 + 指针行 → **不改**
- `renderMemoryExpanded`：蒸馏运行/本月成长/记忆库状态/知识索引/pending/notes → **不改**
- 新增区块 = `view.appendChild` 追加在 §6 之后（记忆板块）或新独立视图，不侵入现有函数体

## 2. 可调设置项补充（复用 /set + /distill/config + /deepsleep/config 既有通道）

| # | 设置项 | 通道 | 类型 | 说明 |
|---|---|---|---|---|
| V-1 | 向量开关 embedEnabled | /set → injection? 或 suite config | toggle | 开=融合召回（默认）；关=纯词法。写 scheduler.json |
| V-2 | 向量 provider 选择 | 新 /embed/config | 下拉 | 本地 bge-m3（默认）/ 云端 API（填 baseUrl+model+keyEnv） |
| V-3 | 蒸馏模型选择 llmProvider/llmModel | 已有 /distill/config | 下拉 | 从 llm.listProviders 枚举（对齐 B-3 旧欠账） |
| V-4 | 深睡阈值组 | 已有 /deepsleep/config | 滑块×2 | 停滞时长 / 探测窗口（已存在，核对 UI 完整） |
| V-5 | 蒸馏节流组展示态 | 已有 /distill/config | 只读+可改 | enableDistill/idleWakeMs/minTurnChars/prescan 已在参数调节，确认展示 running vs persisted 差异 |

**原则**：新增设置集中于「参数调节」视图的追加节或新「向量/模型」节，**不触碰画像/记忆板块的既有控件语义**；写通道全部走既有 /set 或 scheduler.json 模式（备份先行 + 重载生效提示，沿用 /distill/config 范式）。

## 3. UI 结构调整建议（最小侵入 + 允许细节优化）

```
画像板块（保结构）      记忆板块（保 §1-§6 + 尾部追加新区块）
                        ├─ §7 向量召回状态（只读，1.1）
                        └─ §8 晨起摘要 delta（只读，1.2）
参数调节（追加节）
                        └─ 「向量与模型」节（V-1..V-3）
深度睡眠（不改）
插件集合（不改）
```

- 画像/记忆板块**分区结构、信息层级、sc-* 样式语言保留**；新增区块用 `view.appendChild` 在函数尾部追加
- 细节优化（§6）可触碰既有板块的**视觉细节与局部文案**，但不动分区结构/信息层级/样式语言/既有类语义
- 新增样式优先复用既有类；确需新样式用新类（如 `sc-vec-card`），不改既有类语义
- 全部 DOM 用既有 `el()` helper

## 6. 可优化细节清单（不破坏前提，逐项可独立落地）

> 依据：client.js 审查观察到的既有可改进点。每项改动局部、可回退；执行时先截图基准再改。

| # | 位置 | 现状 | 优化 |
|---|---|---|---|
| D-1 | 画像板块·容量卡 | USER/AGENT 两卡各显 `chars / cap` + sub 行条数 | 卡内统一加「% 进度条」行内小条（既有 sc-cap 复用），免去下方独立进度条区 → 卡信息自足；进度条区保留做汇总 |
| D-2 | 画像板块·空态 | 无指针行时仅「（暂无指针行）」灰字 | 空态补引导文案（如"画像会随蒸馏/深睡自动成长，见记忆板块·本月成长"）——复用 sc-mem-empty 样式 |
| D-3 | 记忆板块·蒸馏 hero | hero 卡空态副文案长且挤 | 空态换两行（机制说明一行 + 预期一行），复用 sc-mem-stat-sub |
| D-4 | 记忆板块·知识索引 | 8 条预览 + "展开全部"按钮，行高 12.5px | tag pill 加 title 提示（悬停显示完整主题）；行 hover 背景色与 pointer 一致（视觉统一） |
| D-5 | 记忆板块·pending/notes | notes chips 仅文件名 + 小节数 | chip 悬停 title 已含小节名——改为 chip 内直接显示前 2 小节名（ellipsis），减少一次悬停 |
| D-6 | 状态栏 | 单一 sc-statusbar 灰字 | 增右边距 + 关键状态（画像/向量 mode）分段着淡色（复用 sc-muted/sc-accent 变量，不加新色板） |
| D-7 | 跨视图一致性 | 部分按钮 `.sc-btn.subtle` 与链接按钮 `.sc-idx-more` 混用 | 统一「次级操作」为 subtle 按钮样式；「查看详情」类保持链接式（语义区分） |

> D-1..D-7 均只改 client.js 内局部 DOM/行内样式，不涉及 sc-* 既有类重定义；每项提交后跑 build:client 同步 lib + 面板截图对比。
