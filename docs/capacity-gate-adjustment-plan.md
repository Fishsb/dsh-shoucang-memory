## 2. 根因（收敛为 4 条）

### R1 · 计数口径三处不统一 —— **面板那个数字在结构上不可能显示故障**
| 位置 | 口径 | 同一份 USER.md |
|---|---|---|
| `src/distill-write.ts:172`（**唯一硬拒**） | `body.length` 含空白 | **2967** ⇒ 98.9% |
| `src/panel-memory.ts:213`（面板） | 去空白 | **2619** ⇒ 87.3% |
| `memory_write_gate.mjs:107` / `memory-append.mjs:244` | 去空白 | **2619** |

**判决会翻**（已复现原式）：USER.md 加一行 80 字符 + 小节名 8 字符 ⇒ 含空白 `3063>3000` **拒**；去空白 `2715<3000` **放行**。
> 用户看面板 87% 以为还有 13%（≈390 字符），写门侧只剩 **33 字符** ⇒ 下次必拒。**不是分辨不了，是两个数互相矛盾。**

### R2 · 策略判定长在写入机制里（结构性）
一个设置值被**四台机制各自解释**：`distill-write.ts:172`（硬）· `memory_write_gate.mjs:271`（软）· `memory-append.mjs:249`（软）· 脚本内 `|| 5000`（默认值第三份）。**没有任何单一事实源。**

### R3 · 失败不可观测（穷举 10 条致盲机制，列最重的 5 条）
1. **跨通道聚合掩盖**：`deepsleep-core.ts:324-340` 把六通道合成一个 `landed` ⇒ 画像零落地的轮次**全判 `landed=true`**（实测 **29 轮**），`failStreak` 从未达 3，告警 `deep-sleep-release` 台账 **0 行（从未响过）**。
2. **拒绝率被稀释**：`memory-reconcile.mjs:182-185` 分母是全部 writeEvents(**982**) ⇒ 画像 167 次被稀释成 **7.4%**；UI 在 `panes-observe.js:335`。
3. **采了不显示**：`panel-memory.ts:84/88/100` 采集 `gateRejects`，`src-client/*.js` **零命中**。
4. **回执盲区**：`check-write-receipts.mjs` 只断言回执**带** `attempted`/`written` 字段，**不断言 `written>0`**；且 **142/167 = 85%** 的拒绝**连回执都没有**。
5. **写者不可见**（新发现）：`AGENT.md` mtime = `2026-09-21T17:35:33`，与 18:02 备份**逐字节相同**，而 17:20–17:45 台账**零写入事件**。⚠ **指认不出写者，标未验证**。

### R4 · 目标本身不可达 + 放行≠抵达
- `AGENT.md` 的 `[原则]/[路径]` 行**自身就 8586 字符 = 容量门 286%** ⇒ **3000 对它从不成立**。
- `hot-stable.ts:75-78` 注入配额是 `capStable*0.55`，**与这三个框无关**；实测注入面 agent 块 23 行里 **22 行是 `[原则]` 行、画像行 0 行**；换无关 query 结果**逐字相同**。

## 3. 目标态

**让三个框的行为与它们承诺的一致**：超限**默认不阻断**（提醒 + **强制留痕**），并提供**一个**显式开关恢复硬拒；同时**统一计数口径**。

### 3.1 为什么缺省取"不阻断"（已裁定）
1. **四条路径里三条已是不阻断** ⇒ 缺省取不阻断是**与多数现状一致**，改动面最小。
2. 用户 2026-09-16 已就索引行判定「直接拒绝不符合意图，提醒就可以」（`memory_write_gate.mjs:272`，含三次修正记录）⇒ **本决策是推广既有判定，不是新政策**。
3. 取硬拒则**修完默认仍坏**（USER.md 照旧停在 9/16），且 R3-3 未修前**用户看不到任何提示**，会误判"这功能没用"。

### 3.2 副作用（知情）
- 文件会**无界增长**（`AGENT.md` 已 332%）。
- ⚠ **但不会压坏注入面**：注入配额独立（`capStable*0.55` + `clampLines` 停在首超）⇒ 增长表现为"更多行进不来"，**不表现为预算超支**。代价是存储与可读性。
- 开关随时可拨回。

## 4. 施工前形态约束（**三条硬约束 · 定错则验收全绿也没用**）

### B1 · **不得新增返回值状态**
`writeProfileLine` 返回 `{st:'added'|'dedup'|'failed'} | {st:'rejected';why}`（`distill-write.ts:135`，契约副本 `deepsleep-contract.ts:62`）。若为 `warn` 新增第四态（如 `st:'warned'`）：
- 蒸馏侧 `:525-527` 是 `if added / else if rejected / else if failed`（**无 else**）⇒ 新态掉空档，回执判据 `:538` 把它记成 **`skipped`**（真落盘记成未消化）。
- 深睡侧 `deepsleep-run.ts:755-758` 是 `if added → profileAdded++ else → profileTried++` ⇒ 新态落进 `profileTried`，`otherChannels.done` 只累 `profileAdded`（`:836-839`）⇒ `deepSleepLanded` 判 `landed:false` ⇒ **水位回滚、同批下轮重蒸**。

⇒ **一个真落盘被两个消费方各错一个方向**，而 `typecheck`、`check-write-receipts`、`check-profile-admission` **全都不红**。
⇒ **正解**：通过后仍返回 `{st:'added'}`，告警另挂**可选字段**（如 `warn?: string`）——两消费方零改动。

### B2 · **只关"容量支路"，不得整条门放行**
`memory_write_gate.mjs` 退出码（`:6`）：`0` 允许 / `1` 超容量(strict) / **`2` 指针悬空** / **`4` 格式** / **`5` 疑似凭据**。
⇒ 开关**只**替换容量判据；`exit 2/4/5` 维持原样。写成"非 hard 即通过"会把**悬空指针与明文密钥一起放行**（安全红线）。

### B3 · **开关必须贯通到子进程链**
两份门脚本各有一支 `SHOUCANG_CAP_STRICT==='1'` ⇒ `exit 1` 不写（`memory_write_gate.mjs:248/275`、`memory-append.mjs:250`）。宿主 `capEnv()`（`distill-write.ts:88-91`）**从不注入该变量**。
⇒ 若部署侧曾设 strict，"关掉的门"在子链上**仍是硬的，且无任何信号**。必须**透传**到 `capEnv()`，或**显式声明**"宿主开关不覆盖子链 strict"。

### 4.4 附：并发丢写是**开关化的前置条件**（非加固）
`writeProfileLine` 落盘走 `atomicWriteFile`，源码原话「**不取锁**」（`section-rewrite.ts:14/26`）；`applyPrinciples` 的 `commitPrinciples` **同样不取锁**（`deepsleep-apply.ts` 里只有 `applyPointerOps` 取锁）。
⇒ `AGENT.md` 两个无锁写者**互为末写者胜**；回读校验**只比字节数**（`statSync(p).size == byteLength(text)`）⇒ 内容被并发覆盖且长度相同**检测不出**，当前所有签名都报 `added`。
⇒ 该缺陷**此前被 167 次全拒掩盖**。开关放开前**必须**补「**写后回读内容含该行**」，否则丢写会被记成成功。

## 5. 分册（按依赖序 · 每步可独立验证）

### 册零 · 统一计数口径（**P0 · 不依赖拍板**）
**做法**：`distill-write.ts:172` 的 `body.length` 改为**去空白**，与另三处同源。
**落点**：1 处判定 + 抽取 1 处复用（**不新建模块**——余量 11 行够用；不抽 `decideCapacity()`——≤2 使用点）。
**效果**：`USER.md` 当场解冻（`2619+85+7+8 = 2719 < 3000`）。
**边界**：`AGENT.md`（8895>3000）**仍拒** ⇒ 开关仍需要；两者是**两帖药**。

### 册一 · 零代码止血（**P0 · 立即可用**）
**做法**：参数页把 `cap_agent` / `cap_user` 从 3000 调到 ≥10000（范围上限 30000，`panel-config.ts:280`）。
**依据**：`liveCaps`（`:77-86`）**每次写入都重读** `scheduler.json`（注释原文「面板调容量门后写门即时生效，不必重载插件」）；`capEnv`（`:88-91`）把同值透传给 principles 子进程 ⇒ **两条路径同时放行**。
⇒ **足以立即止血，零代码、当天生效**；开关化因此**只是长期改善**，两者**解耦**。

### 册二 · 开关（**P1 · 缺省已裁定 `false`**）
**做法**：新增**布尔**键 `capacityGate`（`true`=拒 / `false`=不拒），缺省 **`false`**。
- **为何布尔而非三档**：`warn` 与 `off` 对"能不能写进去"**完全等价**（差别仅是**实现者**的可观测性）；三档里**两档不可分辨** ⇒ 违反仓规「判据须可分辨」。且硬拒在索引行侧**已是**可开关语义（`SHOUCANG_CAP_STRICT`，默认关）——画像侧是**唯一没接的通道**。
- **为何不新建 `src/capacity-config.ts`**：门禁余量 11 行够用（+1 行 zod +1 行条件）；新建文件会把 src 模块数 **104→105**，连带 `check-arch-sync` ①② 与两处文档（`AGENTS.md`/`docs/ARCHITECTURE.md`）必须同改——**成本大于收益**。
- **落点六处**（⚠ 前身草案漏了后两处）：
  ① `scheduler.ts` schema +1 行 ② `distillOptionsOf` 映射 +1 行 ③ `distill-write.ts:172` 换判据 ④ `panel-config.ts:242`(allowed) + `:321`(SCHED_KEY) + `:282`(RANGE) ⑤ **`panel-contract.ts:53` 的 `SET_SCALAR_KEYS`**（⚠ 不在 panel-config，两处由 `check-budget-override` ⑦c 逐键锁死）⑥ **两个读侧 + 3 个前端点**（`panel-memory.ts:181-218/336` · `panel-config.ts:81-93` · `panes-memory.js:243/280` · `panes-overview.js:114/320` · `panes-memory-detail.js:136/151`）
- ⚠ 类型：枚举键**原样写字符串**，**不得落进 `Number(value)||0`**（`panel-config.ts:379`；仓内两次先例：`storeMode` 只加白名单未加映射 ⇒ 实测 400；`embedding.dimension` 同型）。
- ⚠ **一个全局档位**，**不是**三个框旁各一个（后者必产生"改一个、另两个不同步"的假可控）。

### 册三 · 可观测补盲（**P1 · 不依赖拍板**）
1. **超限仍留痕**（关键）：`distill-write.ts:526` 的 `gate-reject` 是**当前唯一失败信号**（实测 167 条）。不拒之后若不留痕，就是**亲手关掉唯一信号** ⇒ 须换名（如 `capacity-over`）**继续落一行**。
2. **六通道判据拆开**（`:324-340`）：能分辨"画像通道有提案零落地"。
3. **`gateRejects` 接消费面**：前端显式渲染（现零命中）。
4. **拒绝率按通道**：分母不用全体 writeEvents。
5. **写后回读内容**（§4.4 前置条件）。
6. **失败原因带出来**：`writeProfileLine` 的兜底 `catch { return {st:'failed'} }`（`:160`）**吞掉全部原因**；`distill-infra.ts:85` 的 `audit()` 也是 `catch{静默}`（未调 `fail()`，与 `:70` 的 `ledger` 纪律相反）。
7. ⚠ **不得**加 `written==0 连续 N 次`判据：`attempted` 恒为 1 ⇒ 会退化成**恒真告警**。数据源应改为 `kind=gate-reject` + target∈{USER,AGENT}（167 条，全期覆盖）。
