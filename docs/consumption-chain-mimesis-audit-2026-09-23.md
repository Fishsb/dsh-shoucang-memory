## 1. 目标锚定（先说清"要拟态成什么"）

### 1.1 目标原话与仓内锚点

用户原话（本会话）：**"消费链路模拟人类在同样的任务情境下的思考以及执行任务的过程"**。
仓内对应锚点 = `feature:sc-s05`「**人化执行循环**」，其 `userView` 注册原文即 **"agent 按人类工作方式执行任务"**；落点文件含 `skill/human-execution-loop.md` · `skill/task-protocols.md` · `src/mcl.ts`【读码】`nav_graph mode=task SC-S05`。

⇒ **目标不是"多加几条注入通路"，而是"让供给的时机与内容匹配人类在那一刻的认知状态"**。这条口径由 `three-layer-supply-plan` §2 首次提出（"五通路全部在任务开始这一个时刻消费，而三层行为发生在三个不同时刻"）。

### 1.2 权威文献复核（本轮新增三支）

仓内 09-14 三份研究档已建立六线索（信息觅食 / NDM / 问题求解 / 认知架构 / 元认知 / 自我效能）。本轮**重新检索核验**，并补上仓内**缺失的两支**：

| 支 | 出处 | 核心主张 | 仓内旧档是否覆盖 |
|---|---|---|---|
| **情境意识 SA 三级** | Endsley (1995) *Toward a Theory of Situation Awareness in Dynamic Systems*, Human Factors【一手·exa 取到原文 PDF 与 DOI `10.1518/001872095779049543`】 | SA 分三级：**L1 感知**（环境要素）→ **L2 理解**（综合成意义）→ **L3 预测**（未来状态）。决策质量受 SA 质量约束——**L3 不能跳过 L1/L2 直接获得** | ❌ **缺失**（旧档有"情境感知"字样但无三级结构） |
| **元推理监测/控制** | Ackerman & Thompson (2017) *Meta-Reasoning: Monitoring and Control of Thinking and Reasoning*, Trends in Cognitive Sciences【一手·exa 取到 Cell/PubMed/作者 PDF 三处】 | 元推理 = 对**推理过程本身**的监测（progress / 难度 / 信心）与控制（继续 / 换策略 / 终止）。区别于元记忆（只管检索） | ❌ **缺失**（旧档有 Nelson & Narens 元认知，但那是**记忆**元认知；**推理**元认知是独立一支） |
| **前瞻记忆线索驱动** | Einstein & McDaniel (1990, 2005) 多进程框架【检索·exa 取到 DOI `10.1002/acp.775` / `10.1037/0096-3445.134.3.327`】 | 前瞻记忆（记住"将来要做某事"）靠**线索触发的自发提取**，而非持续战略监控——后者在高负荷下系统性失败 | ✅ 已覆盖（`three-layer-supply-plan` §3.2 引用） |
| **努力的成本权衡** | Kurzban et al. (2013) *An opportunity cost model of subjective effort*, BBS【一手·exa 取到 PMC/Cambridge/Gwern PDF】 | 主观努力感 = 对**机会成本**的读出；认知资源分配是**成本核算**结果，不是燃料耗尽 | ❌ 缺失（可作"何时该停止投入"的理论补充） |
| 信息觅食 / 边际价值停止 | Pirolli & Card (1999)；Goldstein et al. (2019) | 已有，本轮未推翻【沿用】 | ✅ |

**⇒ 文献层结论**：人类在该情境下的认知过程应建成 **三层循环 × SA 三级 × 元推理监测控制** 的组合模型。旧档的三层循环是对的，但**SA 三级与元推理（推理侧，非记忆侧）这两支是空缺**——而它们恰好对应"各种情境状况的决策思考"这一问。

### 1.3 整合模型（本轮定稿口径）

```
┌─ 外层·任务级（SA L1→L2→L3 + Zimmerman 自我调节）
│   感知任务要素 → 理解任务意义 → 预测走向
│        ↓ 产出「方向」（原则/偏好/边界/效能）
│   ┌─ 中层·行动级（Ackerman 元推理：监测 + 控制）
│   │   监测：进展如何？难度多大？信心够吗？
│   │        ↓ 控制：继续 / 换策略 / 终止 / 求助
│   │   ┌─ 内层·认知级（编码特异性 + 信息觅食）
│   │   │   情境匹配提取 → 气味评估 → 边际价值停止
│   │   └────────────────────────────────────────────┘
│   └──────────────────────────────────────────────────┘
└────────────────────────────────────────────────────────┘
```

**三层各自的"判据"是什么**（这是审查的对照标尺）：

| 层 | 人类判据 | 落成可判定项 |
|---|---|---|
| 外层 | SA L1–L3 | 能否说出「当前状态/目标/差异」三元组 |
| 中层 | 元推理监测→控制 | **进展**（有无实质推进）· **置信**（够不够）· **成本**（值不值）→ 继续/换向/停 |
| 内层 | 编码特异性 + 觅食 | 按**情境线索**提取（非内容相似）· 边际价值下降即离开斑块 |

## 3. 逐维对标审查

### 3.1 外层（任务级）：方向 ✅，但 **SA L1/L2 缺位**

- **做实的**：恒定面每步必在，`[原则]`/`[路径]` 承载"方向"。实测每步 2391–2977 字符，其中 `[原则]`+`[路径]` 占 87%。**拟态意图明确且有效**。
- **缺的**：按 Endsley，SA 是 **L1 感知 → L2 理解 → L3 预测** 的链。守藏供给的全是 L3 的**产物**（"我认为该怎样"），而 **L1（当前任务是什么）/ L2（这意味着什么）没有任何专用供给**。此前 `docs/human-task-loop...` §3.5 已指出"缺显式三元组"，本轮复核**仍然成立**。
- **【判读】影响**：模型带着"方向"却未被供给"当前情境的显式理解"⇒ 外层反思无法归因（不知道原始目标表征是什么就已完成）。这一条与"效能估计缺失"同源。

### 3.2 内层（认知级）：拟态最强，但**维度被收窄过**

- **`cueDims` 实测 = `["scope","task"]`**【读码】`criteria.json`。`subject`/`event` **已删**，理由是"两侧皆不产 ⇒ 留着就是假契约"（`cueDimNote` 原文）。
- **这是正确的工程决定**（"契约须描述现状"），但**从拟态角度是维度缺失**：编码特异性研究的提取线索是「在哪、在做什么、涉及谁、什么情绪」四维。守藏现在只有前两维。
- **另有一处**：`taskCueOf` 的匹配是**受控词表 + 整词/子串判定**（`situation-key.ts:130-159`），不硬抽正则——判因充分（中文硬抽恒空、英文过匹配 37%）。这是**对拟态的诚实降级**，好过伪造。
- **【判读】**：内层判据（相关性 + 情境 + 熟悉度）都已在线，**拟态度在"能做的范围内"是够的**；缺口是 `/` 情绪维度（valence）虽已补进 `ringOrder` 末位，但 **cue 层不产**，所以 valence 只能靠"无命中兜底组"进。

### 3.3 中层（行动级）：⚠ **本轮最重发现 —— 元推理监测/控制"绿灯下的哑火"**

这是本次审查的**核心发现**，必须给完整证据链。

**机制层（在线）**：
- M3a：`mcl.ts:678-685` 每步落 `phase:'judge'` 行；`planStepJudgement` 只出"是否离开当前源"的信号【读码】。
- M3b：`mcl.ts:768-772` `emitSwitch` 幂等，落 `mcl-switch` 行【读码】。
- 收益折减：`recall-yield.ts#foldZeroGain` 三态（`action` / `echo` / `none`）。

**真机层（哑火）**【实测·本会话命令】：
```
ledger.jsonl 尾部 mcl-step = 1758 行
  phase: judge 1292 · inject 208 · compliance 258
  switchSource=true  →  0 行
  mcl-switch         →  0 行（全库尾部 60000 行内）
  zeroGain 分布      →  0 x 1293（恒 0）
judge 行字段分布：
  acted=True  574（有真实动作）· acted 缺失 719
  yieldSignal='action' 574
  echo=True 37 · echo=False 537 · echo 缺失 719
```

**根因（读码 + 实测交叉）**：
- `foldZeroGain`（`recall-yield.ts:82`）：**只要 `acted !== null` 就用 action 分支**——`acted=true ⇒ zeroGain = 0`（归零）。
- 真机 `acted=true` 占**全部可观测样本（574/574）**⇒ **每一次折减都是归零** ⇒ `zeroGain` 结构性恒 0 ⇒ `shouldSwitchSource(0)` 永假。
  ⚠ **2026-09-23 圆桌会议订正（本审查档原判"从未触发"，已推翻）**：`acted` 取自 `agent.session.snapshotEvents()`（`mcl.ts:723`）**整个会话**，判据是 `evs.some(e => e.type === 'tool/call')`（`:757-759`）⇒ 语义 = **「本会话是否曾经调用过任何工具」**。会话内调过一次即**恒 true**（全三档实测 `acted=true` 1356 / `false` **0**）⇒ 换向出口在会话生命周期内**不可逆锁死**。这不是"占比偏高"，是**存在性量被当成进展量**。
- ⚠ **原「84.0% 非空」的引用已撤回**：`yield-rounds.jsonl` **无 09-22 数据**，84.0% 是 09-14/15 低值拉低的**累计均值**；**09-17 起单日已是 99.4%**（早于 D5 五天）⇒ 与 D5 无关（见 `consumption-chain-mimesis-plan` §1.1 R2）。
- **代码自己写过这个风险**：`recall-yield.ts:41-43` 原文承认"84% 近恒定 ⇒ 单用它会把换向出口**变哑**"，但当时的处置是"不做朴素换源"，随后 **D5（2026-09-22）仍把 `acted` 提为**主信号**（`recall-yield.ts:53` "真实动作 > 词面代理 > 无证据"）⇒ **注释预警的风险已经发生**。

**为什么这是"会掩盖其他问题"的缺陷**：
| 表面读数 | 实际含义 |
|---|---|
| judge 行 **1293** 条、每步都有 | ✅ 判定频率达标（M3 目标达成） |
| `switchStop=false` 1293 条 | 看起来"没有触发换向"是**正常状态** |
| `zeroGain=0` 恒真 | 看起来"每一步都有进展" |
| **真相** | **"线索变弱即换向"这条人类中层判据，从上线至今一次都没有真正生效过** —— 它不是"没触发"，是**结构上不可能触发**（归零信号占比 ~100%） |

⇒ 与仓内已登记的「**探针 PASS ≠ 生效**」「代理指标非判据」同族：**机制在线、数据在流、结论从未产生**。

### 3.4 前瞻记忆：✅ 真拟态亮点（应保护）

- `due-window.ts#dueSoon`（7 天窗，**单一实现**，`relation-ring` 与 `ring-supply` 共用）【读码】。
- `ring-supply.ts:184`：`why: hits.length ? 'cue' : dueSoon(...) ? 'due' : 'fallback'` —— **到期承诺单独成组**，组序仅次于情境命中。

- 【实测】环记录持续在写（`ring-commit` 当日多笔）。

### 3.5 元推理（事后归因）：✅ 在线且有真实数据
