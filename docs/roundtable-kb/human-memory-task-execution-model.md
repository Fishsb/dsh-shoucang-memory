## 1. 总览：人作为目标驱动的生物计算系统

人面对任务时，不是先全部想好再机械执行，而是一个不断循环的系统：

```text
环境 / 任务 / 他人
        │
        ▼
感觉记忆：输入缓冲
        │
        ▼
注意力门控
        │
        ▼
工作记忆：当前任务现场
        │
        ▼
目标栈 / 中央执行：调度与决策
        │
        ▼
计划 → 执行 → 反馈 → 修正 → 巩固
        ↑                         │
        └──────── 循环 ───────────┘
```

核心结论：

- **感觉记忆**是输入缓冲。
- **工作记忆**是内存和 CPU 缓存。
- **长时记忆**是硬盘和知识库。
- **外部记忆**是云盘、笔记、文档、Git、IDE、TODO。
- **中央执行**是注意力调度器。
- **目标栈**决定当前该做什么。
- **反馈循环**决定如何修正和进步。

## 2. 记忆分类

人的记忆可以从不同维度分类。最核心的是两套：按保持时间分，按意识和内容分。

### 2.1 按保持时间 / 加工阶段分

| 类型 | 特点 | 程序化类比 |
|---|---|---|
| 感觉记忆 | 视觉、听觉、触觉等原始输入，保持极短 | 输入缓冲区 |
| 短时记忆 | 当前注意的信息，约 7±2 个组块，易忘 | 临时内存 |
| 工作记忆 | 边记边操作，容量约 4 个组块 | 内存 + CPU 缓存 + 寄存器 |
| 长时记忆 | 长期甚至终生存储，容量近乎无限 | 硬盘 / 知识库 |

工作记忆通常包括：

- **中央执行**：调度、选择、抑制干扰。
- **语音环路**：语言、复述、内心默念。
- **视空间画板**：图像、空间、心理旋转。
- **情景缓冲**：整合不同来源的信息。

### 2.2 按意识与内容分

```text
记忆
├─ 外显记忆 / 陈述性记忆
│  ├─ 情景记忆：个人经历的事件
│  └─ 语义记忆：事实、概念、规则、词汇
└─ 内隐记忆 / 非陈述性记忆
   ├─ 程序性记忆：技能、习惯
   ├─ 启动效应：先前刺激影响后续反应
   ├─ 经典条件反射：刺激与反应关联
   └─ 非联想学习：习惯化、敏感化
```

### 2.3 其他常见功能分类

- **前瞻记忆**：记住未来要做的事。
- **回溯记忆**：记住过去发生的事。
- **自传体记忆**：个人生活史。
- **情绪记忆**：带强烈情绪的记忆。
- **来源记忆**：记住信息来自哪里。
- **闪光灯记忆**：重大事件时形成的生动记忆，但可能被重构。

### 2.4 记忆总览图

```text
记忆
├─ 感觉记忆
├─ 短时记忆 / 工作记忆
└─ 长时记忆
   ├─ 外显 / 陈述性
   │  ├─ 情景记忆
   │  └─ 语义记忆
   └─ 内隐 / 非陈述性
      ├─ 程序性记忆
      ├─ 启动效应
      ├─ 条件反射
      └─ 非联想学习
```

## 3. 程序化类比：记忆操作系统

可以把人的记忆系统理解为一个“多级存储 + 中央调度 + 外部外挂”的操作系统。

### 3.1 存储层级表

| 人类记忆 | 程序化类比 | 作用 |
|---|---|---|
| 感觉记忆 | 输入缓冲 | 短暂保留原始刺激 |
| 工作记忆 | 内存 / CPU 缓存 | 当前任务现场 |
| 长时记忆 | 硬盘 / 数据库 | 长期知识、经历、技能 |
| 外部记忆 | 云盘 / 外挂硬盘 | 笔记、文档、Git、搜索、TODO |
| 中央执行 | 调度器 | 注意力分配、任务切换、抑制干扰 |
| 目标栈 | 任务队列 / 调用栈 | 管理目标和子目标 |
| 反馈系统 | 传感器 + 监控 | 比较预期与实际 |

## 4. 调度系统：注意力、目标栈与上下文切换

### 4.1 中央执行

中央执行是工作记忆的核心调度器，负责：

1. 选择当前目标。
2. 激活相关长时记忆。
3. 分配工作记忆资源。
4. 抑制无关干扰。
5. 监控执行反馈。
6. 切换上下文。
7. 决定何时巩固、何时放弃。

### 4.2 目标栈与任务队列

```text
目标栈 / 任务队列
├─ 大目标：完成登录功能
│  ├─ 子目标：建用户表
│  ├─ 子目标：写登录接口
│  ├─ 子目标：写前端表单
│  ├─ 子目标：写测试
│  └─ 当前动作：修改密码校验逻辑
└─ 中断：同事来消息
```

特点：

- 大目标拆成子目标。
- 完成后弹出，继续下一个。
- 新任务可插入，形成中断。
- 紧急任务可能抢占当前任务。
- 多任务时需保存现场，再恢复。

### 4.3 注意力门控

注意力决定什么信息能进入工作记忆：

- **选择性注意**：只看关键信息。
- **持续性注意**：长时间保持专注。
- **分配性注意**：同时处理多个信息源。
- **抑制控制**：忽略无关干扰。

程序化类比：
注意力是门控开关和过滤器，决定哪些数据进入内存。

### 4.4 上下文切换

多任务时，大脑会：

1. 保存当前任务现场。
2. 加载新任务现场。
3. 处理新任务。
4. 再恢复原任务。

代价：

- 切换成本高。
- 容易遗忘细节。
- 工作记忆过载。
- 效率下降。

所以程序员常用 TODO、注释、Git、IDE 标签页来外挂上下文。

### 4.5 调度表

| 调度组件 | 功能 |
|---|---|
| 中央执行 | 注意力分配、任务切换、抑制干扰 |
| 目标栈 | 大目标拆子目标，完成后弹出 |
| 优先级队列 | 紧急 / 重要排序 |
| 中断处理 | 新消息、电话、报错 |
| 上下文保存 / 恢复 | 切换任务时保存现场 |
| 资源限制 | 工作记忆约 4 个组块 |

## 5. 使用与循环：预测—行动—检查—修正

### 5.1 核心循环

人的任务执行不是直线，而是循环：

观察环境 → 理解当前状态 → 调取记忆 → 选择下一步 → 执行动作 → 检查反馈 → 修正模型 / 计划 → 更新记忆 → 回到观察环境。

也可以总结为：

- **OODA**：观察 → 定向 → 决策 → 行动。
- **PDCA**：计划 → 执行 → 检查 → 处理。
- **程序开发**：需求 → 设计 → 编码 → 测试 → 部署 → 维护。

### 5.2 循环图

```text
              ┌──────────────┐
              │ 目标 / 意图  │
              └──────┬───────┘
                     ▼
        ┌────────────────────────┐
        │ 感知：读取环境 / 任务  │
        └───────────┬────────────┘
                    ▼
        ┌────────────────────────┐
        │ 注意：筛选关键信息     │
        └───────────┬────────────┘
                    ▼
        ┌────────────────────────┐
        │ 提取：从长时记忆调经验 │
        └───────────┬────────────┘
                    ▼
        ┌────────────────────────┐
        │ 计划：拆解、排优先级   │
        └───────────┬────────────┘
                    ▼
        ┌────────────────────────┐
        │ 执行：写代码、操作、说 │
        └───────────┬────────────┘
                    ▼
        ┌────────────────────────┐
        │ 反馈：编译、测试、日志 │
        └───────────┬────────────┘
                    ▼
        ┌────────────────────────┐
        │ 比较：预期 vs 实际     │
        └───────────┬────────────┘
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
      一致：继续          不一致：修正
          │                   │
          ▼                   ▼
    巩固记忆 / 完成      形成假设 / 再实验
          │                   │
          └─────────┬─────────┘
                    ▼
              回到感知 / 计划
```

### 5.3 嵌套循环

```text
微循环：注意 → 提取 → 操作 → 检查
   ↓
小循环：写一行 → 看报错 → 改一行
   ↓
中循环：写函数 → 运行 → 调试 → 提交
   ↓
大循环：做功能 → 测试 → 重构 → 发布
   ↓
超大循环：需求 → 设计 → 开发 → 维护 → 复盘
```

越外层越慢，越内层越快。做程序开发时，这些循环同时运行。

### 5.4 记忆操作循环

| 认知过程 | 程序化类比 | 说明 |
|---|---|---|
| 编码 | 写入 / 序列化 | 把经验转成可存储格式 |
| 巩固 | 持久化 / 索引重建 | 短时转长时，重复、睡眠、情绪 |
| 提取 | 查询 / 缓存命中 | 线索触发，模式匹配 |
| 遗忘 | 淘汰 / 衰减 / 压缩 | 减少干扰，保留重要 |
| 再认 | 匹配 | 见到能认出 |
| 回忆 | 主动检索 | 没有线索也能调出 |

## 6. 从思考到执行的完整流程

1. **感知任务**
   读需求、听别人说、看报错、看代码。

2. **理解与目标设定**
   把模糊任务变成目标，形成成功标准。

3. **激活记忆**
   从长时记忆调经验，从外部记忆查文档、搜索、旧代码。

4. **计划与分解**
   大任务拆成小任务，排优先级。

5. **执行**
   写代码、点按钮、敲命令、查日志。

6. **监控与反馈**
   编译、运行、测试、看日志、看页面。

7. **调试与调整**
   形成假设，做实验，改一行、加日志、断点、单元测试。

8. **完成与固化**
   提交、写文档、复盘，把经验转入长时记忆。

## 7. 实例：程序开发中的登录功能

```text
需求：用户能登录
   │
   ▼

   ├─ 写登录接口
   ├─ 写前端表单

   │
   ▼

   写代码 → 运行 → 报错 → 读日志 → 假设 → 改 → 再运行
   │
   ▼

   提交 → 文档 → 复盘 → 长时记忆巩固
   下次遇到类似任务，提取更快，甚至形成直觉
```

## 8. 设计原则与启示

1. **容量有限**
   工作记忆很小，所以要用 TODO、笔记、IDE、Git 外挂。

2. **多级存储**
   感觉 → 工作 → 长时 → 外部。

3. **注意力门控**
   只让相关信息进入当前现场。

4. **目标驱动**
   目标栈决定调取哪些记忆。

5. **反馈修正**
   执行不是终点，反馈才是下一步入口。

6. **巩固与遗忘**
   有用的重复、测试、复盘；没用的衰减、抑制。

7. **上下文切换有代价**
   多任务会保存现场再恢复，但成本高。

8. **外部记忆很重要**
   人会把工作记忆卸载到环境里，程序开发尤其明显。

9. **练习形成内隐记忆**
   重复训练会把技能转入程序性记忆，变成直觉和自动化。

10. **情绪与动机影响调度**
    焦虑、挫败、心流都会改变效率。

## 9. 总结

如果用程序来描述人的记忆与任务执行，它不像一段固定代码，而更像：

```text
一个多级存储系统
+ 一个注意力调度器
+ 一个目标栈
+ 一个永远在跑的“预测—行动—检查—修正”循环
+ 一个外部记忆外挂系统
```

最简总图：

```text
环境 → 感觉缓冲 → 注意力 → 工作记忆 ⇄ 长时记忆 ⇄ 外部记忆
                         │
                         ▼
                   目标栈 / 中央执行
                         │
                         ▼
              计划 → 执行 → 反馈 → 修正 → 巩固
                         ↑               │
                         └─────循环──────┘
```

一句话：
**人类做任务 = 长期记忆当硬盘，工作记忆当内存，注意力当调度器，环境反馈当传感器，目标当程序入口；整个执行过程不是一条直线，而是一层层“预测—行动—检查—修正”的循环。**
