## 背景（研究结论一句话）

人做电脑任务的执行决策 = **先评估任务再选策略**（元认知调度），需求边干边演化、线索变弱即换向、证据冗余即停；模型则是模式匹配训练分布、策略单一、少回溯。守藏技能的执行流程按人类机制改造，记忆机制对照人脑记忆循环（编码→巩固→存储→检索→再巩固→遗忘）查缺补漏。

## 待拍板（3 项）

### A. 主动遗忘 = 降级提纯机制（人脑「遗忘」环节补全；2026-09-08 用户拍板方向修正）

- **原则（用户拍板）**：人脑主动遗忘不是直接删除，是**把记忆下放到更低一级记忆板块**——降级的同时提取更通用的经验支撑未来任务；**每一次任务执行就是一次任务提纯总结**。蒸馏链路（巩固环节）已在做这件事，审计的遗忘沿用同一方向：巩固与遗忘共用「提纯」一个动作。
- **现状缺口**：access.log 只用于「提升」（近 5 次审计命中 ≥3 → 提升独立 skill），降级仅靠容量 >85% 被动触发，且重组 7 步的「删过时」缺提纯语义。
- **三级降级设计**（触发后走提纯，不直接删）：
  1. **触发**：连续 2 次审计零 access 命中（非 env/release 类）或容量 >85% 需腾位；
  2. **提纯**：从该 notes 小节提取「下次类似任务的方向指引」（教程式三段：目标/步骤轮廓/注意，对齐 R1 粒度锚与蒸馏 v3.1 格式）→ 合并进索引行概况或更通用小节；
  3. **降级**：细节原文移归档层（`audit/` 下，不进注入面、可追溯），索引行收窄或合并；
  4. **兜底**：提纯后确认无通用价值才删，且走人工裁决队列（audit-protocol §7），不静默删。
- **落点**：audit-protocol §3（重组 7 步增「提纯降级」语义）+ §5 生命周期；`memory_health_check.mjs` 增零召回清单输出。
- **对齐性**：与蒸馏 v3.1 教程式浓缩同构——巩固（新增时提纯）与遗忘（降级时提纯）方向一致，无双标准。

### B. 嵌入模型升级判据（碎片化检索，人脑「联想召回」环节）

- **结论**：当前规模（容量受限数千行级）不需要——指针索引 + 内容锚 + grep + tag 体系（人工语义压缩）够用且零依赖（项目红线）。
- **触发判据**（任一满足再议）：① 同义改写漏检实锤——蒸馏时发现「库里有但没召回」≥2 次；② 容量长期顶格且 grep 召回率下降；③ 出现模糊意图跨主题检索需求。
- **升级路径**：本机 Ollama bge-m3 / nomic-embed-text（2070S 8GB 够跑）→ SQLite + sqlite-vec 或纯 JSON 余弦 → 只挂两处：蒸馏入册时生成向量、④⑤步召回时先语义后 grep 兜底。

### D. 记忆层级扩展：原则层 + 睡眠巩固（2026-09-08 用户提出，设计稿）

- **现状**：两级存储（索引指针 ↔ notes 详情）。缺人脑的**图式层**——多条经验反复提纯凝成的高度泛化原则；提纯只在蒸馏（入册）一端发生，库内无"再归纳"机制。
- **四级层级设计**：

| 层级 | 人脑类比 | 载体 | 注入 | 提纯来源 |
|---|---|---|---|---|
| L0 原则层（**新增**） | 图式/直觉 | `PRINCIPLES.md`（新文件，≤1,000 字符硬限） | 常驻注入 | 多条 lessons/flows 反复命中后归纳 |
| L1 索引层 | 语义 gist | MEMORY/USER/AGENT 索引行 | 常驻（现有） | 蒸馏教程式浓缩 |
| L2 详情层 | 情景+教程 | notes/ §小节 | 按需 read_section | 收尾四步 / 蒸馏 appends |
| L3 暂存归档 | 未巩固痕迹 | pending/ + audit/ 归档 | 不注入 | — |

- **提纯全链（向上）**：任务执行 → pending(L3) → 蒸馏 → notes(L2) → 周期归纳 → 原则(L0)。**遗忘降级（向下）**：notes 细节 → audit 归档，gist 留 L1/L0——每次任务执行=一次沿梯提纯，降级与提升走同一梯子。
- **睡眠巩固双机制**（睡眠=回想巩固**当天**的记忆，2026-09-08 用户补充）：
  - *即时小睡*（已有）：事件驱动蒸馏，会话结束 idle 触发——单次任务的提纯；
  - *深度睡眠*（新增）：**作用域=当天记忆**（本日新增 pending + 本日蒸馏入册的 notes 增量 + 本日 access 命中主题），对当天痕迹做「回想式归纳 pass」——同主题 ≥3 条或单主题当日反复命中 → 提炼 1 条原则写入 PRINCIPLES.md（一句泛化 + 源指针 `← notes/lessons.md §A/§B`），原小节保留作证据。**全库扫描仍归低频周期审计**，深度睡眠只回放当天，不做全库重组。触发借审计既有周期（收尾/新会话补查），不新增守护进程（零依赖原则）。
- **使用挂点**：执行循环①③步（澄清意图/计划）优先读原则层——最粗粒度方向指引，正配 R1 锚。
- **变更面**（走 spec §7）：spec v14（§0 文件定位 + 新增 PRINCIPLES 白名单节 + §6 判定流）；health_check 增 PRINCIPLES 容量/格式校验；SKILL §6「三索引」→「四索引」；write_gate 支持 PRINCIPLES；README/CHANGELOG 同步。

## 设计原则（本次改造遵循，后续延续）

1. 检索贯穿全程（线索触发），写入只在⑥⑦闸口——对应人脑「随时回忆、离线巩固」。
2. 不重编号、指针接入——SKILL 对 task-protocols 的 §0/§6/§7 引用不可破坏。
3. 零依赖优先——嵌入等重机制按触发判据升级，不预支复杂度。
4. 每步决策有地基、有判定、有失效信号——避免「凭感觉执行」。
