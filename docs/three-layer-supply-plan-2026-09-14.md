# 守藏消费链条：三层供给结构规划（2026-09-14）

> **问题**：消费链条中不同内容类型对任务执行的**影响力不同**，其层次结构应与人类行为三层（外层任务级 / 中层行动级 / 内层认知级）同构。当前项目该怎么规划消费链条？
> **前置**：`docs/library-supply-chain-rework-2026-09-14.md`（消费链条现状与五通路）· `docs/four-chains-adjustment-order-2026-09-14.md`（四链条调整顺序）。
> **证据标注**：【活体】= 本会话真实运行观测 ·【实测】= 命令所得 ·【读码】= 源码（带行号）·【判读】= 本文推断。

---

## 0. 结论摘要

| # | 结论 |
|---|---|
| 1 | **影响力不是信息的属性，是「信息 × 当前行为层次」的匹配结果**。同一条 `[原则]`，在预见期注入是方向指引，在执行中途注入是噪声 |
| 2 | 当前消费链条的**根本错配**：五条通路**全部在「任务开始」这一个时刻**消费（§2），而三层行为发生在**三个不同时刻** |
| 3 | 修法不是增加通路，而是**把「判据」与「材料」分离**：**判据常驻**（告诉模型何时该找什么），**材料按层按需**（匹配当下层次才注入） |
| 4 | 三层各自的消费节奏、预算、判据来源**必须分离**——这与 `[原则] 判据域分治` 同构（蒸馏/深睡各自判据），是同一纪律向消费侧的应用 |
| 5 | 低风险起步点：**外层本已做实**（恒常面 always），**内层已成型**（情境槽 / MCL），**中层最空**（判据在提示词里、材料没有独立时机） |

## 1. 先把"影响力"这个词拆开

你说"不同内容类型的影响力不一样"——实测支持这个判断，但**影响力的来源需要说清**，否则会把"重要"当成唯一维度：

| 维度 | 含义 | 当前项目是否按它组织 |
|---|---|---|
| **重要性** | 这条信息有多关键 | ✅ 已按它组织（`carriers` 的 always/gated 分层、P 层优先） |
| **层次匹配** | 这条信息属于哪一行为层 ⇒ 该在哪个时机消费 | ❌ **未按它组织**（所有通路都在同一时刻消费） |
| **时效性** | 多久后失效 | 部分（`isLive` 时态、delta TTL） |

【判读】现状只优化了第一维，第三维部分，**第二维是空缺**——而这正是你指出的那一维。

## 2. 现状对照：五通路全挤在同一个时刻

**【读码】**（详见 `library-supply-chain-rework` §2）：

| 通路 | 消费时机 | 判据来源 | 预算 |
|---|---|---|---|
| (1) 恒常面 stable | **每步**（systemPrompt 常驻） | `indexRowInLayer(always)` | 吃余额，实测 ~2,800 字符 |
| (2) 动态面 dynamic | **会话开始 + query 变化** | `recallIndex` 相关性 | ≤600 |
| (3) 一次性 oneshot | **新会话开头** | `readDawnDelta` | ≤200 |
| (4) MCL 慢通道 | **任务首步（step ≤3）** | 熟悉度 `sim ≥ 0.55` | 600 |
| (5) 情境槽 | **每步**（挂尾部） | 情境键命中 | 300 / topN 3 |

**映射到人类三层**：

```
外层（预见/反思）  ← 通路(1) 恒常面 + (3) delta       ← 唯一做实的层
中层（监控/控制）  ← （无专用通路）                    ← 最空
内层（检索/判断）  ← 通路(2)(4)(5)                     ← 最拥挤
```

【判读】三条通路都在解决**内层问题**（找什么材料、像不像、情境对不对），用了 600+300 字符和两条独立链路；而**中层（执行中"我偏离了吗、该换向吗"）没有任何专用供给**——它的判据（连续 2 次无进展即停、线索变弱即换向）**写在 `skill/human-execution-loop.md` 的提示词里**，不在消费链条里。

## 3. 三层供给模型（目标结构）

### 3.1 外层 · 任务级 —— **方向**（恒常、低频、跨任务）

| 项 | 内容 |
|---|---|
| **行为** | 预见（任务解析/效能估计）→ 表现 → 自我反思 |
| **消费时机** | 会话开始（常驻）+ 收尾 |
| **应供给** | `[原则]`（跨任务约束）· `[偏好]`/`[习惯]`（用户画像）· `[边界]`（能力红线）· 效能历史（这类任务过往成功率） |
| **判据** | 分层准入（`inject=always`）——**已有** |
| **现状** | ✅ 做实（恒常面，P 层 1756 字符，占注入面 87% 为 `[原则]`+`[路径]`） |
| **缺口** | 效能估计**不存在**：无"这类任务我做过几次、成过几次"的供给（`[原则]` 有，成绩没有） |

### 3.2 中层 · 行动级 —— **过程**（任务期、中频、任务内）

| 项 | 内容 |
|---|---|
| **行为** | 行动 → 监控偏离 → 控制（继续 / 换向 / 卸载） |
| **消费时机** | 任务开始给一次流程骨架；**执行中的关键步**给监控信号 |
| **应供给** | `[路径]`（可复用步骤）· 判据（何时停/换向）· 偏离信号（连续无进展计数、线索强弱）· `commitment` 到期（前瞻记忆） |
| **判据** | **任务型**（现在用什么任务 → 取哪条路径）+ **偏离检测** |
| **现状** | ⚠️ **无专用通路**：`[路径]` 被混在恒常面里（与 `[原则]` 同预算），判据在提示词里，**没有任何"执行中提醒"机制** |
| **缺口** | ① 判据与材料未分离（见 §4）② 无"执行中"时机 ③ `commitment` 到期无消费（3 条数据、`dueRank` 只用于槽内排序） |

### 3.3 内层 · 认知级 —— **细节**（步级、高频、情境内）

| 项 | 内容 |
|---|---|
| **行为** | 情境感知 → 检索（气味/斑块）→ 判断（快判 or 慢算） |
| **消费时机** | 每步 / 每次需要判断时 |
| **应供给** | 索引指针（去哪读详情）· 情境记忆（`episode`/`decision`/`outcome`）· 事实（`fact` 时态有效）· 关联（`association`） |
| **判据** | 情境键匹配 + 相关性 + 熟悉度分流 |
| **现状** | ✅ 最拥挤：通路 (2)(4)(5) 三条都在此 |
| **缺口** | 不是"没有通路"，而是**判据常驻缺失**——模型不知道"什么情境该主动查、查到什么程度算够"（检索停止准则，见 §5） |

### 3.4 三层总览表

| 层 | 供给什么 | 时机 | 判据 | 预算 | 现状 |
|---|---|---|---|---|---|
| 外层 | 原则 / 偏好 / 边界 / **效能** | 会话开始 + 收尾 | 分层准入（always） | ~2800（吃余额） | ✅ 做实，缺效能 |
| 中层 | 路径 / **流程判据** / 偏离信号 / 到期承诺 | 任务开始 + **执行中** | 任务型 + 偏离检测 | 待定（建议独立） | ⚠️ **最空** |
| 内层 | 指针 / 情境记忆 / 事实 / 关联 | **每步** | 情境键 + 相关性 + 熟悉度 | 600 + 300（两条独立） | ✅ 拥挤，缺停止准则 |

## 4. 核心机制：判据常驻 + 材料按层按需

这是整份规划的**关键一刀**，也是当前架构最该补的一处。

### 4.1 现状：三者混装

| 三者 | 现在在哪 | 问题 |
|---|---|---|
| **判据**（何时该找什么、找到什么程度算够） | 提示词文档（`human-execution-loop.md`、`task-protocols.md`） | 模型**自愿**执行；消费链条影响不到它 |
| **材料**（具体记忆内容） | 五条通路注入 systemPrompt / 消息面 | 全部按"像不像"选，不分层 |
| **方向**（该往哪走） | 混在常驻面里 | 与 `[原则]` 共享预算，无独立时机 |

【读码佐证】`mcl.ts:165-169` 的 `THIN_CONTRACT` 其实是**一条极小的判据**（"先复述任务、需要经验时 recall、定方向引用一条 [路径]/[原则]"）——但它**只在慢通道**（即"不熟悉的任务"）出现，而且只在**任务首步**。⇒ 项目已经自发做了"判据与材料分离"的第一步，只是**范围太窄、时机太早**。

### 4.2 目标：判据常驻，材料分层

```
┌─ 常驻层（每步都在，字符极小）──────────────────────────┐
│  三层判据：                                            │
│   外层 · 预见期：念一遍任务目标与红线                   │
│   中层 · 执行中：连续 2 次无实质进展 ⇒ 停走回溯；        │
│                线索变弱 ⇒ 换向；承诺到期 ⇒ 主动提        │
│   内层 · 检索时：先情境键、后内容相似；                  │
│                证据冗余即停（不再追加检索）              │
└────────────────────────────────────────────────────────┘
                    ↓ 触发时才注入
┌─ 材料层（按层、按情境、按需）──────────────────────────┐
│  外层材料：原则 / 偏好 / 边界（会话开始，已有）          │
│  中层材料：任务型路径（任务开始，受控）                  │
│            + 到期承诺（前瞻，仅命中时）                  │
│  内层材料：情境记忆 / 指针 / 事实（每步，已有）          │
└────────────────────────────────────────────────────────┘
```

【判读】**判据常驻的代价远低于材料常驻**：一条判据约 30–60 字符，三层合计 <200 字符；而当前注入面 ~2,800 字符几乎全是材料。⇒ 这是**高杠杆、低成本**的改动。

## 5. 内层的两个具体缺口（不在通路数量上）

内层已有三条通路，缺的是**判据**：

1. **检索停止准则**：现无"够了没有"的判据。人类按**边际价值**停止（线索收益降到低于环境平均即离开斑块）。（依据见 `human-task-loop` §1.3）⇒ 需要消费侧记录**查询收益**并据此判断。
2. **快慢分流的可核验判据**：现状 `fast = sim ≥ 0.55 && hasHighConf`，实测**名义 25.4% / 实际 2.3%**；且只有"熟不熟"一维。应补 Kahneman & Klein 的两条件（环境有规律 + 有反馈机会）。

## 6. 中层的具体缺口（最该补的一层）

中层要的是**"执行中的过程供给"**，当前完全空白：

| 缺口 | 需要什么 | 数据是否已有 |
|---|---|---|
| 流程骨架 | 任务开始时给一条 `[路径]`（可复用步骤） | ✅ 有（`[路径]` 5 条，但混在恒常面） |
| 偏离信号 | 连续无实质进展计数 → 触发"停走回溯" | ⚠️ 判据在提示词，**无供给机制** |
| 线索强弱 | 当前方向的信息气味在增强还是减弱 | ❌ 无（需检索收益记账，即 §5-1） |
| 到期承诺 | `commitment` due 到 ⇒ 主动提 | ⚠️ 有 3 条数据 + `dueRank`，但只用于槽内排序 |
| 界限提醒 | 当前动作是否越出任务范围 | ⚠️ 有判据（提示词），无供给 |

【判读】中层是**唯一没有专用通路的层**，而它恰好对应 `human-execution-loop.md` 的 ④⑤⑥ 步（小步执行 / 每步验证 / 偏差即回溯）——**那三步的判据写得最详细，却没有任何运行机制承载**。这是"材料在场、认知动作不在"的又一实例（`mcl.ts` 头注自述过同一问题）。

## 7. 落地建议（按风险递增）

| 序 | 动作 | 层 | 风险 | 说明 |
|---|---|---|---|---|
| **L1** | **判据常驻**：把三层最小判据（<200 字符）并入常驻面 | 三 | 低 | 纯增量文本，不动通路；可一键回滚 |
| **L2** | **中层独立槽**：任务开始给 `[路径]`（按任务型选，从恒常面剥离） | 中层 | 中 | 参照 `situation` 槽先例（独立预算、缺省关、可回滚） |
| **L3** | **到期前瞻**：`commitment` due 到 ⇒ 主动提 | 中层 | 中 | 复用 `dueRank`（已有）+ 独立预算；**零新采集** |
| **L4** | **检索停止准则**：记查询收益 → 斑块切换判据 | 内层 | 中 | 复用 `ledger.jsonl`（已是当前审计源） |
| **L5** | **效能估计**：从 `decision-ring` 派生"这类任务成过几次" | 外层 | 低 | 纯派生，零新采集 |
| **L6** | **两条件分流**：`fast` 增加环境规律性 + 反馈机会 | 内层 | 中 | 替代"放宽 hasHighConf"（见 `library-supply-chain-rework` §4.5） |

**共同纪律**（沿用仓内既有先例）：
- 每项留**全局热开关**，缺省值保证行为零变化
- 预算**独立**（不挤占既有槽——`situation`/`serendipity` 已确立此先例，注册表 note 明确写过"改权重解决不了，只能分槽"）
- 新机检/测试登记 `scripts/check-runner.mjs#CHECKS`
- I1 棘轮已顶格（`applyForgetOps` 120/120）⇒ 新逻辑进新函数
