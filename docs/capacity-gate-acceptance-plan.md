# 设置「容量」三框 · 验收方案（定稿）

> **配套**：`docs/capacity-gate-adjustment-plan.md`（调整方案）。
> **范围**（用户 2026-09-22 确认）：「**UI 里面有几个设置容量的，画像和记忆的**」= `cap_agent` / `cap_user` / `cap_memory` 三框。
> **态标签**：**决策态**。阈值凡标「实测」者为真机数据。

---

## 0. 验收哲学（六条硬约束）

1. **「仓内绿」≠「运行态绿」** —— 仓内门禁全过只是必要条件。
2. **每条判据须有先红证据** —— 写不出"改造前它是红"的实证，**该判据不计入验收**（否则是恒真判据）。仓内自陈先例：`check-write-receipts.mjs:165-174` 曾有三条静态判据**对真实缺陷全都不红**。
3. **不得用配置探针判"真关闭"** —— 假关闭会把 cap 覆写成极大值，外部配置**根本进不去**；唯一有判别力的是**容量来源的读取计数 == 0**。
4. **等价优先于基线** —— 能用 167 条真库拒因逐字节复现（实测 **100.00%**），就免等一轮基线。
5. **每条四要素齐备**：判据内容 / 检查方式 / 通过阈值 / 失败退回。
6. **假旋钮防线** ⚠ —— `cap_memory` **本来就是软档**。给它"加开关"若不接线就是**假旋钮**；必须证明开关对**三个框都有真作用**，或**显式声明**它是 no-op。
