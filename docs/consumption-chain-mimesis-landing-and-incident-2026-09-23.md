```

```

### 2.3 上一次 `error` 的形态与根因

**形态**（`10:09:38Z` 那行）：
```
attributionNote     = "无法解析（stop=error · 输出 0 字符）"
yieldNote           = "无法解析（stop=error · 输出 0 字符）"
releaseSemanticNote = "全部批次无法解析（stop=error ×12 · 输出 0/0/.../0 字符）"
```
⇒ 三路子代理（归因 / 收益判定 / 释放语义）**全部返回空** —— **子代理调用整体失败**，非判据逻辑错。

**根因（本次实测）**：
```

Ollama 进程        → 不存在（Get-Process ollama* 为空）
端口 11434 监听    → 0（未监听）
```
⇒ **嵌入服务整体不可达**。且本次跑出 `convergeCandidateNote = "embed 返回长度不符 ⇒ 未判"` —— 同样是嵌入通道的故障表现。

⚠ **未验证**：Ollama 何时停止、为何停止（未查到停机记录）。**不断言"就是它导致 18:09 那次 error"** —— 只能说**同属嵌入通道故障族**，且本次的 `embed 返回长度不符` 已实测。

## 3. 落地与报错**交汇点**：回流通道 ⚠ **当时误判为"已生效"**（本节已按复验订正）

> ⚠⚠ **本节结论已于同日复验推翻（ACT-363 / ADR-366）**。原文写「写侧 → 台账 → 读侧全链路真机跑通」，**这是错的**：
> 当时只证了**写侧落了行**，**从未验证读侧能否认领它**。复验补上这一步，结果**认不到**。
> 三处静默失效叠加（键口径相反 / 取样指向死会话 / 尾读窗口过小），且全部 fail-closed ⇒ **不报警、只静默不工作**。
> 详见 `docs/consumption-chain-mimesis-plan-2026-09-23.md` §6.3 的订正表。以下原文保留，作为**"只验一半就下结论"的教训样本**。

### 3.1 第一条真机回流行（**原文如下 —— 结论部分已作废**）

```
{"type":"yield.verdict","kind":"yield-verdict","sid":"6be5ac2e",
 "verdict":"unjudged","injectedChars":2709,"nextToolsN":30,
 "at":"2026-09-23T14:53:02.690Z"}
```
~~⇒ **写侧 → 台账 → 读侧**全链路**真机跑通**。~~ ← **此句作废**。
**事实核对**：该行**确已落盘**（写侧无误）；但 `sid=6be5ac2e` 是**长形 id 取错了段**（读侧口径）**且**属一个**已死会话**
（末次活动 09-16 —— 因为取样器据饱和的 `idleSteps` 排序，取到了**最老的 10 行**）。
⇒ 这一行**既没被任何活会话读到、也本就不该写给这个会话**。它能"看起来生效"，
恰恰是因为我当时**只查了"行在不在"，没查"读侧认不认"**。

### 3.2 新字段当场证明自身价值

```
yieldJudged = 10 · yieldHelpedTrue = 0 · yieldUnjudged = 10
yieldSwitchSemantic = false · yieldSwitchCounter = true
yieldNote = "判 10（帮上 0 · 未判 10 · 注入后有动作 10/10）"
```
- `yieldUnjudged=10` 是**本次新增的字段** ⇒ 一眼可见「10 条全判不准」；
- **改造前**：这个 10 **只活在 `yieldNote` 的中文串里**（要靠中文正则才取得出）—— 这正是 obs 席实测的"字段根本不存在"。
- **`yieldSwitchSemantic=false` vs `yieldSwitchCounter=true` 相反** ⇒ 正是方案要治的**计数法误判**的活标本（计数法说该换向，语义判说不该）。

### 3.3 ⚠ 但也暴露一个**真问题**：向量不可达时，模型也判不了

`yieldUnjudged = 10/10`（**全部"判不准"**）⇒ **印证方案 §3.4 的警告**：

> 「**"上模型"不是充分解** —— 模型路径若没有自己的退判率/解析失败率读数，就是同形态的**第四处静默失效**。」

本次正是这个形态：**上游嵌入不可达 ⇒ 模型拿不到有效材料 ⇒ 全判"判不准"**。而**新字段让这件事第一次可见**（这正是落地它的意义）。

**本批行为正确**（fail-closed）：全判不准 ⇒ `verdict='unjudged'` ⇒ **计数不动、不换向** ⇒ **没有产生假信号**。对照旧语义：旧码会因 `acted` 恒 true 归零 / 或因 `echoed` 恒 false 只增不归零 —— **两种都是假信号**。

**归属**：`skill/engine/*` 的 mtime 为 **19:37**（我 21:18 才开工）⇒ **他人在途改动**所致（与我在最终验收里判为"非我造成"的那批同源）。

**但它的实际影响值得单列**：这不只是"仓内门禁红"，而是**真实睡眠的巡检在 warn** —— 即"红"已经渗进运行态。

**关掉它的命令**（⚠ 属**改他人改动面**，我不动）：
```

```
