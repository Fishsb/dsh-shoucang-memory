## 0. 一页结论

1. **向量侧已铺开，不缺。** 真实调用 9 处：`deepsleep-tree`（去重 B/D）· `distill-agent`（chunk 召回）·
   `distill-activation` · `distill-candidates` · `distill-write`（语义去重）· `association-propose/supply`（异域同构）·
   `assertion-graph`（cosine）· `mcl`（熟悉度）· `scheduler`。融合策略 RRF(k=60)（`src/vec.ts:10`）。

2. **真正的缺口是"模糊判断被写成了规则"，且已实证出错两处**：

   | 节点 | 现状 | 实证 |
   |---|---|---|
   | **召回零命中归因** | 纯函数 4 值硬分类（`src/recall-diagnosis.ts:17-89`） | 🔴 **给出与数据相反的方向** ——【注册表】`criteria.generated.ts:185` 原文："⚠ 同期 `recall-diagnose` 的 **coarse** `advice` 给出 `lower-threshold`，与本**细校准相反** ⇒ 以本校准为准（降 0.54 会**过冲注册意图 11.6pp**）" |
   | **冷热/活性模型** | 纯天数阈值 14/44/90 + hits≥5（`src/activity.ts:82-85,184-196`） | 🔴 **已实证失真** —— `skill/scripts/harvest-access.mjs:6` 原文："三模型长期失真（实测「**假冷 26 条**」：49 条冷条目里 26 条从未被记录过命中）" |
   | 检索收益 / 换向 | 计数阈值 `zeroGain >= 2`（`src/recall-yield.ts:17,25`） | ⚠ "这次检索有没有帮上"是**模糊判断**，被降维成计数 |

3. **阈值不是原罪，"无校准的阈值"才是。** 全仓**唯一**有完整预注册校准记录的阈值是
   `mclFamiliarThreshold`（2154 条样本、扫阈值、命中目标 **0.0pp** ⇒ 维持 0.55，`criteria.generated.ts:204`）。
   其余阈值（0.9 / 0.95 / 0.8 / 0.66 / 0.42 / 0.6 / 0.5–0.66）**均无校准记录**。
   ⇒ 本条是本册**最可机检、收益最直接**的落点。

4. **三向机检**（防口号）：`judgeKind` 声明 + **阈值登记制**（§4）。
   **模糊判断不得只有阈值实现**；**每个阈值必须有预注册判据与校准样本数**。

## 1. 机制分层规则（不是"越模型越好"）

沿用用户既有口径"**精确检索用代码，语义模糊/联想判断交向量模型或云端大模型，每处按质量择优**"。

| 层 | 特性 | 用于 | 例（既有） |
|---|---|---|---|
| **确定性** | 可复现、零成本、可逐字节回归 | **精确**：集合成员、格式、计数、水位比较、指针可解析 | `deepsleep-core.ts:163-179`（landed 判据）· `criteria.ts`（L0 内核）· `check-*` 全部机检 |
| **向量** | 便宜（本地 bge-m3）· 可批量（`embedMany`）· 幂等 | **相似 / 新颖 / 覆盖 / gain / 候选生成** | 去重、联想、断言图、熟悉度、召回排序 |
| **大模型** | 贵 · 不幂等 | **归因 / 取舍 / 成立与否 / 生成** | 蒸馏 pass、睡眠 pass；**应当介入而尚未介入**：零命中归因、收益判断、冷热重要性、自足性判定 |

**固定执行顺序**：`确定性预筛 → 向量候选 → LLM 判断`。
**这是项目已有模式的原话**（`src/deepsleep-run.ts:95-97`）："**候选生成交向量，模糊判断交模型**"。

### 1.1 反过来：这些**不应**上模型（诚实边界）

- **水位推进/回滚**：必须确定性（B9 不变量；`done` 才推 `failed` 回滚）。
- **格式门与指针可解析性**：必须确定性（否则无法机检，且会引入新的解析失败模式——见 P8 否决理由）。
- **隐私/跨工作区红线**：必须确定性（模型可被绕过，红线不可）。
- **账目守恒**（`test-usage-truth` 的"账 == 真实裁切"）：必须确定性。
⇒ **判据**：**"可机检性"优先于"智能性"** —— 凡是必须能被机检守住的判据，一律不得交给不幂等的模型。

## 3. 三个升级候选（按收益排序，各有实证动机）

### 3.1 U1 · 召回零命中归因 → 向量 + LLM（**已实证出错，优先级最高**）
**现状**：`recallMissReasonOf` 把未命中硬分类为 `recall-empty / no-highconf / below-threshold / embed-off`，
`recallAdviceOf` 再用计数比较给 4 值方向（`recall-diagnosis.ts:55-89`）。
**问题**：① 分类维度是手写的，真实未命中原因可能落在分类之外；② 方向由**计数大小**决定，不看语义。
**实证**：它给出 `lower-threshold`，而 2154 条样本的细校准结论是"**维持 0.55 不改**"，降 0.54 会过冲 11.6pp（【注册表】`:185`）。
**改法**：保留确定性**计数**（分层第一层，零成本筛样本），把**归因与方向**交 LLM——
输入 = 未命中样本（查询 + 候选行 + sim 分布），输出 = 归因 + 方向 + 理由；并把结论与**细校准**对账。
**判据**：LLM 归因与细校准结论**一致率**（当前实测 = 0，因为方向相反）。

### 3.2 U2 · 冷热/活性模型 → 向量 + 关键性（**已实证失真**）
**现状**：`active/warm/cold` 完全由"距上次命中天数"决定；`salience` = 频次档 + 跨日档（`activity.ts:167-196`）。
**问题**：**90 天未用的安全红线**与**90 天未用的废话**同样冷。天数不是"重要性"的代理。
**实证**：假冷 26 条（`harvest-access.mjs:6`）。
**改法**：活性 = f(确定性信号：命中/时间) ⊕ **向量**（该节与当前活跃工作区/主题的语义距离——即"离热点多远"）
⊕ **LLM/确定性**关键性标记（安全红线 / 契约事实 / 一次性进度）。
关键性判断本身是模糊的 ⇒ **LLM 判 + 留理由**（"宁 keep 勿 archive"口径已存在，`criteria.json` forgetOps）。

### 3.3 U3 · 检索收益/换向 → LLM 判"有没有帮上"
**现状**：`shouldSwitchSource(zeroGain) => zeroGain >= 2`（`recall-yield.ts:25`）。
**问题**："这次检索是否产生实质进展"是**语义判断**（正是本仓"连续 2 次无实质进展即停下回溯"那条行动级判据的
机器化），却被降维成"连续 2 次零增益计数"。
**改法**：候选由确定性/向量产出（哪些轮次"疑似零收益"），**判定交 LLM**（读该轮检索结果与后续动作，判是否真的帮上）。

## 4. 落点：两条可机检的不变量

### 4.1 `judgeKind`（判据机制声明 + 三向机检）

`criteria.json` 每条 criteria 增加 **`judgeKind: deterministic | vector | llm`**（可带 `fallback`）：

| 向 | 断言 | 防什么 |
|---|---|---|
| 正向 | 标 `vector`/`llm` ⇒ **必须有真实调用点** | **假旋钮**（标了模型、实际常数） |
| 反向 | 标 `deterministic` ⇒ **不得** import `vec.js`、不得调 LLM | 精确判断烧模型（不可复现 + 浪费） |
| **正面** | **模糊判断类判据不得只有阈值/规则实现** | 本册核心 |

### 4.2 **阈值登记制**（本册收益最直接的一条）

**规则**：代码中任何**影响判定的数值阈值**，必须在 `criteria.json`（新块 `thresholds`）登记，且登记项必含：
`{ id, value, owner: 文件:行, 预注册判据, 最近校准样本数, 最近校准结论, 复检触发 }`。

- **未登记 ⇒ 机检红**（新增 `check-threshold-registry.mjs`：扫 `src/` 数值阈值常量 ⇒ 比对登记表）。
- **登记项缺"预注册判据"或"校准样本数" ⇒ 红**（不许"登记了但没校准"）。
- **样板（已有的唯一正确范例）**：`mclFamiliarThreshold`（`criteria.generated.ts:204`）——
  预注册目标覆盖率 27.5% · 936 → 2154 条样本 · 两次重校准 · 结论"维持 0.55" · 回滚命令 · 复检触发（N≥300）。
  **本册要求其余 7 个阈值照此补齐，而不是换掉阈值。**

> **为什么"登记"比"换模型"更重要**：U1 的实证说明——**错的不是阈值本身，是"没人验证过这个阈值"**。
> 阈值登记制把"验证"变成**结构性要求**，而不是靠人记得。

## 5. 成本、可复现与回退（三条硬约束）

1. **成本 / 超时**：睡眠已是一次 10 min LLM 子代理（`src/deepsleep-run.ts:132`）。
   ⇒ **分层即对策**：向量本地批量；LLM 只在向量筛出的候选上判断，并受预算配额约束。
2. **不幂等 ⇒ 不可逐字节回归**：LLM 判断点**不能**用 `inject-baseline-diff` 式断言。
   ⇒ 必须**留判断理由 + 可回放**（审计留痕），判据用**结果分布**（一致率/命中率），而非逐字节。
3. **回退不得静默**：`EmbedCfg.enabled=false` / HTTP 失败 ⇒ 确定性回退 + **如实记"未判"**。
   仓内已是此口径：`src/vec.ts:173`（"失败/不可用 ⇒ `null`，调用方**如实记'未判'**"）·
   `src/deepsleep-run.ts:98`（"**绝不退回结构规则假装生成联想**"）。**不得破例。**

## 6. 质量度量：把"增强运行质量"变成可判定的

用户目标是"**增强整个项目的运行质量**"。⇒ 必须有判据，否则是自述。

| 指标 | 定义 | 数据源 |
|---|---|---|
| **归因一致率** | LLM 归因方向 ⟷ 细校准结论 的一致比例 | `audit/mcl-audit.jsonl` + `mcl-calibrate.mjs` |
| **无校准阈值占比** | (未登记 或 无预注册 或 无样本) 的阈值 / 全部阈值 | `check-threshold-registry` |
| **假冷率** | 被判 cold 但实际有真实读命的条目比例 | `access-real.jsonl` + `activity.jsonl` |
| **模型节点有效率** | 标 `vector/llm` 且真实产生非空产出的比例（防假旋钮空转） | 审计 + `judgeKind` 声明 |
| **回退如实率** | 向量/LLM 不可用时"记未判"的比例（应 = 100%） | 审计 |

**全部基线取"改造前"值，登记进 `docs/OPEN-ITEMS.md`**（该表是本仓唯一待办/判据登记入口，
且其纪律是"判据满足 ≠ 免检"，`docs/OPEN-ITEMS.md:43-44`）。

## 9. 本册明确不做

- **不把确定性判据改成模型判据**（水位/格式/红线/账目，§1.1）。
- **不新增模型依赖**（B10）：向量继续用本地既有 bge；LLM 继续走既有路由。
- **不为"用模型"而用模型**：每个升级项必须先有**实证动机**（本册三项各有实证，§3）。
- **不用 LLM 判"自足性计数"**（那是确定性账，见睡眠册 AC-G.3）。
