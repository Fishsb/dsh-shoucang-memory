# Agent 自我反思与经验归纳：外部研究对齐报告（2026-09-09）

> 研究问题（lk 原话转述）：睡眠功能做的是 agent 自身反思成长迭代——像人一样从各种任务经历中归纳**通用认知**与**各种任务完成的通用路径**。检索论文与其他记忆项目的同类设定，看守藏应该怎么做。
> 结论先行：守藏深睡的骨架与业界主流同构（Letta sleep-time + Generative Agents reflection + ExpeL insight 管理的混合体），**已对齐的不用动**；最大的一个缺口是「通用任务路径」这种**可复用 workflow 产出**（对标 AWM，ICML 2025，业界实测 +51% 成功率），建议作为深睡归纳契约的下一个产出类型（P1）。

## 1. 业界参照系（五家）

### 1.1 Reflexion（2023，arXiv:2303.11366）——前驱：单任务失败复盘
- 机制：任务失败后用语言反思（而非标量奖励）生成「下次怎么改」，存入记忆供重试。
- 边界：只解决**同一任务**的重试改进，memory 只留最近 1~3 条反思，不解决跨任务成长。守藏不必对标，但其「语言反馈比标量奖励更有语义」是整个方向的立论。

### 1.2 Generative Agents（斯坦福 2023，arXiv:2304.03442）——反思的触发与形态
- 记忆流：append-only 自然语言观察 + 时间戳；检索 = 近因（指数衰减）+ 重要性（LLM 1-10 打分）+ 相关性（向量余弦）。
- **反思触发**：近期记忆的重要性得分**累加超过阈值（150）**时触发（实测约每天 2-3 次）——事件驱动，不是纯定时。
- **反思三步**：① 从最近 100 条记忆提出 3 个最值得思考的问题 → ② 带问题检索证据 → ③ 提炼 5 条高层洞察，**强制标注证据编号**（insight (because of 1,5,3)）。
- 洞察写回记忆流，可再被反思 → 形成**反思树**（层级递进：观察 → 洞察 → 更高层洞察）。
- 消融实验：砍掉反思模块后行为可信度断崖下跌。

### 1.3 ExpeL（2023，arXiv:2308.10144）——跨任务经验提炼与 insight 生命周期管理
- 经验池：收集**成功 + 失败**轨迹（失败后 Reflexion 式重试形成成败对）。
- **insight 提炼信号**：对比同一任务的失败→成功轨迹对（找分叉点）+ 跨任务成功轨迹的共同最佳实践——「单独看一条失败容易错误归因，成败对比才能定位真因」。
- insight 列表动态管理：**ADD / EDIT / UPVOTE / DOWNVOTE**（有证据支持就加分，违反就降权）。
- 推理时：insight 注入 system prompt + 检索相似成功轨迹作 few-shot，双通道。
- 验证：ALFWorld 59% vs ReAct 40%；insight 跨数据集迁移（HotpotQA→FEVER 63%→70%）。
- 后续（AutoGuide/MSI）：insight 按状态选择性注入（更省上下文，但推理时更贵）。

### 1.4 Agent Workflow Memory / AWM（CMU，ICML 2025，arXiv:2409.07429）——「通用任务路径」的直接对标
- **workflow = 可复用任务路径**：从成功轨迹中归纳，两部分组成——① 一句自然语言目标描述；② 参数化步骤序列（把具体值如 "dry cat food" 抽象成 `{product-name}` 变量，保证跨任务复用）。
- 触发：**任务成功后**归纳（在线模式靠 LLM 评估器判断成败）——只从成功经验学。
- **雪球效应**：简单 workflow（“按名称找地点”）成为复杂 workflow（“查某地邮编”）的子目标，复杂度滚动上升；**主要 workflow 在前 40 个样例内学完**，之后收益趋平。
- 实测：WebArena 相对提升 51.1%、Mind2Web +24.6%，且平均步数 7.9→5.9（更接近熟练者的路径）。
- 关键教训：**抽象变量化**是泛化的关键（不抽象=过拟合单例）；静态 few-shot 例子会过时，归纳出的 workflow 不会。

### 1.5 Letta / MemGPT Sleep-time Compute（2025-04，Letta 0.7.0）——工程形态最接近守藏深睡
- **读写职责分离**：Primary agent 只读（对话），Sleep-time agent 持写工具（memory_replace / memory_rethink），共享 Memory Block——对话时不再分心管记忆。
- **睡眠 agent 用更强模型**（主对话用快模型 gpt-4o-mini，睡眠用 GPT-4.1/Sonnet——睡眠不受延迟约束）。
- 频率可配（sleeptime_agent_frequency，默认每 5 步）——频率越高记忆越新但 token 越贵。
- **anytime 更新**：睡眠 agent 改记忆是渐进的，主 agent 任何时候都能读到（不互相等）。
- 动机原话：记忆增量式形成会「越来越乱」，睡眠 agent 能**持续重写整理出干净、简洁、详尽的记忆**。
- 后续（2025-08）："Is a Filesystem All You Need?"——**文件系统当记忆**在 LoCoMo 拿 74.0%，超过专用记忆工具 Mem0（68.5%）；结论：LLM 对文件操作是「母语」，记忆质量取决于 agent 管理上下文的能力而非工具复杂度。（守藏=Markdown 文件库，正好站在这一边。）

## 2. 守藏深睡现状 ↔ 业界对照

| 维度 | 守藏现状 | 业界参照 | 判定 |
|---|---|---|---|
| 睡眠=离线整理 | 全会话停滞 ≥3h 触发归纳 pass，读写分离（蒸馏/归纳是子代理，不占对话） | Letta sleep-time（分离+异步+频率可配） | ✅ 同构；频率/模型今天起面板可调（/distill/config） |
| 睡眠模型可配 | llmProvider/llmModel 空则继承主会话 | Letta：睡眠用更强模型 | ✅ 机制就位（配更强 provider 即可） |
| 反思产出形态 | `[原则]` 一句泛化 + `→ notes/…` 源指针 | GA 洞察强制引用证据编号 | ✅ 源指针=证据引用，已对齐 |
| 层级递进 | 三级提纯链 pending→notes→原则（向上提纯、向下降级） | GA 反思树（洞察可再反思） | ✅ 等价（原则即顶层，容量约束下不再向上是合理取舍） |
| insight 生命周期 | add/replace 门禁 + 去重 + 审计 | ExpeL ADD/EDIT/UPVOTE/DOWNVOTE | ✅ 等价（replace+审计比投票制简单可靠，不建议上投票） |
| 无材料不空转 | 纯水位语义：无痕迹静默滑窗不睡 | Letta 按频率触发（不做空转优化） | ✅ 守藏更优（今天刚修） |
| **可复用任务路径** | ❌ **无此产出类型**——原则是「方向指引」，不是「步骤序列」 | **AWM workflow：目标描述+参数化步骤**，实测对成功率提升最大 | ⚠️ **最大缺口**（见 §3 P1） |
| 成败信号 | 蒸馏/深睡材料不带任务成败标注 | ExpeL 靠成败对比定位真因；AWM 只从成功学 | ⚠️ 缺抓手（§3 P2） |
| 反思触发 | 纯时间（停滞 3h） | GA 重要性累加阈值（事件型，≈每天 2-3 次） | ⚠️ 可选演进（§3 P3，与现有拍板有张力） |
| 记忆载体 | Markdown 文件 + grep/写门脚本 | Letta 2025-08：文件系统方案 SOTA（74.0% > Mem0 68.5%） | ✅ 押注正确 |

## 3. 差距与落地建议

### P1（✅ 已落地 v17，2026-09-09）：深睡归纳增加「通用任务路径」产出类型（对标 AWM）
- **是什么**：归纳契约在 `[原则]` 之外新增一类产出——`[路径] <任务类型> · 步骤概要 → notes/flows.md §…`，写入 AGENT.md 画像（与原则同门禁：源指针/容量/去重/replace）。
- **为什么值**：AWM 证明「参数化的步骤序列」对完成率提升远大于一句方向性原则（+51% vs 单句 insight）；且这正是 lk 要的「各种任务完成的通用路径」。原则回答“该往哪想”，路径回答“该怎么做”。
- **怎么做**：材料源=notes/flows.md（蒸馏 R2 已把流程类经验写入）+ 窗口内成功蒸馏审计；抽象要求照抄 AWM——具体值变量化（如「<项目名>」「<端口>」），防过拟合单例；契约 v16→v17（DEEP_SLEEP_PROMPT 加 workflows 字段 + write_gate 白名单加 `[路径]` 标签行 + AGENT 容量预算内）。
- **成本**：约半天（契约+写门+注入面同步），无新依赖。

### P2（✅ 已落地 v17，2026-09-09）：给归纳材料带任务成败信号（对标 ExpeL）
- 会话转录的 turn/end 事件本身带 `stop=completed|error`（深睡 FSM 已在解析）；把窗口内「任务成败摘要」（每个会话一行：目标 + 成败 + 关键分叉）加进归纳材料，子代理即可做**成败对比归纳**——ExpeL 证明这是定位真因的最强信号，比只喂成功材料好。
- 成本：痕迹收集处多拼一段（已有事件数据，无新依赖）。

### P3（暂缓，需重新拍板）：事件型反思触发（GA 重要性累加）
- GA 用「重要性累加过阈值」触发反思（事件驱动），守藏用「全部停滞 3h」（时间驱动，用户拍板「只有确认没任务在跑才归纳」）。两者哲学不同：前者及时、后者保守安全。**建议维持现状**；若未来觉得「睡得太晚导致原则滞后」，可加一个保守变体：当日蒸馏 added 数累计 ≥N 时把「待归纳」标记挂起，仍等到停滞窗口再归纳（只是加权重，不改时机）。

### 不建议做
- ExpeL 式 insight 投票（UPVOTE/DOWNVOTE）：守藏已有 replace 逐字匹配门禁 + 审计，投票制引入的复杂度 > 收益。
- 把反思做成对话内实时自省（Reflexion 式）：与「深睡=离线、不打扰会话」的架构定位冲突。
