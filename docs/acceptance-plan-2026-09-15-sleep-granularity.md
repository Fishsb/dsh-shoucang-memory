## 2. P1 / R0 · 睡眠纪元与双维水位

### AC-R0.1 纪元身份唯一且可追溯
- **判据**：每一轮睡眠在审计里带 `sleepEpoch` 字段（`epoch-<序号>-<起时刻>`），且**同一片分片共享同一 id**；`grep` 审计可得该纪元的起止、材料量、片数、产出通道计数。
- **复验命令**：
  ```bash
  node -e "const fs=require('fs');const f=process.env.USERPROFILE+'/.dsh/suite/knowledge/audit/distill-audit.jsonl';const r=fs.readFileSync(f,'utf8').trim().split(/\n/).map(JSON.parse).filter(x=>x.kind==='distill-run');const e=r.filter(x=>x.sleepEpoch);console.log('runs=',r.length,'withEpoch=',e.length,'last=',JSON.stringify(e.at(-1)?.sleepEpoch))"
  ```
- **反例自证**：造一轮**不带** `sleepEpoch` 的旧式审计行，上面的计数必须**少于**总轮次（证明判据真的在看这个字段，而不是恒真）。

### AC-R0.2 双维水位各自独立生效
- **判据**：`时间维已到但内容维不足` ⇒ **不睡**（留痕）；`内容维已到但时间维未到` ⇒ **可睡**（留痕）；两个方向的留痕都可从审计读出。
- **复验命令**：`node scripts/test-epoch-watermark.mjs`（**新增**，须登记 `CHECKS`）——驱动真状态机，断言两个方向 + 一个"双足"方向。
- **反例自证**：把内容阈值设为**极大**，断言"内容维永不满足"时**只**走时间维 ⇒ 行为与改造前**逐字节一致**（回归保护）。这一条**必须先红**：改造前该测试因无内容维而失败。

### AC-R0.3 材料上限与分片（复刻蒸馏侧纪律）
- **判据**：材料 > 上限 ⇒ 切成 N 片，**片数可观测**；**水位按片推进**；任一片失败 ⇒ **该片回滚重试**，已完成片不重跑。
- **对标**：蒸馏侧已有 `chunk/chunkStart/chunkEnd/totalChunks` 标记与"stub watermark=该段推进区间"（`src/distill-agent.ts:242`）。**睡眠侧必须是同一语义，不是新发明**。
- **复验命令**：`node scripts/test-epoch-chunk.mjs`（**新增**，登记 `CHECKS`）。
- **反例自证**：注入"第 2 片失败" ⇒ 断言水位停在**第 1 片之后**、且第 1 片**不重跑**。若水位整轮推进 ⇒ 判 **FAIL**（静默丢料，与 `deepSleepLanded` 的 G-16/G-19 同族缺陷）。

### AC-R0.4 B9 不变量未被降级
- **判据**：`done 才推 / failed 回滚`在**每一维、每一片**上分别成立；`planDeepSleepVerdict` 的既有单测**全绿不改**。
- **复验命令**：`node scripts/test-deepsleep-verdict.mjs && node scripts/test-watermark-guard.mjs`
- **反例自证**：既有两件单测**必须一行不改即通过**。若为了新水位而改动它们 ⇒ 判**不合格**（那是降级既有不变量，不是新增能力）。

### AC-R0.5 面板可观测（渲染级证据）
- **判据**：深度睡眠视图显示 当前纪元起止 / 材料量 / 预计分片数 / 完成片数，且**在首屏**、卡片不换行。
- **复验命令**：`node scripts/ui-geo-regress.mjs --shots <目录>`，并**新增该视图的永久出图**。
- **反例自证**：仓内已有先例 —— H-5/H-16 的成因是"**标题在函数开头、控件在函数末尾**，中间隔着两段 ⇒ 标题下空白"，只看代码/契约**天然失明**，只有出图才发现（`docs/OPEN-ITEMS.md:88`）。⇒ 本项的判据**只能是图**，不能是"契约里注册了"。

## 6. P5 / R2-B · 精要层（L1）

### AC-S.1 精要真的被**读到**
- **判据**：模型按指针读详情时，**先拿到精要**；精要存在 ⇒ 正文读取路径确实经过精要层（**不是只写进文件**）。

### AC-S.2 精要失败不损正文
- **判据**：精要生成失败/不可解析 ⇒ **正文完好、指针完好、本轮判 failed 并回滚**（不留下半成品）。

- **反例自证**：用故障注入器在写入中途失败 ⇒ 断言文件内容 == 写入前内容（逐字节）。

### AC-S.3 精要**不下沉进注入面**
- **判据**：精要层属于"按需读"面，**不进入**恒定注入面（B5：可注入载体必须有渲染器；本方案不新增注入载体）。

- **反例自证**：若精要挤进注入面 ⇒ 注入字节数变化，`inject-baseline-diff` **必须红**（这就是它存在的意义）。
