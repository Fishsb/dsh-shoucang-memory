## 二、逐项落地方案

### 1. 清醒快速编码 ✅（维护）
- **现状**：`distill.ts:4-6` `turn/end` → per-agent idle → 预筛（信号词/pending）→ spawn 蒸馏子代理；产出 `appends`/`newIndex`/`profiles`/`projectCards`；唯一性硬门 + `write_gate`。
- **缺口**：无（生物侧"快速、稀疏、情节特异、抗灾难性干扰"已由「原样正文 + 源指针 + 唯一门」对应）。
- **动作**：不改。仅在 P1/P2 落地后回归一次唯一门阈值是否仍够。

### 2. 睡眠回放（replay）→ P2
- **现状**：`distill.ts:278` DEEP_SLEEP_PROMPT「像人睡前回想**当天**经历」；`:1250-1253` `traceSince()` = `lastDeepSleepAt`；`:2144` 材料头写死「作用域=本日，不做全库扫描」。
- **缺口**：① 只有单日窗，无**跨日回放**（生物有 dream-lag 5–7 天）；② 回放材料是**痕迹**，不是「已有记忆的再激活」。
- **动作**：
  1. 材料增一段「近期再现（近 7 日）**已有条目**清单」——来源 = `audit/access-real.jsonl` 近窗命中 top-N（复用现有聚合，不新建口径）。
  2. 深睡判据加一条：**同一原则在 ≥2 个不同日窗被再次激活** → 允许 `pointerOps` 扩容概况或提升为更高层原则。
- **验收**：连续 2 次深睡的审计行中 `replayHits` 字段非零，且至少 1 条原则被跨日二次激活。
- **风险**：材料膨胀 → 上限设 top-10、每行 ≤80 字（与「材料有界」同法）。回退：删该材料段即回原状。

### 3. 系统巩固 ✅（维护）
- **现状**：`distill.ts:280` `[原则]` 需同主题 ≥3 条痕迹；`:282` `[路径]` 需同类型 ≥2 次且**跨会话 ≥2**；产出写 AGENT.md。与 CLS「海马快速情节 → 皮层慢速统计」同构。
- **缺口**：无（阈值化上提 = 只在重复证据足够时语义化，正是 CLS 的关键约束）。
- **动作**：不改。

### 4. 抽象 / 图式 ✅（维护）
- **现状**：概况 ≤30 字名词短语（spec §8 五条规则）；`[原则]` 一句方向指引；指针树分层即图式骨架。
- **缺口**：无。
- **动作**：不改。

### 5. 复习-强化（LTP / FSRS）→ P1
- **现状**：`activity.ts:79-81` 14/44/90 天状态迁移；`:186` `hits30 ≥ hotHits(5)` → `activity-hot-<day>.md` → 喂深睡（`distill.ts:2137`）。**强化只决定「是否加深/是否转正」，不改变记忆本身。**
- **缺口**：命中不回流到记忆形态。生物侧一次使用 = 一次强化（突触增强、抗衰减）。
- **动作**：
  1. **概况扩容**：`hits30 ≥ hot` 的索引行，深睡 `pointerOps.update` 允许把概况扩到 **≤40 字**（现 ≤30）——强化体现在"路由冗余度"。
  2. **注入加权**：注入档位排序把命中次数作为**次级权重**（现仅相关性 + 新鲜度 + 基线，见 ACT-027）；高命中条目在相关性相同时优先。
  3. **衰减对冲**：`hits` 非零但落在 cold 的条目，`coldFactor` 由 0.35 提到 0.5（曾用过的不该和从未用过的一样冷）。
- **验收**：连跑 3 次聚合，top-20 命中条目的概况平均长度上升；注入预览 `/inject/preview?q=` 中高命中条目进入 top-10 的比例提升。
- **风险**：概况变长挤压行预算 → 硬上限 40 字 + 行总预算仍 ≤100（超则 `write_gate` 拦）。回退：改回 30。

### 6. 干扰 / 竞争性抑制 → P2
- **现状**：唯一性硬门（同标签+同主题精确拒收；bigram 重叠 ≥0.66 近似拒收，spec §8 v19）；consolidation 叶子合并（`distill.ts:1475-1489`）。
- **缺口**：只有「**新增时**防重」，没有「**既有**相似记忆之间的抑制」——高度重叠的两条会长期并存。
- **动作**：
  1. `activity` 增加「**互抑候选**」段：对同文件同标签条目两两算 bigram 重叠，0.5–0.66 区间（低于拒收门但高于无关）→ 列候选。
  2. 深睡材料纳入该段；模型可产出 `treeOps.merge`（已有操作，不用新写）或 `pointerOps.update` 合并概况。
  3. 召回侧：同族条目在融合时**只保留最高分一条**进入 topK（竞争性抑制，防冗余占位）。
- **验收**：审计行出现 `interferenceCandidates: N`；一次深睡至少消费 1 条（merge 或概况合并）。
- **风险**：误并语义相邻但独立的两条 → merge 有归档可回滚 + 逐字 match；召回侧抑制只在**同 §小节**内生效，防误杀跨节。

### 7. 突触下调 / 修剪（SHY）→ P1
- **现状**：`vec.ts:22,41,66` cold/retired 条目在**向量召回**融合时 ×0.35。
- **缺口**：**降权只覆盖向量召回一条通道**——cold 内容仍能被 `grep` 全文命中、索引行仍照常注入。生物侧下调是全网络性的。
- **动作**：
  1. **注入侧**：`panel.ts` 注入装配时，cold 条目的索引行降到「基线补齐」档（不再占相关性档）。
  2. **grep 兜底侧**：`read_section`/grep 命中 cold §小节时，返回**摘要行 + 「该节已冷（90 天未命中）」提示**，而不是直接铺全节（等于把"下调"变成"先看摘要"）。
- **验收**：构造一条 cold 条目 → 注入预览不含它；grep 命中时输出带冷标记。
- **风险**：冷但关键（如一次性安全红线）会被埋 → **retired 与 cold 分开处理**：retired（人工标 superseded 等）才降档，cold 仅排后。回退：改回不区分。

### 8. **主动遗忘** → P0（最大缺口）
- **现状**：`activity.ts:8,200-201` 产出「遗忘候选清单」并明写「仅建议，供人工裁决；本清单**不自动删除**」；`distill.ts:298` 「删除归审计裁决」；实删通道只有 `treeOps.merge`（删 drop 小节）+ 人工。
- **缺口**：**候选无消费端** —— 清单写进 `audit/` 后没人读（深睡材料只读 `activity-hot-*`，不读遗忘候选）。容量因此单调增长，只能靠 `write_gate` 硬顶。
- **动作**（复用既有基础设施，不新建机制）：
  1. **深睡材料**增一段「遗忘候选（cold > N 天）」——与 `hotCtx` 同法读 `audit/activity-*`，**上限 top-10**。
  2. **契约**新增 `forgetOps`：模型对每条候选只能选 **`archive`（下沉归档）** 或 **`keep`（保留并给理由）**，**不允许直删**。
  3. **宿主执行** `applyForgetOps`：
     - `archive` → 把该 §小节整段 **移出 `notes/`**，落到 `notes/archive/<file>-<YYYYMMDD>.md`，**段前补一行指回原指针**；同时把指向它的索引行改指归档文件（或标 `archived` 状态，见 §5 元数据表 `archived` 已有）。
     - 全程 **tmp+rename 原子写 + 操作前归档 + 幂等**（照抄 `treeops.ts` 的既有不变量）。
  4. **不进 grep 兜底**：归档目录默认排除在召回/注入之外（`read_section` 与 `vec` 加一条路径排除），但**人工仍可读**。
- **验收**：玩具副本 8 项自测（照 `scripts/test-treeops-split.mjs` 套路）——归档落盘 / 指针改指 / 原节消失 / 幂等 / `keep` 不改动 / 越权（模型给 `delete`）被拒 / 归档可回滚 / 审计留痕。
- **风险**：误归档 → 归档非删除 + 原节全文留档 + 指针可回溯；**且默认只归档 cold≥90 天且命中为 0 的节**（双条件，防误伤）。

### 9. 睡眠分相（NREM / REM）→ P2
- **现状**：只有**一种**深睡（单 pass）：`DEEP_SLEEP_PROMPT` 同时做原则提炼 + 画像 + 指针 + 树操作。**无 REM 相**。
- **缺口**：REM 对应「跨域整合、联想重组、抽象、情绪标记」——现在所有判据都要求**同主题**（≥3 同主题痕迹 / ≥2 同类型任务），**跨主题联想无处发生**。`distill.ts:1483` 也自认「跨主题大合并留给后续阶段」。
- **动作**：
  1. 深睡后追加 **第二 pass（轻量）**：输入 = 本轮新产出的 `[原则]` + 全库 `[原则]` 清单（**不含**当天痕迹，控制材料），任务 = 找出 **2 条以上原则的共同上位原则**（跨主题联想），产出仍走 `principles` add/replace + 源指针。
  2. 单独开关 `enableRemPass`（缺省关）与独立模型档位（复用 `sleepProvider/sleepModel` 回落链）。
  3. 产出必须带**至少 2 个不同主题的源指针**，否则宿主拒收。
- **验收**：开启后审计行出现 `remPass: {candidates, added}`；产出原则的源指针覆盖 ≥2 个不同 `##` 主题。
- **风险**：LLM 硬凑上位概念（幻觉）→ 双源指针硬门 + `≥3 条痕迹` 沿用 + 宁缺毋滥；先 shadow（只记候选不入册）跑一段再开写入。

### 10. 显著性（NE / DA）→ P1
- **现状**：无。优先级只靠命中次数 + 标签（`env`/`lesson` 等）+ 四问。
- **缺口**：生物侧 DA 标记**显著性/奖赏**，优先巩固「结果好/被纠正/被用户拍板」的东西。
- **动作**：
  1. `activity` 聚合时对候选加**显著性分**：`+2` 用户拍板/明确纠正；`+1` 任务成功达成（`goal complete` / episode outcome=success）；`-1` 失败尝试。
  2. 深睡材料「加深候选」段按 **hits30 × 显著性** 排序（现仅按 hits30）。
  3. 显著性分**不落 notes、不进索引行**（守 v11「运行时与维护信息分离」），只活在 `audit/activity.jsonl` 与材料里。
- **验收**：构造一成功一失败两条同 hit 数条目 → 材料排序成功者在前。
- **风险**：显著性来源不可靠（episode outcome 判定）→ 只作**排序权重**，不作入册门槛。

### 11. 线索依赖检索 ✅（维护）
- **现状**：词法+向量融合召回（`vec.ts`）、`§小节` 内容锚定位、`read_section` 主路径 + grep 兜底、指针路由四要素。
- **缺口**：无。
- **动作**：不改（P1/P2 的降权与抑制会改动排序，届时回归一次召回质量）。

### 12. 元认知反思 ✅（增益·维护）
- **现状**：`distill.ts:276` 深睡「反思三通道」——认识自己（原则写 AGENT.md）+ 认识用户（画像 USER.md）+ 沉淀任务路径（`[路径]` 写 AGENT.md）。
- **缺口**：无（这是生物对照之外的增益项：把"自我/他者模型"做成两个一等公民）。
- **动作**：不改。

### 13. 压缩语义（**需拍板**）
- **现状**：概况放索引行 + **正文原封不动留 notes**，懒加载只是延后读取 ⇒ **无损索引化**。生物侧压缩是**有损**的（丢细节保 gist，产生系统失真但容量不涨，见 Nagy 2020）。另外 `notes/` 无硬限（>8000 仅提示），容量单调增长。
- **缺口**：`压缩 ≠ 索引化`。若不承认这点，第 7/8 项的"遗忘"就永远只是"降权"。
- **两条路（须二选一，否则 #8 没有语义依据）**：
  - **路 A（承认索引化）**：不改语义，容量问题全交给 §8.1 分裂律 R / K 摊薄 + `write_gate` 红线。**#8 只做归档不做删除**。
  - **路 B（真压缩）**：细节移出 `notes/` 进 `notes/archive/`，正文里只留 gist + 归档指针；容量真的降，但**不可逆程度上升**（可回滚但要人捞）。
- **建议**：**先走路 A**（#8 的 archive 形态已经够用），把路 B 列为观察项——等 `notes/` 真的顶到 8000 且归档后仍不够，再谈有损。

## 四、不做清单

- **不做直删**：`forgetOps` 只允许 `archive`/`keep`，删除仍归人工审计裁决（守 §2.7.2 与「变更先判因备份」）。
- **不动触发节奏**：深睡仍「全部会话停滞 ≥3h」；不引入"浅睡/午睡"多相调度（避免堆叠）。
- **不把显著性写进索引行**：守 v11「运行时与维护信息分离」。
- **不为 REM 相新建调度器**：挂在既有深睡 pass 之后，单开关。

## 附：神经科学侧基准

- [Kim & Park 2025, BMB Reports — Systems memory consolidation during sleep](https://pmc.ncbi.nlm.nih.gov/articles/PMC12576410)：系统巩固 vs 突触巩固；NREM（slow-oscillation+spindle+ripple 三重耦合 → 回放 → 稳定化）／REM（theta → 整合、抽象、情绪标记）；SHY 全局下调 + NREM 增强 / REM 修剪；NE 调巩固时机、DA 调显著性优先。
- [McClelland, McNaughton & O'Reilly 1995 — CLS](http://wixtedlab.ucsd.edu/publications/Psych%20218/McClellandMcNaughtonOReilly95.pdf) · [Kumaran, Hassabis & McClelland 2016 — CLS Updated](https://web.stanford.edu/~jlmcc/papers/KumaranHassabisMcC16CLSUpdate.pdf)：海马快速情节 / 新皮层慢速统计，睡眠回放完成转移。
- [Nagy, Török & Orbán 2020, PLOS Comput Biol — Optimal forgetting: semantic compression](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1008367)：遗忘 = 用生成模型对情节做有损语义压缩，失真与泛化同源。
