## 1. 验收断言

### A 类 · 落点完备性

| # | 断言 | 判据 |
|---|---|---|
| A1 | **每个 Record kind 都能映射到唯一一面**（内容/经历/元） | 遍历 `records.jsonl` 1,177 条的 kind 集合，逐一由 S0 契约的 `projection` 判面；出现"无面归属"或"多面归属" ⇒ FAIL |
| A2 | **三面载体都真实存在且可读** | 内容面：三索引 + notes 可读；经历面：环记录 105 条可读且 `file=''`；元面：`ledger.jsonl` 可解析 |
| A3 | **时态单一实现** | `fact-ring#isLive` 是唯一 `validFrom/validTo` 判定处（grep 无第二份） |

### B 类 · 数据面一致性（X4/G6）

| # | 断言 | 判据 |
|---|---|---|
| B1 | **三处根的主从关系有唯一声明** | 注册表或 `targets.ts` 中能查到"活体根 = 哪个、另两处是什么" |
| B2 | **面板可显示当前活体根** | 一屏可见；数值与实际读取路径一致（非硬编码） |
| B3 | **声明与实测一致** | 实测三处内容差异（标签分布不同）与声明相符；若声明"同步"，实测必须同步 |

### C 类 · 审计面合流（X3/G9）

| # | 断言 | 判据 |
|---|---|---|
| C1 | **一份命令出全域分流指标** | 合流后 `mcl-step` 总数 = 冻结档 1,120 + 现行档中 `mcl-step` 部分（**无重复计数、无遗漏**） |
| C2 | **跨期口径显式** | 输出中标注每条记录的来源档与时间范围；`channel` 缺失项（184 条）单列不并入分母 ⚠️ |
| C3 | **不迁移数据** | 冻结档 mtime/size 不变（校验前后一致） |

### D 类 · 工程纪律（双棘轮）

| # | 断言 |
|---|---|
| D1 | `audit-wiring`：I1 ≤120 / I2 ≤12 不破 |
| D2 | `audit-fnspan`：无新增超 120 行函数（基线含 `applyForgetOps 120`、`mountDistillEvents 123`） |
| D3 | `audit-architecture`：循环 0、隐藏环 0、深度 ≤11 |
| D4 | `check-hardcode .`：零硬编码 |
| D5 | `check-runner` 全绿（77 项 + 新增） |

### E 类 · 文档对齐（X1）

| # | 断言 |
|---|---|
| E1 | `check-arch-sync` **六项全 PASS**（模块数三方一致 · 注入预算 4000 一致 · 桥退役 0） |
| E2 | `ARCHITECTURE.md` 补入 MCL 行，且其载体/职责与 `scheduler.ts:689` 实测一致 |
| E3 | 深睡归属在文档中**明确标注**（不再隐含在蒸馏产线内） |
