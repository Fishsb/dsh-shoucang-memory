## 2. 施工卡

### X1 · 修 L8（`droppedStable` 真实化）—— **会改注入文本**

**缺陷**：`panel-shared` 里 `const droppedStable = 0` 是**硬编码 0**，而 stable 段实际会丢
`dA.length + dU.length` 行（两块 55%/45% 分块裁切）。⇒ `droppedAll` **只算了 oneshot**，
末尾那行「本步受预算 N 字符约束省略 M 行」的 **M 少算**。

**为什么此前没修**：修它会**改变注入文本**（M 变大或该提示行首次出现），而"注入文本不变"是
R1/R2 的验收前提。⇒ 必须**单独一轮**做，并在验收里**逐字符说明差异**。

**做法**（最小）：
```ts
const droppedStable = dA.length + dU.length          // 真实（原先硬编码 0）
const droppedAll = droppedStable + droppedOneshot.length
```
⇒ 注意 `dA`/`dU` 作用域在稳定面缓存分支内 ⇒ 需**提升**（或复用已写入的 `cache.realCut.dropped`）。

**风险与纪律**：
- 注入文本**有意变化** ⇒ 对拍会 FAIL，**这是预期的**；断言要求**差异只出现在末尾提示行**
  （若出现在别处 ⇒ 说明改错，须回退）；
- 变化须**记 CHANGELOG**（用户可见）；
- 基线须**更新**（`--write`）并记录"有意变化"的正反向证据。

### X2 · L2 长函数 —— **决策而非默认拆分**

`audit-fnspan` 是**报告态**（不判失败），且这两个函数**不是装配函数**（I1 不判它们）。
⇒ 本卡**不预设"必须拆"**，而是**给出行数与理由，做出决策**：
- 若拆：须证明**行为不变**（对拍/单测）；
- 若不拆：须写明**为何不拆**（如"拆分只动行数、不改任何判据；而 `deepsleep-run`/`materials`
  的接缝已在领域层划过，再切是**按行数硬切**"—— 那正是门禁明令禁止的）。
