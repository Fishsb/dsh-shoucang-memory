## 1. 病灶（一条根因 · 三条放大链）

**根因（架构级）**：`§小节名` 是库的**内容锚**（`skill/SKILL.md`：指针 § = 小节名 = 内容锚），但"**如何把名字解析成小节**"这件事在仓内**有四份各自为政的实现**，且**四者对"多命中"的处置互不相同**：

| # | 实现 | 位置 | 同名多命中时的行为 |
|---|---|---|---|
| ① | 读侧（权威声明） | `skill/scripts/read_section.mjs:27-31` | **取第一个命中**（静默） |
| ② | 写门 | `skill/scripts/memory_write_gate.mjs:111-124,200-211` | 标题**集去重** ⇒ 同名折叠，视为存在 |
| ③ | 材料/树操作 | `src/treeops.ts:460 matchSection`（消费者：`forgetops#sectionExists` · `deepsleep-materials:131` · treeops rename/merge/split） | **多命中 ⇒ 返回 null（宁缺毋滥）= 判为不存在** |
| ④ | 写入件 | `skill/scripts/memory-append.mjs:54-93` | 逐级下钻，**取第一个命中** |

⇒ 同一个指针 `notes/env.md §插件注入`：**读侧能读出正文、写门判通过、材料侧判"不存在"并静默剔除**（检查报告 §2-L4 已实证）。

**放大链 1 · 写入面有旁路**：`src/distill-write.ts:283` 的新索引行走 `memory-append.mjs <target> - --new <行>`，该分支（`:96-101`）**只校验行首标签**，对行内 `→ notes/x.md §y` **零校验**；而唯一做 §校验的写门**不在这条路上**。先红实证：隔离库塞一条悬空指针 ⇒ **append exit 0 落盘**，同一行过写门 ⇒ **exit 2**。

**放大链 2 · 写门自短路**：`memory_write_gate.mjs` 中容量分支（`:234-266`）**排在**正确性判定（`:267 issues.length → exit 2`）**之前**，两支都 `process.exit(0)`。实测容量：MEMORY **26022/5000=520%** · AGENT **7489/3000=250%** · USER 2619/3000=87% ⇒ **§指针判据当前只在 USER.md 上真正生效**。同一文件双跑（cap=5000 → exit 0 且不提指针；cap=999999 → exit 2 列出 56 条）即为证据。`:246` 的注释「悬空指针 exit 2 不动」与实况相反。

**放大链 3 · 无可见面**：唯一逐条列出悬空的 `memory-reconcile.mjs` **不在 `check-runner.mjs#CHECKS`**，且**恒 exit 0**（实测有 ❌ 仍 exit=0）；面板「指针健康」已于 2026-09-11 按用户要求移除；`check-shared-fn.mjs`（在册）**只扫 `src/*.ts`**，`.mjs` 工具链的重复实现不在其视野。

**后果（均已实测）**：
- 悬空 **90 段 / 775（11.6%）**：真缺失 57 段（48 组）+ 同名歧义 33 段（4 组）；去重 52 组。
- 读侧：`read_section notes/lessons.md "路径基准差异"` ⇒ **exit 1**（小节不存在）。
- 材料侧：深睡冷候选 37 条 → **10 条被静默剔除（27%）**（无计数、`catch{}` 吞掉）。
- **新增仍在继续**：库 git 取证 `§ZCode 环境` / `§会话开头注入` / `§版本控制与上游协作` **首现 2026-09-18**。

## 2. 目标态（架构决策 D1–D5）

> 每条决策都写清**为什么不采用更简单的做法**——简单做法在本架构下会退化回现状。

**D1 · 「三态」取代「二值」。** 寻址结果 = `exists | ambiguous | missing`（+ 候选集）。**歧义 ≠ 不存在**。
*为什么不只用二值*：同名小节是**真实存在**的情况（实测 env.md 2 处），二值语义必然二选一地造假——要么静默取首个（读侧现状，检索结果不可预期），要么判不存在（材料侧现状，静默丢知识）。

**D2 · 语义单源，物理多处，**由差分锁**保证同口径。** TS 侧 `src/section-ref.ts` + 库工具链 `skill/scripts/section-ref.mjs` 各一份实现是**不可消除**的（子进程活件零依赖、不得 import `src/`——仓内 `findSecrets` 已有同款先例与注释）。
*为什么不追求物理唯一*：硬追会产生"`src` 依赖库内脚本"或反之的**跨面耦合**，与「数据根外置（ADR-0006）」「脚本零依赖」两条既有约束冲突。⇒ 正确的不变量是**语义单源可机检**：新增 `check-section-ref-parity`（差分锁），同一夹具集驱动两处实现，逐例比对 `state + 候选集`，不一致即红（含反例自证）。

**D3 · 唯一强制点：索引行准入。** 任何写入主档（MEMORY/USER/AGENT）索引行的路径，落盘前必须过同一 `SectionRef` 校验：`missing ⇒ 拒`（沿用写门 exit 2 语义）；`ambiguous ⇒ 放行但要求父/子路径消歧或显式标注`。
*为什么不只修那条旁路*：旁路是"当前已知的一条"；强制点落在**准入判据**上，才是路径无关的收口。

**D4 · 正确性与容量正交。** 判据分两类：**正确性**（凭据 exit 5 / 指针 exit 2 / 格式 exit 4）与**容量**（用户 2026-09-16 判定：提醒即可、不阻断）。二者**必须都报**：容量分支**不得**成为吞掉正确性结论的早退分支。退出码优先级：`5 > 2 > 4 > 容量(0)`。
*为什么不改回容量硬拒*：容量硬拒的后果已在案（AGENT 279% 时深睡全被挡、水位回滚）——那是**新引入的风险**，不是修问题。

**D5 · 锚变更必须同步指针（结构性收口）。** 小节 rename/move/merge 之后，索引指针必须仍可解析；由机检守「操作后悬空数不增」。
*为什么必要*：实测 52 组悬空里**20 组属"该主题在另一个 notes 文件里"**（例：`lessons.md §决策与施工边界` → 实际在 `flows.md`），说明**搬家没有维护指针**；只修存量不修这条链，指针会继续漂。

## 3. 语义设计（SectionRef v1）

**归一（三步，全部显式）**
1. 去行尾日期括号：`X（2026-09-03 增补）` → `X`（与 `coreName` / 门禁既有口径一致）。
2. 大小写与空白归一（全角空格、连续空白）。
3. 路径切分：`§父/§子` 与 `§父/子` 等价（斜杠即层级分隔）；`§A/§B` 为**并列候选**（同一文件的多个小节）。

**裁决表（唯一口径，两处实现必须逐例一致）**

| 情形 | state | 候选集 | 读侧（read_section） | 写门 | 材料侧 |
|---|---|---|---|---|---|
| 归一后精确命中恰好 1 个标题 | `exists` | 该节（`exact=true`） | 返回正文 | 通过 | 保留 |
| 无精确命中、双向包含（loose）恰好 1 个 | `exists` | 该节（`exact=false`） | 返回正文 | 通过 | 保留 |
| 命中 ≥2 个（含同名 `##`/`###`） | `ambiguous` | 全部（含各自父路径） | 返回首个 + 顶部横幅列出其余候选（`--strict` ⇒ exit 1） | 通过 + 提示消歧 | **保留 + 标注歧义**（不再静默剔除） |
| 0 命中，但**文件存在** | `missing` | 空 | exit 1 + 列可用小节 | **exit 2 拒写** | 剔除 + **计数可见** |
| 文件不存在 | `missing` | 空 | exit 4 | exit 2 | 剔除 + 计数 |

**兼容性**：`forgetops#sectionExists(memRoot,file,sec)` 保留签名，内部改为 `resolveSection(...).state === 'exists'`⇒**行为对既有调用点不变**（歧义仍为"否"），但新增三态接口供消费者升级；`test-forgetops.mjs ⑪` 四条断言继续绿。

## 5. 影响面（逐面，含用户要求的 UI/RPC）

| 面 | 是否受影响 | 说明 |

## 8. 不做（边界）

- **不重命名 notes 文件、不重构章节层级**（除 P2a 的同名合并）。
- **不引入向量判定"小节同一性"**：成本高、不可复现；词面 Dice 足以把存量分成 A/B/C 三档，C 档本就是人工判断。
- **不改容量口径**（MEMORY 520% 是**登记事实**，不是本册的修复对象；容量口径变更须单独拍板）。
- **不复活**已按用户要求移除的面板「指针健康」版面——可见面走**在册机检 + 对账器同源**（Q4 若拍板，可另行讨论最小 UI 落点）。
- **不碰** `_memory/`（仓内非活体副本）与知识区（非记忆库）。
