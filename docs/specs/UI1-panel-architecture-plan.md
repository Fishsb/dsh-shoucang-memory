**38 条 RPC 路由** · **19 个领域模块**（环 8 · 记录 2 · 读侧 3 · 观测 3 · 断言 2）。

### 1.4 **核心矛盾**

| 侧 | 纪律 | 状态 |
|---|---|---|
| 后端 `src/` | `check-module-growth`（冻结棘轮）· `audit-fnspan` · `audit-wiring` I1/I2 | ✅ 完备 —— 本轮多次被它拦下并**逼出领域接缝拆分** |
| 前端 `src-client/` | **无** | ❌ **一条都没有** ⇒ `body.js` 长到 **5477 行**而无人知 |

⇒ **这不是功能问题，是纪律不对等。** 加板块只会让单体更长。

### 1.5 门禁现状的两个约束（决定了下面的做法）

| 约束 | 实测 |
|---|---|
| `check-module-growth` **不能直接扩面** | 它**硬编码** `const SRC = join(root,'src')`，扫描面是 **`src/**/*.ts`**；而 `src-client/` 是 **`.js`** |
| 组件使用**不可静态全判** | `UI.button` 是 `body.js` 内 `var UI={}` 的方法，`wa-*` **运行时生成** ⇒ 静态只能看到字面量 |

### 1.6 回归证据的**覆盖边界**（决定要不要补证据）

`ui-geo-regress` 实测覆盖：弹窗/内容区/4 KPI 首屏/操作卡/**按钮由组件库承载**/**`shadowRoot` 存在**/
进度条接管方案值/**零 `wa-select` 残留**/下拉就位 · 且 **`.click()` 8 次**。

**但它不测**：`submit` = 0 · `fetch(` = 0 · `POST` = 0 ⇒ **不覆盖"提交 → RPC → 回流"**。

⇒ 仅凭它**不足以**证明"拆分后行为不变"，故方案含 **U5** 补齐。

## 2. 决策

### U0 · 让纪律可见（**必须先做**）

**为什么最先**：没有门，拆完会**长回去** —— 后端就是靠棘轮才被迫按接缝拆的。

| 卡 | 内容 |
|---|---|
| **U0-a** | **改** `check-module-growth.mjs`：支持**多扫描根**（`src/` + `src-client/`）且支持 **`.js`**；把 `body.js` **5477** 冻结为基线（棘轮，只许收紧） |
| **U0-b** | 新增 **`check-ui-components.mjs`**：**字面量对账** —— `vendor.js` 的 import ↔ 代码中的 `wa-*` 字面量，**两个方向都报**。**门内必须注明局限**：`UI.button`/`UI.select` 这类运行时生成的用法**扫不到**（不得声称"覆盖全部组件使用"） |
| **U0-c** | 新增 **`src-client/` 解析可读性**断言（防引入语法错误后静默）—— 现在连这一步都没有 |

### U1 · **按 fan-in 逐个抽服务**（**不做大 ctx 一次性迁移**）

**依据（node 实测 · 第二轮对抗）**：顶层 **125 个符号** = **90 函数 + 35 `var`**；这些 `var` 被**赋值 49 次**；
**90 个函数里 69 个引用可变符号**（只有 **21** 个纯函数可直接抽）。**高 fan-in 分布**：

| 符号 | fan-in | 性质 | 处置 |
|---|---|---|---|
| `UI` | **34** | 纯渲染封装 | **抽为 `ui-kit.js`** ⇒ 一次惠及 34 个函数 |
| `Derive` | **25** | 派生/格式化工具 | 抽为模块（只读） |
| `Cfg` | **15** | 配置读取 | 抽为模块（只读） |
| `Log` | **12** | 日志器 | 抽为模块（可注入） |
| `CSS` | **8** | 样式常量 | **只读常量**，最易抽 |
| `refs` · `inject` · `Store` · `Fold` · `memoryViewScroll` | 7/6/4/4/4 | **真·可变状态** | **留在入口**，按需以参数传给少数函数 |

**做法**：**按 fan-in 从大到小，一次抽一个**（`CSS` → `UI` → `Derive` → `Cfg` → `Log` …），
**每抽一个立即跑 `ui-geo-regress`**；**真状态留在入口**。

> ⚠ **为什么不是"先建一个大 ctx"**：那会**同时改动 69 个函数的签名** ⇒ 反馈周期长、回归面大，
> 与"小步可验"背道而驰（该判断由第二轮对抗实测得出，见判因记录 §6.1）。
>
> ⚠ **模块形态**：`body.js` 是**手写 IIFE**（末行 `})();`）且**内部含条件 CJS 导出**（`module.exports` ×2）
> ⇒ 拆成 ESM 时**包装形态要一并处理**（U2 需含此步）。

### U5 · 补行为级证据（**补 §1.6 的缺口**）
