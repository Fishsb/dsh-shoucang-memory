# S4 · 消费链条验收方案

> 配套：`S4-consumption-plan.md`。**任一项 FAIL 即 S4 未完成。**
> **本板块的特殊性**：它是**收口**——前四块产出的类型必须在这里**真的可达**。因此验收的核心不是"新功能能用"，而是「**声明的东西真的抵达了注入面**」。

---

## 1. 验收断言

### A 类 · 可达性完备（**本板块核心**）

| # | 断言 | 判据 |
|---|---|---|
| A1 | **S0-契约中 `reachable:true` 的类型，实际注入面能取到** | 按类型逐一构造情境，实测其在注入文本中出现（端到端，非单测） |
| A2 | **`reachable:false` 的类型确实取不到**（且原因与契约 `why` 一致） | 反例验证 |
| A3 | **正面断言可复现**：`supply-assembly` 当前状态（输出只进诊断面）**必须被机检判为"未抵达"** | S4-9 的反例 |
| A4 | **105 条环记录可达** | 情境命中时能在注入面看到环记录行（**含 `why:cue` 依据**） |

### B 类 · 预算与装配单一化（G5）

| # | 断言 | 判据 |
|---|---|---|
| B1 | **只有一份预算账** | `panel-shared` 不再手写三层切分；`SupplyBudget` 是唯一预算类型 |
| B2 | **账与真实裁切可比** | 记账的 `kept`/`dropped` 与**实际注入文本**一致（逐字节比对，非"近似"） |
| B3 | **五处差异逐项决策留痕** | 抬头/块标题/`- ` 前缀/段序/省略文案，每项有决策记录（**禁止静默切换**） |
| B4 | **换装配后注入字节差异可解释** | diff 出的每一处差异都能对应到 B3 的某条决策 |

### C 类 · 三层供给生效

| # | 断言 | 判据 |
|---|---|---|
| C1 | **判据常驻在位** | 三层判据（<200 字符）出现在每步注入面；字数为实测值 |
| C2 | **中层 `process` 槽真在工作** | 置 `process` 预算 > 0 ⇒ 任务开始时注入 `[路径]`；置 0 ⇒ **行为与现状逐字节一致**（缺省零变化） |
| C3 | **`[路径]` 已从恒常面剥离** | 开启 `process` 后，`[路径]` 不再同时出现在 stable 面（不重复供给） |
| C4 | **到期前瞻生效** | 构造 `commitment` due ⇒ 中层注入该承诺；未 due ⇒ 不注入 |
| C5 | **经历面扩容有数值依据** | `topN`/`budgetChars` 的档位由**历史审计回算**得出，非拍脑袋 ⚠️ |

### D 类 · 内层两项判据

| # | 断言 | 判据 |
|---|---|---|
| D1 | **检索停止准则** | 记录查询收益；同一来源连续 N 次零增益 ⇒ 触发换向（审计可见） |
| D2 | **两条件分流** | `fast` 需同时满足：`sim` + `hasHighConf` + 环境有规律 + 有反馈机会；审计能解释"为何不快判" |
| D3 | **快通道率变化可测** | 改动前后 `channel=fast` 占比对比（**基线：名义 25.4% / 实际 2.3%**） |
| D4 | **零贡献率改善** | step1 `injected>0` 占比对比（**基线 49.3%**）——这是 S4 的**最终效果指标** |

### E 类 · 不变量守卫

| # | 断言 | 判据 |
|---|---|---|
| E1 | **恒定面必在**（R1） | `[原则]`/`[路径]` 不被比例裁；P 层行数不因新槽而减少 |
| E2 | **被裁留痕**（R2） | 构造超预算 ⇒ 注入面出现"另有 N 条未进入"提示 |
| E3 | **块不丢**（R3） | 构造 AGENT 侧超预算 ⇒ USER 画像段**仍在**（历史缺陷：曾整段挤掉） |
| E4 | **槽不互挤**（R4） | 开启 `process` ⇒ `situation` 与 `dynamic` 的保留行数不变 |
| E5 | **未新增常驻注入点**（R5） | 注入挂点数不增（走既有挂点） |

### F 类 · 工程纪律

| # | 断言 |
|---|---|
| F1 | `audit-wiring` I1/I2 不破 |
| F2 | `audit-fnspan` 无新增超 120 行 |
| F3 | `audit-architecture`：循环 0、隐藏环 0、深度 ≤11 |
| F4 | 新增测试/机检**已登记** `check-runner`；全绿 |
| F5 | `check-hardcode .` 零硬编码 |

## 3. 关键真值表（防假绿）

| 场景 | 期望 | 理由 |
|---|---|---|
| 模块**被 import 且被调用**，但输出不进注入面 | **FAIL** | 正是 `supply-assembly` 现状——G10 的假绿本体 |
| 记账说 `kept=48` 但注入面只有 18 行 | **FAIL** | 仓内已自认"影子账是近似值"⇒ 本板块要求**逐字节可比** |
| `process` 开启后注入变多，但 `situation` 保留数变少 | **FAIL** | 违反 R4 独立槽 |
| 新槽"接好了"但**缺省值不是 0** | **FAIL** | 必须可回滚，缺省零行为变化 |
| 只测单测（`test-*.mjs`）不测端到端注入 | **FAIL** | 可达性只能端到端证明 |
| `[路径]` 同时在 stable 与 process 出现 | **FAIL** | 重复供给（C3） |
