# S2S3 · 三层记忆供给链协调方案（L1 窗口级 / L2 会话级 / S3 睡眠）

> **性质**：**决策态方案册**（讨论→决策自由；**施工须具名授权** · R1）。
> **用户口径（2026-09-19，本册依据）**：
> 「L1 窗口级快速总结知识；**L2 会话级复盘需要参考整个会话 + L1 子代理产出的信息，并且需要去调整 L1 产出的信息**；
> **S3 睡眠不产出**，但需要**审查当日（睡眠区间）每一条记忆信息在会话实际中产生的影响**，然后做**裁剪压缩**——
> 像人休息整理信息一样，把细节全部压缩，**只保留重要方向节点**（可参考 skill 文档规则），尽量压缩细节。」
> **一句话架构**：**视野逐层放大（窗口 → 会话 → 当日全库）· 动作逐层变重（产出 → 校正 → 压缩）· 越靠上越少产出、越多整理。**

## 2. 三层协调协议（本册的核心）

### 2.1 视野与权限矩阵（**唯一事实源，三层共用**）

| 层 | 看到什么 | 能做什么 | **不能做什么** |
|---|---|---|---|
| **L1** 窗口 | 本窗口会话增量（现状 ~313 事件） | 产出索引行/画像行/候选（**只增**） | 不改历史、不跨窗口判断 |
| **L2** 会话 | **整个会话**（分层取材，§2.3）+ **L1 全部产出**（含未落地失败清单）+ 库内相关召回 | 产出会话级主线/教训；**调整本会话内 L1 条目**（revise/merge/demote，**归档留档、可回滚、绝不直删**） | **不得跨会话改写**；不做遗忘/删节（那是 S3）；不新增画像"生长"（归属见 §5-Q1） |
| **S3** 睡眠 | **当日（睡眠区间）新增的全部记忆条目** + **每条在会话中的实际影响证据**（§2.4）+ 库内全量 | **压缩**：合并/提纯/降级/归档；**方向节点保留、细节归档** | **不产出新内容**（`principles.added == 0` 为硬判据） |

### 2.2 交接协议（三条单向链，不闭环 → 无循环依赖）

```
L1 ──(本会话全部条目 + 失败清单)──► L2 ──(会话主线 + 校正后条目 + 未决)──► S3
                                                                          │
                                        影响账 + 压缩结果（只回写库，不反向派活）◄─┘
```
- **交接物形态化**：L1→L2 走"条目清单（含 seq 锚点）"；L2→S3 走"**当日条目 + 会话主线**"；S3 回写"影响账 + 压缩档"。
- **失败必须随行**：L1 未落地的条目（`dispatch-failed`）必须进入 L2 材料（否则 L2 会以为"会话没这条知识"）——**这是当前最大的断点**。

### 2.3 L2 材料口径（**看全但不喂全文**）

| 段 | 内容 | 上限 |
|---|---|---|
| ① L1 产出清单 | 本会话全部已落地条目 + **未落地/被拒清单**（含拒因） | 全量（薄行） |
| ② 会话骨架 | 每轮 `turn/end` 的**目标一句话**（由 L1 逐轮已产出的摘要复用，不重算） | ≤80 轮，超出按"信息密度"取样 |
| ③ 关键锚点原文 | **转折点**：纠错/失败/决策/用户更正/长耗时步 —— 按 seq 定位取原文片段 | ≤12 段 × ≤40 行 |
| ④ 库内相关 | 既有记忆召回（复用 `recallRanked`） | ≤20 行 |

⇒ **视野 = 全会话（靠 ①②覆盖）**，**成本 = 关键片段（靠 ③控）**，不随会话长度线性膨胀。

### 2.4 L2 触发与幂等（"会话告一段落"的可判据化）

现状**没有"会话结束"内核事件**（实测：只有 `agent/disposed`/`session/disposed`，主会话长期不销毁）。故采用**双维判据 + 兜底**：

| 判据 | 阈值（初值，待校准） | 理由 |
|---|---|---|
| 静默维 | `turn/end(completed)` 后空闲 ≥ **30 min**（与 L1 的 10 min **显式分层**） | 区分"这一轮结束"与"这条会话告一段落" |
| 内容维 | 本会话自上次复盘以来**新增 L1 条目 ≥ 8 条** 或 新增事件 ≥ 1200（≈ 会话中位 758 的 1.5 倍） | 空会话不烧 LLM |
| 兜底 | `agent/disposed` / `session/disposed` 命中即触发（幂等保证只补一次） | 防漏 |

**幂等锚**：水位文件已是 per-sid（`sessionId/lastSeq/runId/phase`）⇒ 增 `reviewedSeq` 字段；
**纪律复用既有"只在 done 时推进水位"**——复盘失败 ⇒ `reviewedSeq` 不前移，下轮重试（与 L1 同款断点续传）。

### 2.5 S3 影响审查（"每条记忆在会话实际中产生的影响"）

**证据面（全部现成，无需新建遥测）**：

| 影响维度 | 数据源 | 判据形态 |
|---|---|---|
| **是否被注入** | `mcl-step` 的 `hit/injected` | 确定性（有/无） |
| **是否被真读** | `audit/access-real.jsonl`（真实读埋点）+ `access.log` | 确定性（有/无） |
| **是否帮上忙** | `audit/yield-rounds.jsonl`（收益判定）+ `recall-diagnosis` 归因 | **代理指标**（见 §5-Q3） |
| **是否被回收** | 决策环 `outcome` / 承诺 `settle`（`ring-events.jsonl`） | 确定性（有/无） |
| **冷热与竞争** | `audit/activity.jsonl`（hits/lastHit/status） | 确定性 |

**影响账（每条一条记录）**：`{ 条目, 产出层(L1/L2), 产出时刻, 注入次数, 真读次数, 收益命中, 回收态, 裁决 }`，
裁决三档：`keep-direction`（保留方向节点）/ `compress`（压成一句方向）/ `archive`（细节归档，**可回滚**）。

### 2.6 压缩粒度（"只保留重要方向节点"）

- **参照 skill 文档现有规则**（不另造）：`skill/SKILL.md` 的三层（外层/中层/内层）+ notes 小节粒度 **R=1000 字** + 「宁粗勿细」+ 索引行四要素（`[tag] 主题 · 概况 → 指针`）。
- **压缩形态**：细节正文 → `notes/archive/`（沿用 `forgetops` 的**归档不直删**纪律）；索引行**保留一条方向**（主题 + 一句方向 + 指针指向归档）。
- **硬门**：压缩后 ① 索引行**只减不增** ② 每条被压缩项必须能在影响账里找到裁决依据 ③ 失败自动回滚（水位不前移）。

### 2.7 S3 睡眠汇报（**每轮一份 · 日历式永久留存**）+ 问题标记（**只标记不处理**）

> **用户口径（2026-09-19 增补）**：「每一次睡眠要产出一个汇报（睡眠的提存与压缩）；导致反向或无用的**汇报即可、不要处理**
> ——因为可能不是记忆本身的问题、而是注入/召回判断有问题，而睡眠自己去检索信息太浪费时间，**做好标记就可以**；
> 汇报要**像日历一样一直有、不会删除**且**UI 可见**；还要一个**睡眠产出问题统计**。」

**① 留存形态（append-only，永不删除）**

| 产物 | 路径（相对知识区） | 说明 |
|---|---|---|
| 人读汇报 | `reports/sleep/<YYYY-MM-DD>.md` | **每日一份**；同日多轮 ⇒ 同日文件内按轮追加小节（**不覆盖**） |
| 机器可读 | `audit/sleep-reports.jsonl` | 每轮一条（统计与 UI 的数据源） |
| 问题队列 | `audit/sleep-issues.jsonl` | 每条标记一行（**状态机**：`open → 处置/关闭`，只增不改历史行） |
| 现有 `delta.md` | **退役**（2026-09-19 用户拍板：**有日报板块就不需要它**） | ⚠ **但不能连注入源一起退役**：每轮注入面的「🧠 最近成长」正由它派生 ⇒ 注入侧改为**从报告派生**（同一函数），`delta.md` 只退役"文件与呈现" |

**② 每轮汇报的内容（固定五段）**
1. **区间**：`sleepEpoch` / 起止时刻 / 材料量（沿用既有审计字段）
2. **提存**：本轮新增/替换/合并了什么（逐条 + 源指针）
3. **压缩**：归档/压缩了什么（逐条 + **影响账依据**）
4. **问题标记**（★ 本轮重点）：`unused`（无用）/ `counter`（反向）清单 + 证据 + **"未处理"明示与原因**
5. **统计**：本轮计数 + 累计趋势（供 §2.7-④ 的看板）

**③ 问题标记的判据（**确定性证据**，睡眠不做检索、不追因）**

| 标记 | 判据（全部来自既有遥测） | 语义 |
|---|---|---|
| `unused`（无用） | 产出后 **N 天**（**缺省 3 天 · 可调 1–30**）内：**注入 0 次**（`mcl-step`）**且真读 0 次**（`access-real.jsonl`） | 该条从未进入任何一轮上下文 |
| `counter`（反向） | 被注入/被读之后，**同主题在后续轮被否定或纠正**：L2 校正为 `demote/merge`、或用户显式否定（`[更正]` 类信号）、或该主题的决策环 `outcome=miss` | 引入后产生了负向后果 |
| `suspect-recall`（**疑似召回问题**） | 标记为 `unused` **但**索引行质量正常（指针可解析 · 格式合规 · `[tag]` 合法） | **归因指向注入/召回面，不归因记忆本身** |
| `suspect-quality` | `unused` **且**索引行本身缺陷（指针悬空/格式违规/主题与正文不符） | 才可能真的是记忆质量问题 |

**④ 问题统计（睡眠产出问题统计 · 只读聚合）**
- 维度：**按类型**（unused/counter/suspect-recall/suspect-quality）× **按时间**（日/周趋势）× **按来源层**（L1 / L2）× **按文件**（notes 目标）。
- 关键比率：`unused 率`（本轮产出中从未被用过的比例）· `suspect-recall 占 unused 的比例`（**这个比值高 ⇒ 问题在召回面，不在记忆面**——正是用户担心的那一类）。
- 出口：面板「睡眠汇报」视图的问题统计卡 + 只读端点（§4 影响面）。

**⑤ 边界（防越权处置）**
- **只标记、不处置**：`unused/counter` **不触发** archive/delete；S3 的压缩裁决（§2.5）**必须另有影响账依据**且**与标记相互独立**。
- **不追因、不检索**：标记只记录事实（次数/时间/来源），**不做"为什么没用"的推断**（那是注入/召回面的事，且代价高）。
- **可追溯**：每条标记携带 `产出层/产出时刻/条目指针/证据读数/状态`，处置动作在 `sleep-issues.jsonl` **追加**状态行（不改历史）。

## 4. 影响面

| 面 | 影响 |
