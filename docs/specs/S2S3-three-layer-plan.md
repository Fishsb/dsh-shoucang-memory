# S2S3 · 三层记忆供给链协调方案（L1 窗口级 / L2 会话级 / S3 睡眠）

> **性质**：**决策态方案册**（讨论→决策自由；**施工须具名授权** · R1）。
> **版本**：**v2（2026-09-19 圆桌会审后修订）**。会审 = 会议 `s2s3-三层供给链-落地方案会审`（7 专家 · orchestrated · 导出见会议目录 `export.md`）。
> **用户口径（2026-09-19，本册依据）**：
> 「L1 窗口级快速总结知识；**L2 会话级复盘需要参考整个会话 + L1 子代理产出的信息，并且需要去调整 L1 产出的信息**；
> **S3 睡眠不产出**，但需要**审查当日（睡眠区间）每一条记忆信息在会话实际中产生的影响**，然后做**裁剪压缩**——
> 像人休息整理信息一样，把细节全部压缩，**只保留重要方向节点**，尽量压缩细节。」
> **一句话架构**：**视野逐层放大（窗口 → 会话 → 当日全库）· 动作逐层变重（产出 → 校正 → 压缩）· 越靠上越少产出、越多整理。**

> ⚠ **v2 相对 v1 的实质变化**（会审裁定，非文字修饰）：① 现状读数**口径化**并**勘误四处事实错误**（§1.2）；
> ② 册零从"L1 落盘修复"升为**落盘一致性前置项**（写入原语 + 库级锁 + 既存缺陷修复，§3.0）；
> ③ 册一「L2 能改 L1」**降为 append-only 校正提案流**（执行权留 S3，§3.1）；④ 容量红线改按**写门口径**报数（§1.1）。

## 2. 三层协调协议（本册核心）

### 2.1 视野与权限矩阵（**唯一事实源**）

| 层 | 看到什么 | 能做什么 | **不能做什么** |
|---|---|---|---|
| **L1** 窗口 | 本窗口会话增量 | 产出索引行/画像行/候选（**只增**） | 不改历史、不跨窗口判断 |
| **L2** 会话 | **整个会话**（§2.3）+ **L1 全部产出**（含失败清单）+ 库内相关召回 | 产出会话级主线/教训；**提出校正提案**（revise/merge/demote，**限本会话**，append-only，**不直接改库**） | **不得跨会话改写**；**不得直接改库**（执行权在 S3）；不新增画像"生长"（归属见 §5-Q1） |
| **S3** 睡眠 | 当日（睡眠区间）新增条目 + 每条的实际影响证据（§2.5）+ 库内全量 + **L2 校正提案流** | **压缩**：合并/提纯/降级/归档；**执行 L2 提案**；方向节点保留、细节归档 | **不产出新内容**（**三通道**断言：`added==0 && replaced==0 && profiles==0`） |

### 2.2 交接协议（单向链，不闭环）

```
L1 ──(本会话条目清单 + 失败清单 + manifest)──► L2 ──(会话主线 + 校正提案流)──► S3
                                                                              │
                                        影响账 + 压缩结果 + 睡眠汇报（只回写库，不反向派活）◄┘
```
- **交接物形态化**：L1→L2 走"条目清单（含 seq 锚点）+ **失败明细**"；L2→S3 走"**当日条目 + 会话主线 + 校正提案流**"；S3 回写"影响账 + 压缩档 + 汇报"。
- **失败必须随行**：L1 未落地的条目必须进 L2 材料（否则 L2 会以为"会话没这条知识"）——**当前断点**：`write.ingest` 441 行**只有计数、无条目标识**（`target` 只是路由名 "shoucang"）⇒ 册零补 **+1 字段**（§3.0）。

### 2.3 L2 材料口径（看全但不喂全文）

| 段 | 内容 | 上限 |
|---|---|---|
| ① L1 产出清单 | 本会话全部已落地条目 + **未落地/被拒清单（含拒因与条目身份）** | 全量（薄行） |
| ② 会话骨架 | 每轮 `turn/end` 的目标一句话（复用 L1 已产出摘要，不重算） | ≤80 轮，超出按信息密度取样 |
| ③ 关键锚点原文 | 转折点（纠错/失败/决策/用户更正/长耗时步），按 seq 取原文 | ≤12 段 × ≤40 行 |
| ④ 库内相关 | 既有记忆召回（复用 `recallRanked`） | ≤20 行 |

⚠ **"本会话 L1 全清单"今天不存在**（manifest 只在同轮内存、CAP=1500 丢最早行）⇒ 册零须补 **manifest 持久化** `<kRoot>/audit/distill-manifest/<sid>.jsonl`（§3.0-D5）。

### 2.4 L2 触发与幂等（"会话告一段落"的可判据化）

无"会话结束"内核事件（实测：只有 `agent/disposed`/`session/disposed`）⇒ 双维 + 兜底：

| 判据 | 阈值 | 备注 |
|---|---|---|
| 静默维 | `turn/end(completed)` 后空闲 ≥ **30 min**（与 L1 的 10 min 显式分层） | **待拍板 H-4** |
| 内容维 | 自上次复盘以来新增 L1 条目 ≥ **8** 或新增事件 ≥ **1200** | **待拍板 H-4**（实测段中位 4 ⇒ 阈值可能偏高，须校准） |
| 兜底 | `agent/disposed`/`session/disposed` 命中即触发（幂等保证只补一次） | ⚠ 主会话长期不销毁 ⇒ **短会话可能永不触发**；审计须能区分 `not-triggered / skipped-by-threshold / reviewed` **三态**（否则"漏触发"与"无内容"不可分） |

**幂等锚（双证）**：水位 per-sid（`sessionId/lastSeq/runId/phase`）增 `reviewedSeq`，并**同批落 `formatVersion` + `agentFingerprintAt`**（与 `distill-watermark.ts:125-139` 同款）——格式迁移后 seq 重排 ⇒ 不符即整段作废重跑。
⚠ `reviewedSeq` **不得并入 `distill-watermark.jsonl`**（该流 sid 末行生效，L1 每段一写会冲掉）。

### 2.5 S3 影响审查（"每条记忆在会话实际中产生的影响"）

| 影响维度 | 数据源 | 判据形态 |
|---|---|---|
| **是否被注入** | `mcl-step`：**必须先过滤 `phase==='inject'`** 再读 `injected` | 确定性（有/无） |
| **是否被真读** | `audit/access-real.jsonl`（**水位派生**：须先断言采集新鲜度，否则"真读 0"与"未采集"不可分） | 确定性 |
| **是否帮上忙** | `audit/yield-rounds.jsonl` + `recall-diagnosis` | **代理指标：只排序，不裁定** |
| **是否被回收** | 决策环 `outcome`（**唯一反向语义 `hit==='0'`**，`src/decision-ring.ts:171`）/ 承诺 `settle` | 确定性 |
| **冷热与竞争** | `audit/activity.jsonl`（**6 个读侧**，须收敛出口） | 确定性 |

⚠ **`injected` 字段三义（反例 1）**：`src/mcl.ts:511` 在 `phase==='inject'` fast 通道**硬写 `injected:0`**（实测 phase=inject 中 `injected===0` 有 3072 行）；slow 通道 `injected` 实为**材料字符数**（`mcl.ts:533`，值域 246–482）；compliance 段 **3498 行根本没有该字段**。
⇒ 统一口径写死：**"已注入" = `phase==='inject' && typeof injected==='number' && injected>0`**。

**影响账（每条一行）**：`{条目, 产出层(L1/L2), 产出时刻, 注入次数, 真读次数, 收益命中, 回收态, 裁决}`；裁决三档 `keep-direction / compress / archive`。
**落盘**：**并入 `audit/sleep-reports.jsonl`**（同源同形，**不另开** `audit/impact/<day>.jsonl` —— 会审裁剪）。

### 2.6 压缩粒度（只保留重要方向节点）

- 复用 skill 现规则：`skill/SKILL.md` 三层 + notes 小节粒度 **R=1000 字** + 「宁粗勿细」+ 索引行四要素。
- 形态：细节正文 → `notes/archive/`（沿用 `forgetops` **归档不直删**）；索引行保留一条方向（主题 + 一句方向 + 指针指向归档）。
- 硬门：① 索引行**只减不增** ② 每条被压缩项**必须能在影响账找到裁决依据** ③ 失败自动回滚（水位不前移）。

### 2.7 S3 睡眠汇报（每轮一份 · 日历式永久留存）+ 问题标记（只标记不处理）

> **用户口径（2026-09-19）**：「每一次睡眠要产出一个汇报（睡眠的提存与压缩）；导致反向或无用的**汇报即可、不要处理**——因为可能不是记忆本身的问题、而是注入/召回判断有问题……**做好标记就可以**；汇报像日历一样**一直有、不会删除**且**UI 可见**；还要一个**睡眠产出问题统计**。」

**① 留存形态（append-only）**

| 产物 | 路径（相对知识区） | 说明 |
|---|---|---|
| 人读汇报 | `reports/sleep/<YYYY-MM-DD>.md` | 每日一份；同日多轮 ⇒ **同日文件内按轮追加，不覆盖** |
| 机器可读 | `audit/sleep-reports.jsonl` | 每轮一条（统计与 UI 数据源；**影响账亦并入此流**） |
| 问题队列 | `audit/sleep-issues.jsonl` | 每条标记一行（状态机 `open → 处置/关闭`，**只增不改历史行**） |
| `delta.md` | **退役（仅限文件与呈现）** | 注入面「🧠 最近成长」改为**从报告派生**（同一函数）——**别把消费者当产物退役**（§3.4、§5-U2） |

**② 每轮汇报固定五段**：区间（`sleepEpoch`/起止/材料量）· 提存（逐条 + 源指针）· 压缩（逐条 + 影响账依据）· **问题标记**（unused/counter 清单 + 证据 + **"未处理"明示与原因**）· 统计（本轮计数 + 累计趋势）。

**③ 问题标记的判据（确定性证据，不检索、不追因）**

| 标记 | 判据 | 语义 |
|---|---|---|
| `unused` | 产出后 **N 天**（缺省 **3**，可调 1–30；§5-Q5）内：**注入 0 次**（**须按 `phase==='inject'` 口径**）**且真读 0 次**（须断言采集新鲜） | 从未进入任何一轮上下文 |
| `counter` | 被注入/被读之后，同主题**被否定或纠正**：决策环 `outcome.hit==='0'`（**Q7 裁定源 = `ring-commit`**）· L2 提案为 `demote/merge` · 用户显式否定 | 引入后产生负向后果 |
| `suspect-recall` | `unused` **但**索引行质量正常 | **归因指向注入/召回面，不归因记忆本身** |
| `suspect-quality` | `unused` **且**索引行本身缺陷 | 才可能是记忆质量问题 |

**统计口径修正（防趋势结构性失真）**：`unused` 标记**永不回收**（追加式状态机）⇒ 一条第 3 天被标记、第 5 天被真读，统计上仍是 unused ⇒ **比值会单调上升**。
⇒ 分母**固定为"当日产出条数"**，读数时**重算当前证据**，并**另存两字段** `unusedAtFirstObservation`（当时是否未用）与 `stillUnused`（现在是否仍未用）；比率**必须带分母绝对值**。

**④ 问题统计（只读聚合）**：按类型 × 时间（日/周）× 来源层（L1/L2）× 文件；关键比率 = `unused 率`、**`suspect-recall / unused`（该比值高 ⇒ 问题在召回面而非记忆面）**。出口 = 面板卡 + 只读端点（§4）。

**⑤ 边界**：**只标记不处置**（`unused/counter` **不触发** archive/delete；压缩裁决**必须另有影响账依据**且与标记**相互独立**）· 不追因不检索 · 可追溯（每条标记带产出层/时刻/指针/证据/状态）。

**会审新发现（不在五册内，但会污染册二判据）**：**同段重复蒸馏**——同一 `sid+chunk+区间` 被蒸馏最多 **24 次**：`352 行 − 173 键 = 179 条重复`，**拆为两种机制**：① **强制路径二次发射 16 条**（同键 Δt **<1s**，`dispatch-failed` → `dispatch-failed-forced`，16/16 可配对）② **真重蒸 163 条**（同键 Δt **≥1s**，水位未推进后重跑，涉及 42 键；同键次数分布 `{2:11,3:6,4:10,5:2,6:4,7:3,8:2,9:1,15:1,22:1,24:1}`）。
③ **同键内"除 `at` 外全字段相同"者 = 0 行** ⇒ **不存在纯时间戳重复记账**，即 179 条全是真事件（16 次二次发射 + 163 次重蒸）。
既有"失败 ⇒ 水位不推进 ⇒ 重试"的纪律会**放大**此现象，且每次重蒸都可能 `added>0` ⇒ **知识重复产出**（档 L 1105 vs 档 S 574 的落差即其量化）。
