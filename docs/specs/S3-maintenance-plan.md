# S3 · 维护链条方案（库 → 库）

> **板块职责**：**唯一能重写历史**的链条——整合、提纯、纠错、遗忘、跨主题重组。人类对应：**睡眠巩固**。
> **依赖**：S0（契约）· S1（落点）· **S2（生产产物是它的材料）**。
> **证据**：【读码】`deepsleep*.ts` 10 件 ·【文档】`cognition-mapping-landing-plan`（13 项机制对照）·【实测】审计。

---

## 1. 边界

| 是 | 不是 |
|---|---|
| 吃**库内**材料（pending / notes / 审计 / 环记录） | ✗ 读会话原文（那是 S2 的输入） |
| **重写**已有内容（合并/分裂/降级/提纯/失效） | ✗ 只增不改（那是 S2 的纪律） |
| 维护**深睡水位** | ✗ 维护蒸馏水位（S2，虽同一状态机） |

**人类对应**：NREM（表征转化/稳定化）≈ 归纳 pass；REM（跨域整合/抽象/情绪标记）≈ `crossTopic` pass。

### 2.3 关键实测【实测】

- `ledger.jsonl` 中 `check.sleep` **126 条**，`write.consolidate` **仅 8 条** ⇒ **睡眠自检活跃，但实际写入极少**。
- `audit.deep-sleep-probe` 10 条：多条 `result: stall`（`idleMin 59–67`）⇒ 探针判定"疑似卡住"。
- `episode 7` 条（`ledger` 中）vs 环记录 105 条 ⇒ 维护链的环产出规模有限。

## 3. 目标

### 3.1 独立入口（X2）——本板块最高优先

```
现状：scheduler → registerDistill → createDeepSleep
目标：scheduler → registerDistill ┐
                                  ├─ 维护链独立注册（新装配函数 ≤120 行）
              scheduler → registerMaintenance ┘
```

**约束**：I1 顶格（`applyForgetOps` 120/120）⇒ **新建装配函数**，不得塞入既有；`composition.ts` 句柄显式传递，**不新增惰性桥**（B3）。

**验收核心**：**行为等价**——迁移前后同窗口同材料跑出同产物（§5-C1）。

### 3.2 补齐四项机制（按价值排序）

| 序 | 机制 | 动作 | 依据 |
|---|---|---|---|
| 1 | **M4 产出健康度对账** | 深睡结束即出"本轮产出/被拒/空转原因"结构化摘要；**空转也要记**（当前 `closureOk` 107/107 全 false 即此问题） | 无它则无法判断维护链是否在干活 |
| 2 | **M2 遗忘候选消费** | 深睡材料增一段「遗忘候选（cold > N 天）」，上限 top-10 | `cognition-mapping` #6 已有方案 |
| 3 | **M3 跨日回放** | 判据加"同一原则在 ≥2 不同日窗被再激活 ⇒ 允许升格/扩容" | `cognition-mapping` #2 |
| 4 | **M1 REM 相** | `crossTopic`（带向量候选去判 + 宿主硬门 ≥2 个不同 § 源指针） | 已接线，仅需策略开启 ⚠️ 产物直接并入 AGENTS.md 画像，噪声代价高 |

### 3.3 空转可见化（M4 的延伸）

【实测】`check.sleep` 126 条 vs `write.consolidate` 8 条 ⇒ **必须能一眼看出"最近 N 轮深睡的空转率"**。这属 S3 的**交付物**，不是可选项。
