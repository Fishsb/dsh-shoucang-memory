## 0. 本验收方案的特殊要求：**先红后绿**

按成长画像那条 **[原则]**（修动前先加断言让旧行为变红以实证缺陷，改后转绿；断言拦下过宽修法则收窄）：

> **凡断言"改造后与改造前等价/一致"，其首次运行必须 FAIL。**
> 若首跑即绿 ⇒ **说明断言没测到那件事**（自证不足），须先收窄断言再施工。

这直接针对本会话反复出现的失效模式（"未跑与通过不可区分"）。**F2 / A2 / A4 三处强制适用。**

## R0 · 可对拍前置（**方案已修订**，见下方 R0-注）

**问题**：`buildHotMemoryText` 嵌在 `panel-shared.ts` 内**不可导出**（导出数已达
`audit-architecture` 棘轮上限 35）⇒ 无法在单测中调用它。

**修订（2026-09-14 实测后）**：原方案要求"抽模块使其可导出"。实测发现宿主端点
`GET /api/shoucang-panel/inject/preview?q=…` **直接返回真实注入文本** ⇒ **对拍无需抽模块**，
且证据更强（覆盖真实库的全部选行 / 裁切 / 画像分块行为，而非构造夹具）。
故 R0 改为**真机基线对拍**，**取消那次约 300 行的高风险搬移**。

| # | 断言 | 判据 | 实测 |
|---|---|---|---|
| **F1** | 改动前落**多 case 真机基线** | 三 case：`q=''`（**基线分支**）/ 有词（**相关性分支·命中**）/ 零命中词（**补位分支**）—— 单 case 覆盖不到相关性分支，会假绿 | ✅ 2928 / 3373 / 3318 字符 |
| **F2** | 改造后同端点**逐字节 == 基线** | `node scripts/inject-baseline-diff.mjs` → exit 0；不等时**打印首个差异字符位置 + 两侧上下文** | ✅ 连跑两次稳定 |
| **F3** | 基线落**非公开树**（含真实记忆内容） | `git check-ignore` 命中；不进公开树 | ✅ `_memory/audit/`（`.gitignore:22`） |
| **F4** | 端点不可达时 **SKIP 而非 FAIL** | exit 3（check-runner 判 skip） | ✅ 已登记 CHECKS |

> **R0-注（方案修订留痕）**：这是"**实测改变方案**"的又一例 —— 原设计把"能对拍"等同于"能 import"，
> 实测后发现**运行态端点本身就是更强的对拍面**。修订同时**避免**了一次高风险搬移，而那次搬移的
> 必要性**完全来自错误前提**。
> **附带收获**：本门是仓内**第一条守「注入文本逐字节」的回归门** —— 此前没有任何门守这一层
> （用户可见的注入文本若意外变化，只能靠人发现）。

## 判定口径

- **任一断言 FAIL ⇒ 该卡未完成**，不进入下一卡（沿用五阶段的"全绿方进"）。
- **SKIP 只允许一种情形**：R3-C3（数据不足），且**必须**同时交付复验方法。
- 本方案**不产生**新的"⛔ 经决策不采纳"项 —— R1/R2 的等价性验收若通不过，
  说明该架构改造**真的做不到**，届时须回到 S4 的 ⛔ 状态并**如实记录失败原因**（不得悄悄降级为"待办"）。
