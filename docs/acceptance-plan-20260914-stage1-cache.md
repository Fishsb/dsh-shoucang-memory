## 0. 总则

### 0.1 一句话口径

**任一条验收项红 ⇒ 本修复未完成。** 不存在"基本完成"。
唯一允许的例外：已显式登记为 xfail 的既有项（须点名）。

### 0.2 四条纪律（前三条沿用上一轮方案，第 4 条是上一轮**血的教训**）

1. **结论与证据同源**：每条结论附「同一次读取」的证据（路径 + 字节/行数 + 时间）。
2. **否定结论前先列全变体**：说"某处没引用 X"之前，把 `export const` / `export function` / `export async function` 等形态都搜过。
3. **反向证伪不可省**：任何新增门禁必须制造一次违规证明它会红。**只证明"绿" = 未验证。**
4. **【新增】区分「缓存没失效」与「输出没变」**（B1 的直接教训）：任何"××立即生效"的主张，
   判据必须落在**输出**上，而不是落在"缓存键变了"上。
   ⇒ 只验前者会**恒定假绿**：键变了、输出没变，正是本轮要修的那个病。

### 0.3 关键提醒

- **「仓内绿」≠「运行态绿」**：本修复属宿主侧代码，必须部署 + 用户热重载；**热重载未做不得记通过**。
- **不得用"读码看着对"代替判据**：本轮的病就是"读码看着完全正确"。
