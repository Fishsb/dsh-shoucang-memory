# 守藏面板 UI 优化方案 v1（展示内容 + 调节选项）

> **性质**：设计审计 + 优化方案（先文档；按 `[原则] 变更先判因备份`，改动一律**增量**，不动 `client.js` 既有结构骨架与 `sc-*` 样式语言）。
> **判因**：面板已从「3 视图」长到 **6 视图 / 30 端点 / 记忆板块 11 组**，且近三轮（MCL、判据 v2、库 git、体检 token 账）**只加了后端能力与端点，没同步 UI**——`/criteria`（判据+台账）、`/mcl/status`（认知环）**在 UI 里没有落点**；调节面存在「双通道 + 生效时机不一」的老问题。这是"能力长、控制面与展示面没跟上"的典型 settings rot（见 §1 规则 12）。
> **不变量**（引用本仓 `[flow]`/`[偏好]`）：`设计极简抗堆叠` → **拒绝再堆新面板**，先做信息层级与合并；`GUI preset 与内部文档` → 与既有 `docs/ui-design-20260909.md` / `settings-audit.md` 的拍板一致，**只增量**；`变更先判因备份` → 每项改动可回滚、先备份 `client.js`。
> **本轮只出方案，不改码**（改码需你点头；UI 改动的验收标准见 §7）。

## 1. 外部知识（可执行版 · 12 条）

来源：[Settings Page Best Practices · Living Checklist](https://setting.page/settings-page-best-practices-living-checklist)（2026-06）· [Windows app settings 指南](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings) · [Grafana dashboard best practices](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices) · 同类本地 LLM 面板（[LM Studio vs Open WebUI 对比](https://markaicode.com/vs/lm-studio-vs-open-webui/)、[Open WebUI settings/admin guide](https://mljourney.com/open-webui-features-settings-and-admin-guide/)）——**同类面板的共识是"发现式默认 + 渐进披露"**。

| # | 规则 | 对我们的含义 |
|---|---|---|
| R1 | 设置页回答**五问**：去哪改 / 改了会怎样 / 影响谁 / 能否撤销 / 是偏好还是高风险 | 每个控件旁给「作用域 + 生效时机 + 后果 + 是否可回滚」 |
| R2 | **按用户心智分桶**，不按后端模型分桶（Preferences / Privacy / Advanced / System…） | 现"参数调节"一页混了注入偏好 / 容量门 / 阈值 / 模型 / 通道 → 拆为「注入与画像」「记忆与容量」「模型与向量」「后台与调度」，高级项折叠 |
| R3 | **渐进披露**：常用在前，高级后置/折叠 | 记忆板块 11 组 → 首屏 5 组 + 「展开更多」 |
| R4 | **toggle 只用于即时二元状态**；互斥用 radio；多选用 checkbox；select 慎用 | 现 3 档以上枚举（level 5 档 / persona 4 档）当前是自绘 slider → 应为 **segmented radio**（可键盘） |
| R5 | **控件与风险匹配**：高风险需确认/解释/日志 | 改动容量门（影响写入拒绝）、遗忘阈值（影响归档）→ 需后果说明 + 保存反馈 |
| R6 | **文案说结果不说机制**（"Send weekly summary" > "Enable digest mode"）；避免双重否定 | 现描述多为机制（"v17 已生效：关闭=不注入画像…"）→ 改为「关掉：不再带画像（省 ~500 字符）」 |
| R7 | **始终显示状态**：saved / pending / invalid / failed | 现在**只有一处全局 status 条**；需每控件生效态徽章（`已生效` / `待重载`） |
| R8 | **就近校验**（不要只用全局错误条）+ 保留未保存编辑 | 数字输入需单位 + 范围 + 就近报错 |
| R9 | **作用域显式**（Personal/Device/System）+ 权限锁定原因可见 | 现"根目录 YAML 显示项 vs 全局注入参数"界线只在一句描述里 |
| R10 | 观测面板：**围绕关键信号组织**、**同类可比**、别硬编码变量 | 徽章只 3 项；趋势缺基线（"本周成长"无对照） |
| R11 | **空态/首访即最重要的状态**：给下一步动作，不只有"不可用" | 向量未就绪应给「启动 Ollama / 检查 :11434」的动作提示 |
| R12 | **设置页会像代码一样腐化**：定期复审、按工单重复点清理 | 建立"能力 vs 控件 vs 展示"三方对齐清单（本文 §6 验收） |

## 2. 目标信息架构（IA）

**保持 6 个顶层视图不变**（认知成本最低），调整**分桶、首屏与折叠**：

```
[记忆]  首屏：状态徽章行(v2 扩容) → 记忆库状态 → 知识索引 → 候选队列
        折叠区：notes 详情 / 本地知识区 / 向量召回 / 本周成长 / 判据注册表(移入"运行")
[画像]  保持（画像行 + 索引行来源）
[运行]  蒸馏运行 → 深度睡眠（状态机 + 回执 + 趋势）→ 认知环(MCL) → 判据注册表与对账 → 插件集合
[配置]  参数调节（分 4 桶 + 高级折叠 + 生效态徽章）→ 配置原文（YAML，只读说明+编辑）
```
- 新增落点：**运行**视图承接 `/criteria` + `/mcl/status` + 库 git 状态（**不再往记忆板块塞**——含我上一轮插入的判据卡，**自我修正**：它把首屏组数从 9 抬到 10）。
- 顶层视图名与分组标签保持既有（`记忆/运行/配置`），仅把「插件集合」从"运行"移入运行视图尾部（语义归位），不动路由。

## 5. 控件规范（落地细则）

| 控件 | 何时用 | 规范 |
|---|---|---|
| toggle | **即时生效的二元**开关（如 `hot_memory`、`mclEnabled`） | 右对齐；旁注作用域徽章；关=说明后果 |
| segmented radio | 3–5 档互斥（persona 4 档、level 5 档、融合策略） | 键盘方向键可达；当前档高亮；label 说结果 |
| number input | 阈值/容量（可用 slider 辅助） | 一律带单位 + placeholder 默认值 + `min/max`；越界就近红字 + 不入库 |
| select | 仅长列表（模型清单） | 保留；空列表给"如何去装模型" |
| 按钮 | 触发动作（检测端点 / 重载插件 / 生成报告） | 动词短语；执行中禁用 + 文案变"进行中…"；结果进 aria-live |

## 7. 验收判据（可测，不是"看着好"）

1. **每屏信息块 ≤ 7**、**任意设置点击深度 ≤ 2**（视图 → 控件）。
2. **每个控件有**：作用域徽章 + 生效态徽章 + 单位/范围/默认 + 就近校验。
3. **参数-能力对齐率 100%**（`scheduler.Config` zod 键 ↔ 面板控件 ↔ `/config` 返回三方列表逐一比对，可脚本化）。
4. 空态/错误态**必带下一步动作**（无"只有不可用"）。
5. **键盘可达**全控件；状态变化有 `aria-live`。
6. 展示面：`/criteria`、`/mcl/status`、库 git、容量水位**均可见**（本轮新增能力零遗漏）。

## 8. 明确不做（防堆叠）

- 不引入 UI 框架/组件库（保持纯 DOM + `sc-*`；零依赖红线）
- 不做"仪表盘墙"（新增可视化仅当承载**决策**：如容量水位、判据对账）
- 不做主题/皮肤系统、不做国际化（当前单用户中文）
- 不新增常驻注入点（判据/认知环视图走**按需端点**，守 `[lesson] 注入重复计费`）
- 不自动重启插件/宿主（重载交用户点，守红线）

## 9. 排版与布局（第三轴 · 逐板块）

### 9.1 外部排版知识（可执行 8 条）

来源：[Spacing Scales Explained · 8pt Grids and Tokens](https://alltools.dev/reference/design/spacing-scales-explained/) · [Design Tokens Beyond Color: Typography and Spacing](https://alexmayhew.dev/blog/design-tokens-comprehensive) · [Atlassian Spacing foundation](https://atlassian.design/foundations/spacing) · [Visual Hierarchy 6 principles (2026)](https://roundcut.app/blog/visual-hierarchy-ux-6-design-principles-2026-tested) · [10 Techniques to Improve Visual Hierarchy](https://www.parallelhq.com/blog/what-can-be-used-to-improve-visual-hierarchy) · [W3C WCAG #1945（cards/dashboards 非文本对比）](https://github.com/w3c/wcag/issues/1945)

| # | 规则 | 对我们的含义 |
|---|---|---|
| S1 | **4px 基准 + 8pt 节奏**：间距只能取 4/8/12/16/24/32/48 | 现 6/10/26/34/42/290 等裸值 → 全部归一到标尺 |
| S2 | **间距令牌化**（primitive → padding/gap 语义层） | 补 `--sc-sp-1..6` 与语义 `--sc-gap-row/--sc-pad-card/--sc-gap-group` |
| S3 | **字号模数 + 行高**：正文字号 ≥13px（中文 ≥14px 更稳），行高 1.5–1.7；标题 1.25 模数 | 现 11/11.5px 小字（状态栏/YAML/mono）需 ≥12，正文 13–14 |
| S4 | **层级靠 3 件事**：尺寸/字重、颜色对比、**留白**——不是靠加边框与阴影 | 现 `.sc-h1`19px + 组标题 + 小标题三级无统一标尺；卡片类过多 |
| S5 | **留白即分组**（Gestalt 邻近原则）：组内 4–8，组间 16–24 | 现组间/组内间距混用同一档（6/10/12）→ 层次读不出来 |
| S6 | 明暗对比：正文 ≥4.5:1，非文本（图标/边框/状态点）≥3:1 | 我们的 `--sc-faint:#666` 在 `#1e1e1e` 上约 3.1:1（仅够非文本，不可用于正文） |
| S7 | 行宽上限（可读性）：正文 ≤ ~72ch；窄栏用 `max-width` 而非硬 width | 现 `max-width:290px`（persona）/`min-width:220px`（range）混用 → 统一「控件列宽」语义 |
| S8 | 密度分档：同一面板只允许**一种行高基线**（紧凑 32 / 常规 40） | 现 setting-item 与 badge/stat 卡行高不一 → 统一两种 |

### 9.3 目标标尺（写进 CSS 顶部的令牌块）

```css
/* 间距（4px 基准/8pt 节奏） */
--sc-sp-1:4px; --sc-sp-2:8px; --sc-sp-3:12px; --sc-sp-4:16px; --sc-sp-5:24px; --sc-sp-6:32px;
/* 语义 */
--sc-gap-row:8px;        /* 行内元素间 */
--sc-gap-item:var(--sc-sp-3);   /* 列表项之间 */
--sc-gap-group:var(--sc-sp-5);  /* 分组之间（留白即分组，S5） */
--sc-pad-card:10px 12px; --sc-pad-section:var(--sc-sp-4) var(--sc-sp-5);
/* 字号（模数 1.2；中文正文 ≥13） */
--sc-fs-xs:12px; --sc-fs-sm:13px; --sc-fs-md:14px; --sc-fs-lg:16px; --sc-fs-xl:19px;
--sc-lh-tight:1.35; --sc-lh-normal:1.55; --sc-lh-loose:1.7;
/* 圆角/边框 */
--sc-r-sm:6px; --sc-r-md:8px; --sc-r-lg:12px; --sc-r-pill:999px;
/* 控件列宽（S7：统一语义，不再各自 max-width） */
--sc-w-control:280px; --sc-w-read:72ch;
```
**层级策略（S4）**：一级=页面标题（`--sc-fs-xl` + 600）· 二级=组标题（`--sc-fs-sm` + 600 + `--sc-gap-group` 上留白 + **可选 1px 顶边**）· 三级=行标签（`--sc-fs-md`）。**阴影只用于模态层**，内容区一律「背景层 + 1px 边框」。

### 9.5 落地与验收

- **批次**：并入 §6 —— 新增 **U2.5「排版标尺」**（令牌化 + 三原语统一；不动信息结构，可与 U2 并行）：① 令牌块落地 ② 裸 px/内联样式替换（**按板块逐个替换**，每板块独立可回滚）③ 字号/圆角/间距归一 ④ focus 环 + 双编码状态。
- **验收（可测）**：
 1. CSS 中**除 `1px` 边框/图标外无裸 px**（可用脚本 `grep -o '[0-9]\+px' client.js | sort -u` 复核）；
 2. 间距值**全为 4 的倍数**且只取标尺 6 档；
 3. 字号只取 `--sc-fs-*` 五档；正文 ≥13px；
 4. 每板块**层级 ≤2 级标题**（页面级 + 组级），行标签不再单独占标题位；
 5. 组间/组内间距比 ≥ **2:1**（留白即分组可量化）；
 6. 正文对比度 ≥4.5:1、非文本 ≥3:1（`--sc-faint` 降级为「仅非文本」用途）；
 7. 每个控件有 `:focus-visible`；键盘可达率 100%。
