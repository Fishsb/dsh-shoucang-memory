# ADR-0002：蒸馏固化归属守藏——完整蒸馏通道自记忆插件迁入（suite 单一蒸馏器 + 动态目标路由）

> 状态：superseded（2026-09-07 守藏退役归档 ADR-0003：蒸馏器随插件下线，本决策转历史）

## 背景

用户拍板的 suite 产品原则：**守藏必须安装，成员插件依赖守藏；守藏 + 任意一个成员插件即可完成自循环**（用户原话「其他插件自身只要安装守藏就可以达成自身功能完整」）。

现网缺陷：蒸馏固化链路（事件 watcher 触发 + spawn LLM 子代理裁决）整体在记忆插件（dsh-managing-memory，ADR-0003/0004/0005）。**守藏 + pmg 组合（无记忆插件）无法完成知识积累**——候选无人生产，devref-card 写门空转。此缺陷直接违背上述产品原则。

原 shoucang F-002「蒸馏唯一权归记忆插件 watcher、守藏禁止恢复蒸馏链路」与本方向冲突，经用户拍板 **superseded**（方案 A「守藏机械兜底、记忆在场即让位」与 C「维持现状」均被否，选 B 完整搬迁）。

## 决策

1. **单一活跃蒸馏器 = 守藏，永久唯一权**：蒸馏执行权（触发 watcher + LLM 子代理裁决 + distill-contract 路由）整体迁入守藏 scheduler；记忆插件退位为「知识库承载 + 引擎供应商」（库纪律 append/write_gate/read_section/health 与机械引擎 archive-lib/check/candidate_grep 留仓不动）。
2. **机械引擎零拷贝复用**：候选发现/信号召回不搬代码，守藏经注册表路径直接 node 调用记忆仓 scripts（单一事实源，守成员零拷贝注册制）。
3. **双库定位与板块（用户拍板 2026-09-06）**：
   - **记忆插件库 = 泛用元记忆**：用户画像（USER/AGENT）、跨项目通用经验/教训/工作流（三索引 + notes 七类）——非项目绑定知识。
   - **pmg 卡库 = 项目知识库，分两板块**：① **项目板块**——绑定被治理项目的开发知识（对齐现有 docs/devref/cards 三卡册 how-to/reference/decision，按项目归属）；② **通用板块**——跨项目通用规则/资料文档（如 DSH 插件开发规范、工具用法资料），不绑定单一项目。
4. **白名单门禁（双端，用户拍板 2026-09-06）**：各库自带**白名单配置**（记忆插件 config 定义记忆库收什么、pmg config 定义卡库两板块各收什么）；守藏蒸馏器只读消费——蒸馏产出先判归属（R0 路由 + 库内板块判断），再过**目标库白名单校验，不符合不存**（拒收不回退他库，写审计日志供抽查）。白名单是各库自治边界，守藏不代写不代改。
5. **R0 目标动态路由**（按装配解析，解析失败沿降级链回退）：
   - memory 目标：记忆插件库（三索引+notes）→ 守藏本地知识区
   - project 目标：pmg devref-card（项目板块/通用板块）→ 守藏本地待办区
   - 白名单校验在目标解析**之后**执行（先定库再验单）；守藏本地三索引沿用记忆库同款白名单口径。
6. **守藏本地知识区 = 与记忆库同构的轻量三索引**（MEMORY/USER/AGENT + notes）：**位置在 `$DSH_HOME` 数据目录**（运行时探测，零硬编码；私人数据不入守藏公开仓，沿 ADR-0006 结构分离精神）；维护工具（write_gate/health/read_section）零拷贝复用记忆仓 scripts——`MEMORY_ROOT` 指向守藏数据目录跑同一套脚本（ADR-0006 数据根外置的直接收益）；记忆插件日后安装可整体并入（迁移工具对齐 devref-card/migrationHint 模式）。
7. **蒸馏配置归守藏 config**（suite 节扩展 distill: 成员）：空闲唤醒时长（缺省 10 分钟，承接原记忆仓 F-001）、子代理模型（缺省跟随会话，承接原 F-002）。
8. **守藏 UI 信息同步（读时拉取）**：panel 数据源改为动态探测（守藏本地知识区 ∪ 记忆库，按装配；替换现读死的 `~/.dsh/skills/managing-memory/`）；蒸馏固化后用户打开/刷新面板即见最新数据；新增蒸馏统计卡（最近蒸馏时刻 + 产出/拒收计数，对接审计日志）。不做 host→client 实时推送（复杂度高收益低）。
9. **验收场景 = 组合矩阵**（守止单装不承诺，机械上顺带可用）：守藏+记忆＝泛用元记忆循环；守藏+pmg＝项目治理+知识库循环（项目+通用两板块）；三者全装＝全功能（现网形态）。
10. **切换节奏 = 单飞**：先关记忆插件 watcher 再启守藏 watcher，无双写窗口、无去重逻辑；切换点选在守藏侧目标路由与 LLM 通道验证通过之后；会话记录不丢，空窗期候选由下次触发照常捞回。

### 阶段 0.5 技术查证结论（2026-09-06，5a 规范检索门：DSH 源码 + plugin-dev-guide + 踩坑卡对照）

**可行性：全部绿灯，且修正一处方案误判**——
1. **无需「daemon 形态升级」**（原方案误判）：记忆插件本身就是 external 插件（super-injector 注入），watcher 能力来自 `inject = ['tools','llm','subagents','agents']` + `ctx.on('session/event'|'agent/created'|'agent/disposed'|'session/disposed')`——全部是官方 cordis 契约（注册=effect、卸载自动撤销）。守藏 scheduler 同为 external 插件，**扩 inject 声明即可获得同等能力**。
2. **spawn 子代理契约已验证**（记忆插件生产代码）：`ctx.subagents.start('spawn', { parent: 活agent实例(ctx.agents.get), maxDepth: 1, agentOptions: {provider, model}, persona, toolFilter: {allow:[]} })`；provider 校验经 `ctx.llm.listProviders()`。
3. **迁移单元清单**（记忆插件 index.ts 中蒸馏机器 ≈260 行整体迁 scheduler）：事件订阅 4 钩子 + idleTimers 状态机 + extractDelta（snapshotEvents 水位增量，含 block-end 文本展开）+ distillPrescan（信号词零 LLM 预筛）+ spawn/JSON 解析 + 写入分发（memory-append / knowledge-append --project-card / R2 pending 回退）+ watermark 水位文件。
4. **坑位防御照抄清单**（源=devref/pitfalls）：禁 spawnSync 全异步 runAsync；定时器随 ctx 生命周期（agent/disposed 清理）；reload 后旧 ctx 失效→错误 catch+水位保留重试；maxDepth=1+persona 委派禁令+toolFilter；路由归一化未知回退 memory（宁滥勿丢）；**待补强**：LLM 路由钉死传染防护（连败≥2 弃用捕获路由）现实现仅有启动期警告，迁移时补全。
5. **新查证点（阶段 1 执行）**：白名单跨读机制——蒸馏器读记忆插件/pmg 的白名单配置，候选项：a) `ctx.settings` 服务跨插件读（需查契约）；b) 白名单文件放各库数据目录（如 knowledge/whitelist.json，库自治维护、蒸馏器读文件，松耦合且守藏本地知识区同款适用）。倾向 b，阶段 1 定稿。
6. **数据文件迁移**：watermark + pending 候选（arb-*.md）+ 审计日志 → 守藏数据目录（`$DSH_HOME/suite/distill/` 与 `suite/knowledge/`，运行时探测零硬编码）；切换时记忆仓存量 pending 积压整体移交消化（格式同源零改造）。

## 后果

- 正面：产品原则达成——装守藏即得完整知识循环，成员按需组合；单一蒸馏器无双写风险；机械引擎零拷贝不分裂；配置随能力走（归守藏）。
- 副作用/成本：记忆插件失去执行者角色（指挥者语义由守藏承接，宪章需修订）；切换期蒸馏短暂停摆（单飞空窗，分钟级）；守藏本地三索引与记忆库并存期需要迁移工具收口；记忆仓 ADR-0003/0004/0005 的执行层语义部分由守藏承接（文档需加移交指针）。
- 风险缓解：单飞切换点前置验证（阶段 2 全场景过才切）；候选队列格式同源，积压移交零改造；所有治理变更过 pre-commit 门禁。

## 替代方案

- **方案 A 分层兜底**（守藏机械候选兜底、记忆在场即让位、LLM 裁决仍归记忆插件）：改动最小，但「守藏+pmg 组合固化不完整」依旧（仅积累不固化），不满足用户拍板的产品原则——弃。
- **方案 C 维持现状**：缺陷原样保留——弃。
- **双轨并行切换**（新旧 watcher 并行观察期）：需新增去重标记逻辑，复杂度与风险高于分钟级空窗损失——弃（选单飞）。
