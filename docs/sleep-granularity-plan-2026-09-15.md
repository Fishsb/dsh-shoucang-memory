## 3. 现状实测：粒度阶梯已存在，但**中间层缺失 + 跨粒度冗余**

### 3.1 阶梯现状【实测 2026-09-15】

| 级 | 载体 | 体量 | 谁读 |
|---|---|---|---|
| L2 正文（细） | `notes/*.md` | **119,126 B** / 8 文件 | 按指针 get_file 读 |
| L1 索引（中） | `MEMORY.md` 46 行 · `AGENT.md` 67 行 · `USER.md` 4 行 | **21,716 B** | 供给装配 |
| L0 注入（粗） | 恒定面 + 动态面 + 情境面 | **2,391–2,977 字符/步** | 每步必进 |

**阶梯是存在的**（119 KB → 21.7 KB → ~2.8 K 字符）。问题不在"没有阶梯"，而在下面两点。

### 3.2 缺口一：中间粒度层缺失（正文与索引之间是**二值跳变**）

现在的粒度只有两端：**正文（几 KB/节）** 与 **索引行概况（≤30 字）**。
中间没有"精要层"——模型按指针读详情时，拿到的是**全量流水正文**，不是"该节精要"。
⇒ **母命题"太详细反而干扰模型能力"，在"按需读详情"这条路径上完全成立，且当前无处可施。**

### 3.3 缺口二：跨粒度冗余（最硬的证据）

`AGENT.md`【读码 + 实测】同时存在三种形态：

| 形态 | 例 | 粒度 |
|---|---|---|
| 索引行 | **一条 `[原则]` 索引行**（正文已脱敏；形态 = 「标签 · 主题 · 概况 → 指针」，此处 `→ notes/flows.md §全局工程纪律/§记忆体系分工`）（L18） | 最粗 |
| 画像行 | **一条 `- [原则]` 画像行**（正文已脱敏；形态 = 「`- [标签] 主题 · 概况 ← 源: distill <id>`」，此处 `← 源: distill <hash>`）（L15） | 中 |
| **完整叙事行** | **一条无标签叙事行**（正文已脱敏；形态 = 「散句 + 所在小节」，此处位于 `## 常犯错误-越界`）（L20） | **细** |

**L18 与 L20 是同一条教训的两个粒度版本；L23 与 L47 同理。而两者都进注入面**【活体】——
本会话注入的 agent 画像段里，粗形态（`- [原则] … → notes/…`）与细形态（`- 曾据单次实测断言 git 被墙…`、`- 先定谁何时读什么…`）
**同时在场**。

⇒ **结论：现有睡眠只做了"加粗"（新增粗粒度索引行），没做"收细"（回收与粗粒度语义同源的细粒度行）。**
这是零风险的压缩面——**比注册表声称的 302 字符大得多**（叙事行合计 ≈ 600–700 字符 · 【判读】待精确统计，见验收 AC-2.1）。

> ⚠ **口径待统一（必须先解决）**：三处计数互不一致——
> 本文实测 `AGENT.md` = **18 条 `[原则]` + 6 条 `[路径]`**；`criteria.json:458` 写「**18 条**互不重复」；
> `master-architecture-plan §2.1`（2026-09-14）写「17 指针 + 15 画像」。
> **任何粒度压缩都必须先把"什么叫一条"这个口径定死**，否则会重演 OPEN-ITEMS §5「登记口径不清 ⇒ 表自我繁殖」的坑。

### 3.4 缺口三：触发是单维时间，材料无上限

## 4. 目标架构：把"粒度阶梯"变成睡眠的显式产出

### 4.1 粒度阶梯五级（目标态）

```
L3 认知/性格   ← 最粗：人格与思维模式（P 层，always 注入）
L2 原则/路径   ← 方向与可执行路径（索引行 + 画像行）
─────────────── 以上进注入面（预算 4000 字符，实测每步 ~2.8K）
L1 精要         ← 【新增】每节的中等粒度重述（"该节说了什么"）
L0 正文/沿革    ← 细：全量事实、步骤、参数（按指针读；原版留沿革可回溯）

── 以上为**投影层**（全部可重构） ──
S  脚手架       ← 转录 / audit/*.jsonl / ring-events.jsonl / records.jsonl
                  **不是"层"，是投入品**：未自足时必须可回源；**自足后可弃**
                  （**可弃 · 不可语义改写** —— 见 §4.3）
```

**关键：L1「精要」是本次唯一新增的粒度级**，它同时服务两个目标：
① 按需读详情时给模型的是精要而非流水（母命题的直接实现）；
② 精要是 L2 原则的**可核验素材**（原则必须能从精要推出，而不是从 400 行流水里"感觉"出来）。

### 4.2 睡眠的五个动作（对应文献机制）

| 动作 | 文献 | 现状 | 本次 |
|---|---|---|---|
| **选择**（哪些进本轮） | L5 need/gain 优先级 | 🟡 活性/冷度 | 加**内容水位 + 预算配额**（R0） |
| **压缩**（细 → 精要） | L3 图式抽象 | ❌ 无通道 | **新增 L1 精要层**（R2-B） |
| **收敛**（跨粒度去冗） | L1/L4 图式对齐 | ❌ 只加粗不收细 | **跨粒度收敛**（R2-A） |
| **释放脚手架**（自足 ⇒ 弃源） | L6 再巩固 / L9 自足边界 | ❌ 无概念 | **自足性判定 + 冷归档**（R2-C，§4.3） |
| **降权**（冷/噪声） | L7 SHY | 🟡 仅冷度归档 | 后续（本册不含） |

> 「释放脚手架」是本轮新增的第五个动作，也是**唯一能让库真正停止膨胀**的动作 ——
> 前四个都只是在**重排**既有内容，只有它**减少**资产的依赖面。

### 4.3 资产生命周期：细节 → 提炼 → 自足 → 弃脚手架（**本轮修正 · v3**）

> **两次修正的由来**
> - v1 主张"程序性/事实通道不参与压缩"（依据 AWM +51.1%）→ **用户 2026-09-15 推翻**：库的所有信息都可重构。
> - v2 主张"源层不可变、只追加"→ **用户再次推翻**：*"源层就是一个记录，是可以丢弃的；细节丢失了，人就没有认知、没有记忆了吗？"*
>
> **v2 错在哪**：我把"源层"当成了**永久层**，于是库永远欠源 ⇒ 压缩永远不彻底，且磁盘单调增长（与用户"在意磁盘"直接冲突）。
> 正确的模型是：**源层不是"层"，是流水线的投入品（脚手架）。**

**新模型：单向流，不是固定分层**

```
细节（源） ──蒸馏/睡眠提炼──► 投影（认知/经验/原则/路径）
   │                                    │
   │                                    ├─ 未自足 ⇒ 脚手架必须保留（可回源校正）
   └──── 提炼完成且被验证 ──────────────►└─ 已自足 ⇒ **脚手架可弃**（认知独立成立）
```

⇒ **判据**（直接来自用户的反问）：**认知必须自足。**
若一条投影条目**必须靠回源才能成立**，那它不是认知，而是**索引**（指针的另一种形态）。

**自足性判定（机检，不得自述）**

| 状态 | 条件 | 源层处置 |
|---|---|---|
| **未自足** | 消费验证次数 < N，**或**出现 ≥1 反例 | ❌ **必须保留**可解析回源路径；回源不可达 ⇒ 该条**冻结**（只能归档，不能改写） |
| **已自足** | 消费验证 ≥ N 次 **且** 0 反例 | ✅ **脚手架可弃**（默认形态 = **归档冷存 / 无损编码压缩**） |
| **再巩固触发** | 消费时出现**反例** | ⚠ 该条退回**未自足** ⇒ 需要回源校正（此时丢源 = 永久失去校正机会） |

- 消费次数与反例数**都从既有审计/环记录算出**，**不由 LLM 声明**（防"自述自足"）。
- N 与判定口径进 §8 预注册表，用真实数据校准（同 OPEN-1 的预注册做法）。

**源层唯一硬约束（修正后）**

> **可弃，但不可语义改写。**
> 理由：语义改写会**污染唯一的校正基准** —— 保留一个已被自身偏见污染的"源"，**比没有源更危险**
> （你会以为它有权威性）。⇒ 只允许**无损编码压缩 / 冷归档**，不允许摘要化改写。

**依据**：【文献】L8 —— gist 化**同时制造过度泛化与虚假记忆**；脚手架期"可回源"是唯一能**事后发现**它的机制，
而自足期之后不再需要它。**L9（contextual binding theory）给出边界条件**：并非所有表征都变得自足，
故必须有"自足性"这个可判定的中间态，而不是一刀切。

⇒ 于是"要不要压细节"从**价值争论**变成**可证伪实验**（§8 预注册断言 A/B/C）。

**粒度终点表（修正版）**

| 通道 | 粒度终点（建议，非禁令） | 说明 |
|---|---|---|
| 陈述性/语义 | 方向（L2→L3） | 母命题直接成立 |
| 程序性 `[路径]` | **原则上可压到"步骤轮廓"** | ⚠ AWM +51.1% 的反证**降级为断言 A**：若压后任务成功率下降 ⇒ 该项回滚 |
| 事实 `fact` | **原则上可压** | 需要精确值时必须**回源**（审计/配置/转录）取回 |
| 承诺 / 决策 / 价态 | **状态**（谁欠谁 / 到期 / 在什么情境下好或坏）必须由**结构化记录**承载 | 到期提醒是中层的 **cue 驱动判据**，**不得依赖会被压缩掉的 md 叙述** |

## 5. R0 · 睡眠纪元与双维水位

**定义**：**睡眠纪元（`sleepEpoch`）** = 上一次睡眠成功 → 本次睡眠成功之间的区间。
它**既是触发单位，也是度量单位**（R1 以它为样本）。

| 项 | 设计 | 与现状的关系 |
|---|---|---|
| 纪元 id | `epoch-<单调序号>-<起时刻>`，写入全部纪元日志与审计 | 新增（命名避开已占用的 `epoch`） |
| 时间水位 | 沿用 `lastDeepSleepAt` + 双证，**done 才推 / failed 回滚** | ✅ 已有，不变 |
| **内容水位（新增）** | 材料累积量（字符 / 条数 / 工具事件数）达阈值 → **可睡**（OR 关系，与时间维并列） | 新增；`newTracesMin` 仍是**下限** |
| **材料上限 + 分片（新增）** | 超上限 → 切 N 片，**片间共享 epoch id**，每片一次 pass，**水位按片推进** | **复刻蒸馏侧已解决的机制**：`src/distill-chunks.ts` + `chunk/chunkStart/chunkEnd/totalChunks` 标记（`src/distill-agent.ts:242` v18 注释） |
| 可观测 | 面板显示：当前纪元起止 / 材料量 / 预计分片数 / 完成片数 | 复用既有 `/deepsleep` 路由 |

## 7. R2 · 跨粒度收敛（存量重构的真正形式）

**这是对 §3.3 缺口的正面施工**，也是母命题"压缩粒度"的**正确落点**。

### 7.1 两个动作

| 动作 | 内容 | 为什么可回滚 |

- **可回源硬门（本轮新增·唯一红线）**：每条重构后必须仍有一条**可解析的回源路径**；回源不可达 ⇒ 该条冻结（§4.3）。

## 8. R1 · 有效性度量：固定预算下的"有效方向数"

**为什么必须是这一条**：现有判据只保证**不丢料**（`deepSleepLanded` / 水位回滚 / 门禁），**没有"睡得有没有用"**。

**目标函数（可量化、可由既有数据算出）**

> **在固定注入预算下，最大化被覆盖的「有效方向数」。**

- **预算**：`injection.budgetChars=4000`（【注册表】`:457`），实测每步 2,391–2,977 字符（`:458`）。
- **有效方向数**的代理（三者都可从既有审计/环记录算）：
  1. 互不重复的**方向条目数**（现在 87% 预算给习得原则 ⇒ 分母就是它）；
  2. **平均支持度**：一条方向被多少条真实痕迹支撑（`← 源:` / `distill <id>` 可回溯）+ 被多少个**不同工作区/会话**消费；
  3. **误注入率**：注入后被证明不适用/被 replace 的比例。
- **样本单位 = 纪元**（R0）⇒ "这一纪元睡完，下一纪元的命中率/误注入率/同问题步数有无改善"。

**与粒度压缩的关系（母命题的定量化）**：
粒度越粗 ⇒ 单位预算覆盖的方向越多 ⇒ **有效方向数上升**；
但 §7.2 的判据封住了退路（不能靠删内容换数字）⇒ 唯一通路就是**跨粒度收敛 + 精要层**。
