# audit-protocol.md — 审计协议（周期审计与归档人工裁决）

> SKILL §10 触发后的完整 SOP。触发：容量 >85% / 任务收尾 / 新会话补查。维护走 spec §7 变更机制。

## §1 触发条件与频率边界

- **触发**：主文档容量 >85%（health 实测）/ 任务收尾（SKILL §10 收尾判定）/ 新会话补查（上一任务已完成时）。
- **频率边界**：非每 turn 收尾——"一次指令→多轮工具→最终交付"的大循环结束才算；纯咨询例外可轻量（task-protocols §4）。

## §2 审计主流程

`node scripts\memory_health_check.mjs [--out audit\<日期>.md]`（完整报告归档 `audit\`）→ 逐条**实际读取索引与详情原文** → 过「R0 领域路由 + Q0 归属 + 职责门 + Q1」→ 处置（保留/合并/删除/迁移项目卡库）→ 表格报告（`条目|归属|职责门|Q1|处置|理由`）→ CHANGELOG 留痕 → 复检 exit 0。

**route=project 候选迁移（审计处置项；调度权归守藏，协作宪章 v2/ADR-0007）**（⛔ 2026-09-07 随记忆栈退役终止，ADR-0003——守藏调度与蒸馏均下线，本节转历史流程留档）：记忆侧审计**负责发现积压**——检查各项目 `docs/devref/pending/` 积压（≥3 张或 >24h），提示宿主 agent 执行迁移（发现积压后由守藏调度中枢认领，pmg devref-card 执行）：目标项目 `node <pmg-skill>/scripts/devref-card.mjs <项目> --init`（首次）→ 卡内容按 cardType 转入对应卡册（`devref-card.mjs <项目> --title … --card-type … --text … --source "迁移:pending/<原文件>"`）→ 原候选移 `pending\.processed\`。蒸馏宿主（守藏蒸馏器）已在蒸馏时经 workspace 反解直写项目 pending（E3 桥）+ migrationHint 调度提示（协作宪章），此处只处理降级/回退残留与积压清扫。

## §3 重组 7 步（维护 SOP）

读全 → **提纯降级**（原「删过时」，SOP 见下）→ 删重复 → 合并同类 → 拆分过杂（>100 行或 >80% 容量）→ 按日期重排 → 更新索引/INDEX → 汇总变更。

**提纯降级 SOP（2026-09-08 用户拍板：人脑遗忘≠删除，是下放到更低记忆板块并提取通用经验）**：
1. **触发**：降级判据命中（§5：连续 2 次审计 access.log 零命中 且 类别非 env/release）或容量 >85% 需腾位；
2. **提纯**：从该 notes 小节提取「下次类似任务的方向指引」（教程式三段：目标/步骤轮廓/注意，对齐 R1 粒度锚与 distill-contract v3.1 格式）→ 合并进索引行概况或更通用小节；
3. **降级**：细节原文移 `audit/archive/` 归档层（不进注入面、可追溯），索引行收窄或合并；
4. **兜底**：提纯后确认无通用价值才删，且走 §7 人工裁决队列，不静默删。
- 工具支撑：`memory_health_check.mjs` 候选统计段输出**零召回清单**（对照 notes 小节 ↔ access.log 命中），提纯对象从清单起步。

## §4 固化核对清单（五处同步，必核）

候选固化入册时逐项核对：① 索引行已写（`[tag] 主题 · 概况 → …§小节`）② **概况与对应小节要点一致（含内容更新后概况未失真抽查）** ③ `notes/INDEX.md` 条目元数据表已登记（创建/溯源行）④ notes 小节已建/已并入 ⑤ CHANGELOG 留痕——五处缺一即补；health 的「元数据表覆盖」「指针/注册」检查为机器兜底。

## §5 反思闭环与生命周期

- 任务收尾坑点/新事实 → `pending\` → 审计分流固化（环境→lessons，agent 学习→agent.md §学习史；**R3 项目专属→蒸馏器直写项目工作区 docs/devref/shoucang/**，2026-09-08 单库化——pmg 卡库已移除，不再有卡库迁移通道）。
- **主题提升判据**（机械化）：单子文档 >80% 容量，或近 5 次审计中检索命中（access.log 统计）/审计条目 ≥3 次 → 评估提升为独立 skill → 主索引条目退化为纯指针，正文不再常驻本库。
- **主题降级判据（提纯方向，与提升构成双向生命周期；2026-09-08）**：连续 2 次审计 access.log 零命中 且 类别非 env/release → 进 §3 提纯降级流程——细节下放归档层，通用经验提纯留存支撑未来任务（**每一次任务执行就是一次提纯总结**，巩固与遗忘共用同一动作）。
- **深度睡眠归纳 pass（L0 原则层唯一写入口；2026-09-08，睡眠=回想巩固当天的记忆）**：**宿主自动触发**（守藏蒸馏器 10min 巡检：全部任务会话停滞 ≥3 小时 → 自动执行一次，每轮停滞窗口至多一次；审计轮可手工兜底同一 pass）。
  停滞判定=**会话活跃状态机**（不靠单点时间戳）：任意事件→RUNNING，turn/end(completed)→ENDED；RUNNING 无事件 ≥3h → PROBING（**多轮采样**转录文件比对 mtime/size）→ 输出增长=**正常长任务**（刷新水位，不睡）/ 无增长且会话在=**SUSPECT→STALLED 疑似卡住**（不阻塞睡眠，发审计告警需人工确认）/ 无增长且会话已消失=**EXIT 异常退出**（计入停滞）/ 探针不可用或探测异常=无法确认，**按停滞处理→正常睡**。**只有确认「长线任务正在推进」才拦住睡眠**（用户拍板口径 2026-09-08）；停滞计时一律沿用最后事件时刻，不刷新成当前时间（否则永远睡不着）。
  **防误判加固（2026-09-08，避免单次采样错判误睡长任务）**：① 每轮 `samples`（默认 3）次采样，任一次检出增长即判长任务；② 多信号交叉（转录增长 + 事件心跳 + agent 存活 + agent 状态），**状态活跃但无输出增长=证据冲突**→转 SUSPECT 复核而非直接判卡住；③ 判卡住需**连续 `confirm`（默认 2）轮**确认，首轮落 SUSPECT（**阻塞睡眠**待下轮巡检复核）；④ 探针不可用/异常**重试 `retries`（默认 2）次**仍失败才落定；⑤ 单轮总时长 `maxMs` 兜底防悬挂；⑥ 探测期间来新事件立即中止并回 RUNNING（卡住的会话可复活）
  1. **作用域=当天痕迹**：本日新增 pending + 本日蒸馏 appends 写入的 notes 增量 + 本日 access.log 命中主题（**不做全库扫描**，全库重组仍归周期审计）；
  2. **归纳**：同主题 ≥3 条或单主题当日反复命中 → 提炼 1 条跨任务泛化原则（一句，对齐 R1 粒度锚），带源指针 `← notes/<file>.md §A/§B`；
  3. **落盘**：经 write_gate 写入 `PRINCIPLES.md`（spec §5.8，≤1,000 硬限，超限=原则间合并）；原小节保留作证据，不迁移不删除；
  4. **修正（再巩固）**：新经验与既有原则冲突时原地 replace（同一入口、同一门禁）。
  5. **双画像巩固（2026-09-08 v15，助理的自我认知）**：同一 pass 同步输出 `profileOps`——用户跨任务稳定偏好/背景/禁忌 → `USER.md`（用户画像，库中唯一直接关于「人」的文件）；agent 自身稳定做法/能力边界/常犯错误教训 → `AGENT.md`（agent 自我画像；库中其余 notes/原则/索引皆为 agent 为履行助理职责积累的自身资产）。每条须带 notes 源指针，与原则同红线（项目专名/路径不上提）；宿主直写，门禁同蒸馏 profiles。

## §6 完整性自检与恢复

health 覆盖：缺失(4)/重复(3)/指针·格式(5)/超限(2)。异常 → 按重组 7 步修复；局部损坏用 `dist\`/CHANGELOG 复原；无法自愈 → 保留现场如实上报（零容忍）。

## §7 归档人工裁决入口（可选）

`archive-timer --pending-list` 取队列 → `archive-check <sid>` 查看 → 四裁决（ADD/NOOP/MERGE/SUPERSEDE）→ `archive-mark --done` → `--dequeue <sid>` 清队；或直接编辑 pending 候选。
蒸馏链路协议（触发/预筛/契约/安全阀）事实源 → `engine/distill-contract.md`；兜底 CLI（--due/--drain/--status 等）已注册为 DSH 原生工具（`_dsh_external_dsh_managing_memory_*`），语义见工具描述。

## §8 第一性原理闭环核验（审计增问，ADR-0005 配套）

每轮审计必答三问：
1. **本期是否有 ≥2 次同类问题？** 核验方式：`grep -l "同类:" pending\*.md` + candidate_grep 召回对照——同一 `同类: <主题>` 出现 ≥2 次 → 对应根本解（ADR/机制/契约变更）是否已落地？未落地 → 升级为审计处置项（同门禁效力）。
2. **现有规则/门禁是否被绕过 ≥1 次？** 有 → §0 反思规则本身是否缺陷（规则失效≠违规者的错）→ 提出规则修订候选。
3. **route 分流质量抽验**：grep 插件日志 `route=` 统计 memory/project/discard 分布与 projectCards 落点成功率；R1/R2 误判嫌疑（如 memory 路由连出空数组）→ 复核 distill-contract 判定锚。

核验结果写入审计报告（audit\<日期>.md）尾部。
