## §0 第一性原理反思流程（完整版；SKILL L1 §0 为注入面压缩版）

**触发**：任何问题——报错、走不通、异常、同类问题反复、方案分歧、审查发现异常。

**判定流程（三问）**：
1. **症状还是缺陷？** 同类问题已出现 ≥2 次 = 设计/机制缺陷（孤立症状只修一次）；首次出现也可能是缺陷征兆（先判断属于哪层）。
2. **缺陷在哪一层？**
   - 方案路线错 → 全局重审目标与路线（是否整个方向就错了）
   - 机制缺失 → 是否该建机制/门禁/自动化（而非每次人工救火）
   - 知识缺失 → 本地知识库（记忆 notes / docs/devref / engine 契约 / docs/map）→ 检索网络（web_search / platform_search 开源项目实况与成熟解）
   - 惯性误判 → 默认姿势在主导（如"顺手打补丁""照搬旧结论"）→ 强制换路径
3. **根本解在哪？** 选项按成本升序：检索成熟解 → 补建机制 → 重审方案路线 → 推翻重来 → 升级用户拍板（涉及方向/事实变更时）。

**禁止惯性打补丁**：同类问题第 2 次出现时**禁止再打补丁**，必须走根本解流程。

**信息来源顺序**：本地知识库 → 网络检索（开源项目/官方文档实况）→ 实验验证 → 用户拍板。

**产出沉淀（反思不丢）**：
- 查明为架构/机制缺陷 → 记 ADR（治理项目）或候选沉淀 pending（规则级）
- 症状修复 → 踩坑当天落 pending（对齐 SKILL 踩坑即时沉淀纪律）
- **计数载体（供审计 §8 机械化核验）**：候选文件头部加一行 `同类: <主题词>`——同类问题复发时在既有候选行追加主题（不新建文件）；审计时 grep `同类:` 即统计本期复发分布
- 审计闭环核验 → 见 audit-protocol.md §8

## §1 任务类型分流总则

SKILL §3 声明任务类型后按本节流程执行；一任务含多阶段（如先咨询后 build）→ 按阶段切换类型并重新声明。类型不清 → 按 consult 起步（只读安全），询问用户后再切。

| 类型 | 触发动词 | 核心边界 |
|---|---|---|
| build/执行 | 修复/补建/优化/做/继续/落地 | 方案确认门 → 执行 → 交付纪律 → 收尾判定 |
| fix/审查 | 审查/检查/分析/看看/评估/核对 | 只读+结论交付；禁止顺带改文件；发现项写「建议下一步」 |
| consult/咨询 | 整理方案/咨询/问答/第一性原理分析 | 只读；可多轮方案呈现；收尾可轻量或跳过 |
| wrap-up/收尾 | 交付完成/goal 达成/任务收尾 | 触发收尾四步（§5） |

## §2 build/执行 流程

① 只读收集（核对真实状态，依据=文件内容/脚本输出/容量数字）→ ② 方案呈现（目标/步骤/命令/预期/回退）经确认 → ③ 执行（已确认方案内连续步骤按 todo 推进；新增未确认范围须重提；每处门禁实际审查给理由）→ ④ 交付逐条 ✅/❌ 对照 → ⑤ 收尾判定（§5）。
- lib/src 双份维护的项目：改后 typecheck/build + reload 闭环（对齐治理规则 5c）。
- 插件行为改动：过治理三道门（规范检索/场景矩阵/构建验证）。

## §3 fix/审查 流程

只读收集 → 逐项核对（读原文，不凭印象）→ 结论交付：发现项按「现象/根因/依据/建议下一步」四段；**禁止顺带改文件**（即使"顺手就能修"）——修复是新任务走 §2。审查发现异常 → §0 反思（是文档失真还是实现缺陷？）。

## §4 consult/咨询 流程

只读收集 → 结论/方案呈现（可多轮迭代）→ 交付即停。**例外**：纯咨询（单轮事实回答、无可沉淀动作）收尾可轻量或跳过（SKILL §10）。方案经用户确认转 build 时 → 重新声明任务类型。

## §5 wrap-up/收尾 流程

**触发**：交付即停完成 / goal `update_goal complete` / 大循环结束（非每 turn）。

**收尾四步（SKILL §10 注入面为压缩版）**：
1. **候选召回** → `node scripts\candidate_grep.mjs`（信号词扫描本次会话明文记录，纯召回不写库）
2. **R0+四问初筛** → 逐候选实际核对：R0 领域路由（R1 泛用/R2 项目/R3 丢弃）→ 通过者四问 Q0-Q3，注明每项理由；「拿不准」→ §0 反思（边界定义问题还是知识缺失）
3. **落点** → 通过写入 `pending\`（含拟标签与日期；**R2 项目相关带 `[route:project]` 标记**，迁移项目卡库）；拒绝的在交付说明给理由
4. **触点重计时** → `node scripts\archive-mark.mjs <当前会话id> --touch`（防静默误唤醒）

**新会话检查时机**：上一任务已实际完成 → 补触发收尾清单；未完成/中断 → 不触发、不伪造完成，仅轻量 health 兜底。

## §6 委托与并行细则（SKILL §9 注入面 1 行的展开）

- **独立子任务** → `subagent`/`subagent_fork` 默认后台；大批量扇出 → `workflow`；同会话延续 → `subagent_fork`。
- **子代理 prompt 必须完整自足**（子代理不见父会话上下文）；喂上下文 ≠ 让它猜。
- **失败返回 null** → 如实报告不补造；先 §0 反思：prompt 不自足？拆分不合理？环境缺失？——禁止盲目重试同 prompt。
- **子代理不直接写父记忆**：产出由父代理按 R0+四问评估后写入（子代理无记忆写权限语义）。

## §7 工具失败恢复速查（自 SKILL L3 下沉）

- Invoke-WebRequest 报错 → Invoke-RestMethod/curl.exe；pwsh 管道 EPERM → 换 stdio 结构
- read 中文误报 Binary → pwsh 读字节/文件头验证；edit 匹配失败 → read 确认重试；文件被外部改 → 重读无冲突再写
- 版本未核验 → 直连官方 API；换路定位 → grep `notes/` 关键词再 read 片段
