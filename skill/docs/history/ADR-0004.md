# ADR-0004：方案 E：蒸馏触发事件驱动化（session/event watcher 替代轮询扫描）

> 状态：accepted（2026-09-05，用户拍板；spike 实证 session/event 可达）

## 背景

方案 B→C→D 的演化史是补丁循环：轮询扫描架构下陆续打了 9 轮补丁（死锁→阈值→路由传染→日期硬编码→5 层 subagent 过滤→异步 spawn 守卫→spawnSync 冻死根治→递归根治→idleWake 传参）。第一性原理审查发现根源不是 bug 而是架构错位——**用文件系统轮询 + CLI 子进程 + 多套状态机重新发明了 DSH 已原生提供的会话生命周期观测**：

| 本质需求 | DSH 原生能力 | 轮询架构的替代实现（错位） |
|---|---|---|
| 知道"任务停止了" | `session/event` 的 `turn/end`（O(1) 事件） | 每 60s 轮询扫描 348MB 会话树（O(N)，spawnSync 冻死主线程） |
| 知道"会话是谁的" | `agent.session.header.origin`（一个字段） | 转录 zstd 全解压读 header（9.4s/个）+ 5 层过滤防线 |
| 有地方跑蒸馏 | 事件回调天然持有 agent 引用 | spawn 借活 agent 宿主 + 子代理会话回流递归 |
| 记住"蒸馏到哪了" | session event seq | mark JSONL + pending 队列 + state.json 四套状态 |

社区证据：dsh-advisor（每 turn 审查插件）用 `ctx.on('session/event') + agent/created/disposed` 全事件驱动零轮询；dsh-mnemon 用 agent 生命周期绑定（child 永不 review）。规范证据：dsh-plugin-dev 档案（多帧 zstd 契约、scoped cordis、settings 官方契约）。

Spike 实证（2026-09-05）：super-injector 注入插件**实时收到 session/event**（tool/result、step/start、assistant/chunk 全流）；`agents.roots()` adopt 可用；root 会话 header 无 origin（仅 subagent 有 `origin:'subagent'`——天然判据）。

## 决策

1. **触发 = session/event 事件驱动**：`ctx.on('session/event')` 过滤 `turn/end` 且 `reason.kind === 'completed'`；经 agents store 查 header 排除 `origin==='subagent'`（child 永不蒸馏，单行判据替代 5 层过滤）；per-agent idle 定时器（idleWakeMs，F-001 默认 10min）——新 turn/end 重置、到点且 agent 仍 idle 才蒸馏。
2. **生命周期**：`agent/created` 挂 watch + 启动 `agents.roots()` adopt；`agent/disposed`/`session/disposed` 清 timer；全部注册在插件 ctx（effect 自动清理，reload 零泄漏）。
3. **蒸馏输入 = 内存增量**：从 `agent.session.snapshotEvents()` 取上次蒸馏水位之后的 user/message 与 assistant text block-end，零 zstd 解压、零文件扫描。
4. **执行体 = spawn 蒸馏子代理**（保留方案 D 语义；事件架构下无扫描器，子代理回流递归天然消失）：parent=该 root agent；`Promise.race` 10min 超时 + AbortController（消灭互斥卡死）；输出结构化 JSON。
5. **写库 = 引擎 memory-append 安全阀**（不变），调用改**异步 spawn**（runAsync）——插件内消灭全部 spawnSync（冻死问题从机制上根除，含 5 工具链路）。
6. **状态收敛**：蒸馏水位单文件 `audit/distill-watermark.jsonl`（{sessionId,lastSeq,at}）；pending 队列 / distill-queue / state.json 蒸馏字段退役。
7. **退役**：daemon 轮询 tick、discover、pending 队列、plist/runDue 的 subagent 过滤、touch 协议依赖、ticking 守卫。**archive-timer CLI 保留**（无插件环境手动兜底 + 引擎测试）。
8. **规范修正**（dsh-plugin-dev）：package.json peer 改 scoped `@deepseek-ai/cordis`；src type import scoped；zstd 多帧契约在引擎标注；UI 待办按 settings namespace + `settings.plugin.item` 契约实现。

## 后果

- 正面：轮询/过滤/守卫/状态机四类补丁层整体退场（插件 ~260 行→~180 行且无防御性分支）；O(N) 树扫描归零（CPU 与主线程冻结从机制上消失）；会话身份/生命周期由宿主原生保证；F-001/F-002 语义更精确（turn 结束后 idle 计时）。
- 副作用：① 历史冷会话不再自动蒸馏（无事件）——archive-timer --due/--drain 保留手动兜底；② 蒸馏依赖 agent 在 store（宿主常驻保证）；③ turn/end 非 completed（error/max-tokens）不触发——内容可能滞留至下个 completed turn。
- 风险缓解已内建：scope 过滤（spike 已过）、spawn 超时、effect 清理、水位持久化（重启 roots adopt 读回）。

## 替代方案

- 继续轮询架构修补：维护成本指数增长（9 轮补丁实证）——弃。
- 完全移植 mnemon 三层记忆（provider 化存储）：超出需求、迁移成本巨大——弃（仅借鉴其生命周期绑定与 child 排除）。
- agent 会话内工具触发蒸馏：依赖 agent 自觉、漏触发无兜底——弃（事件 watcher 全自动）。
