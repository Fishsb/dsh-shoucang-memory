# ADR-0006：文档树结构分离——私人记忆数据移出公开仓库根（`_memory/` 集中 + MEMORY_ROOT）

> ⚠️ **历史归档：本 ADR 仅记录当时决策背景，不得作为现行依据。** ADR 机制已随项目治理插件 `project-map-governance` 整体移除而停用；本目录已停止维护、不再新增。现行唯一权威为仓库根 `AGENTS.md`，判据的现行事实源为 `skill/engine/criteria.json`。时间线提醒：本文早于 2026-09-08 三位合并为仓根单插件与 2026-09-11 重新上线，读时须结合现状。

> 状态：accepted（2026-09-06 用户拍板执行）

## 背景

本仓库 `Fishsb/dsh-managing-memory` 为开源技能仓，但**同一棵树同时承载两类内容**，靠 `.gitignore` + 推送前人工甄别区分：

1. **可发布**：规则/引擎/流程文档（SKILL.md、memory-whitelist-spec.md、audit-protocol.md、task-protocols.md、engine/、scripts/、docs/map）。
2. **私人数据**：个人记忆 notes/（七类详情+INDEX）、三索引（MEMORY/USER/AGENT.md）、候选 pending/、归档运行产物 audit/——含用户画像与本机路径，**绝不可公开**。

`.gitignore` 虽已排除上述私人目录，但它们**物理上与公开文件同根混放**，任何全树操作（容器同步、测试 cpSync、发布前扫描、未来工具枚举）都会连带触碰私人数据 → 每次发布需逐文件私密扫描审查；测试容器还曾 cpSync 真库造成污染。缺陷层级：**机制缺失**（无结构性隔离，靠人肉审查纪律兜底）。

## DSH 原生能力对照（架构拍板审查门）

| 需求 | DSH 原生能力 | 本决策是复用原生还是自建？为何 |
|---|---|---|
| 文件仓库内容结构分离（公开 vs 私人） | 无原生概念（非 DSH 会话能力；属仓库布局/文件系统层面） | 自建最薄层：目录集中 + gitignore 结构性排除 + 脚本数据根 env 重定向 |

## 决策

1. **私人数据移入 `_memory/` 子目录**（仓库根下，gitignore 排除）：`notes/`、`MEMORY/USER/AGENT.md`、`pending/`、`audit/`（含 .gitkeep 一并迁出索引）。公开树根下不再存在任何个人记忆文件。
2. **治理地图只登记公开树模块**（engine/scripts/docs）；`_memory/` 加入 governance.json `ignore`，check/sync 不扫描；docs/map 的孤儿模块文档（root|tree/notes|pending|audit）清除。
3. **脚本数据根 = `MEMORY_ROOT` 环境变量**，缺省 = 脚本目录上一级（兼容生产技能副本根下 notes/ 布局）。受影响：archive-lib、memory_health_check、memory-append、memory_write_gate、read_section、test.mjs。engine/knowledge-append 经注册表 `<dshHome>` 占位不变。
4. **test.mjs 容器化**：公开树副本 + `_memory/` 数据并入临时容器，容器内调用显式 `MEMORY_ROOT` 指向容器 → 测试不碰真库、无泄漏。
5. **本机拓扑说明**：`docs/map/private.md`（gitignore 不入库，含本机路径供 agent 导航）；公开叙述（README/index）只声明「本仓库不含个人记忆，私人数据不入库」，不带本机路径。
6. **发布免审查**：推送 = 公开树 + 文档，私人数据在 `_memory/` 物理不可达，无需逐文件私密扫描。

## 后果

- 正面：发布/推送结构性免审查；公开树对全树工具透明（测试 cpSync 不再连带私人数据）；开源使用者 clone 只获规则/引擎，无隐私顾虑；地图与真实模块一致（error 门禁 0）。
- 副作用/成本：工作区公开树 ≠ 数据根（不同构），开发/测试须显式 `MEMORY_ROOT` 指向 `_memory/`；生产技能副本（C 盘）数据仍在技能根下，靠脚本缺省兼容——**两套布局长期并存**，规则靠文档同步、数据各自演进。
- 风险缓解：脚本改动纯增量（env 缺省=原行为），C 盘生产不受影响；git mv/rm 全可逆；ADR 记录使未来 agent 不迷路。

## 替代方案

- **保持同根 + gitignore + 发布前审查**：无结构性保证，每次发布人肉甄别（原状）——弃。
- **私人数据移出仓库目录（放 ~/.dsh 或别处）**：隔离最彻底，但本仓库是技能仓，数据与脚本同仓部署才自洽（生产副本=数据+规则一体）；且跨机可移植性差——弃。
- **工作区与生产完全同构分叉（两棵都含数据）**：维护成本高、漂移面大——弃。
- **scripts 数据根硬编码本机 `_memory/` 绝对路径**：把本机路径带进公开仓——弃（选 env 注入）。
