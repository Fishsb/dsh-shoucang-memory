# ADR-0003：方案 D：蒸馏固化收敛为 spawn 蒸馏子代理单通道（空闲时长唤醒判定 + 模型可配）

> 状态：accepted（2026-09-05 落地 + E2E 实证）

## 背景

- 方案 C（ADR-0002 v2）的蒸馏/固化由插件 daemon 内 `ctx.llm.stream()` 直裁 + memory-append 直写，无子代理；存在裁决/固化死锁（已修）、LLM 路由传染、深思考召回缺口等问题，且"执行体在 daemon 内"与用户期望的"唤醒子代理执行"不符。
- 用户方向（2026-09-05 拍板）：① 蒸馏固化收敛为**单一自动通道**（agent 执行中产候选→统一走蒸馏固化）；② 唤醒判定 = **会话任务停止（静默/空闲）满可配置时长**（F-001，默认 10 分钟），非任务结束即唤醒；③ 唤醒后**走子代理**执行完整蒸馏+固化（不等 1h、不滞留中间队列）；④ 子代理模型**默认跟随会话当前模型、可单独指定**（F-002）。
- Spike 实证（2026-09-05）：daemon ctx 能 `agents.list()` 见全部活 agent（id 带 `session-` 前缀）且**可 spawn 子代理**（fork 需活 parent 继承上下文，spawn 不继承但同样需活 agent 作执行宿主）；`ctx.subagents`/`ctx.agents` 在插件可注入。fork/spawn 子代理模型覆盖：agentOptions 空=继承主会话（实测 completed 用 deepseek/deepseek-v4-flash）；显式传 provider 需真实 adapter 注册名（`deepseek` 报 NO_ADAPTER，`deepseek-official` 才对）。

## 决策

1. **执行体 = spawn 蒸馏子代理**（`ctx.subagents.start('spawn', ...)`），替代方案 C 的 daemon 内 LLM 直裁（doAdjudicate/doConsolidate 移除）。子代理不继承父上下文，feed 转录机械信号 + `pending/` 候选；借任一活 agent（`agents.list()` 取，带 `session-` 前缀）作执行宿主；**跳过 origin=subagent 会话防递归**。
2. **唤醒判定（F-001）**：daemon 每 tick `--due` 发现静默会话入 pending 队列；蒸馏触发 = pending 非空（即会话已静默满 `idleWakeMs`，默认 **600s=10 分钟**，config 可调）。蒸馏间隔冷却 60s、单轮 1 个。
3. **子代理职责**：persona 内四问裁决 + 查重（宁缺毋滥）→ 输出结构化 JSON `{appends,newIndex,skipped}`（不授予写工具，`toolFilter allow:[]`）→ **宿主执行** `memory-append` 安全阀入册（白名单小节/无锚拒写/容量门禁/写前备份）→ 成功候选归档 `.processed/`。
4. **状态机**：仅子代理 `completed` 才 `archive-mark --done` + `--dequeue`；`aborted/error` 保留队列待下轮重试（spike 实证 aborted 曾误 done 丢内容，2026-09-05 修）。
5. **模型（F-002）**：`agentOptions` 空 = 继承主会话当前模型；config `llmProvider/llmModel` 可指定（需真实 adapter 名，如 `deepseek-official`；配置 UI 待办）。
6. **存储约束不变**：候选只落 `pending/`（统一 `<日期>-arb-*.md`）；写入一律经引擎 memory-append 安全阀；进度/队列在 `audit/`。

## 后果

- 正面：全自动单通道闭环（会话静默 → daemon 发现 → spawn 蒸馏子代理 → 裁决/查重/入册）；唤醒时长为用户可配置（默认 10min）；子代理模型可独立指定；memory-append 安全阀仍兜底写库；E2E 实测通过（蒸馏子代理正确裁决：新知识入册 notes+MEMORY 索引、重复知识 SKIP 查重）。
- 副作用/成本：每次蒸馏 spawn 一个子代理（LLM 成本 + 秒级延迟）；需活 agent 作执行宿主（宿主常驻时总有）；子代理可能被引擎误发现再次蒸馏 → 已加 origin=subagent 跳过。
- 边界：子代理只裁决不直写（安全阀在宿主）；aborted/error 自动保留重试不丢。

## 替代方案

- A. 方案 C 继续（daemon 内 LLM 直裁）：无子代理、与用户"唤醒子代理"方向不符、问题多——被本 ADR 取代。
- B. fork 蒸馏（继承父会话上下文）：daemon 静默唤醒时目标会话常已无活 agent 上下文可继承；spawn 更贴"自动蒸馏"。fork 保留为 agent 会话内主动触发的可能补充（暂未用）。
- C. agent 工具内触发蒸馏（非 daemon）：spike 证明 daemon 本身可 spawn（带 `session-` 前缀取活 agent），无需 agent 工具钩子——daemon 自动触发更简洁，选 daemon。

## 修订记录（2026-09-05 运行期修正）

1. **spawnSync 冻死主线程根治**（WorkBuddy 诊断）：daemon tick 的同步 spawnSync 在会话树 348MB 后冻结 web 服务循环——改异步 spawn + 在航守卫 + 10min 超时；补丁同步 src 消除 build 覆盖隐患。
2. **蒸馏子代理递归根治**（参考 dsh-mnemon「child 永不 idle-review」架构）：蒸馏子代理自身被 --due 再蒸馏 → 无限递归（每 60s API 调用彻夜）。修：引擎 isSubagentSession（读转录 header）+ discover 排除 + pending-list 过滤 + runDue 拦截清 mark（subagent-clear，实测清 84 个）+ 仅 completed 才 done。
3. **idleWakeMs 生效**：daemon tick 经 env `ARCHIVE_SILENT_MS=idleWakeMs` 传引擎——F-001 默认 10 分钟真正生效（此前实际 13min）。
